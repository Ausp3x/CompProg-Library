## Closest pair

### Implemented contract

`03-Geometry/05-closestpair.hpp` exposes `ClosestPair { pair<int,int> ids; lll distance2; }` and `closestPair(const vector<Point2<T>> &)`. T is a signed integral coordinate type of at most 64 bits; supported tests instantiate int8_t, int16_t, int and lng. Inputs are preserved. Indices refer to the original input, are increasing, and the lexicographically smallest index pair wins every squared-distance tie. Fewer than two points returns `ids={-1,-1}, distance2=0`; zero distance for a duplicate pair is a valid answer distinguished by its indices.

The size precondition is n <= INT_MAX. The bounding-box diagonal squared must be <= 2^127-1; an unsigned 128-bit, short-circuit subtraction check asserts this without overflowing even for a fully spread signed-64-bit input. Differences widen before subtraction. Thus every evaluated distance fits signed lll. Coordinates themselves may use the full signed-64-bit storage range: extreme singletons and tight clusters near either endpoint work. This is a stated span restriction, not support for all possible signed-64-bit point sets. Invalid bounds remain preconditions in -DNDEBUG. The n > INT_MAX assertion is inspected, but an allocation above that size is not exercised.

Worst-case deterministic O(n * log(n)) time, O(n) auxiliary memory; 2 * n int arrays and O(log(n)) stack in the general case, one int array for duplicates/axis-collinear returns. Initial (x,y,original-index) total sorting exactly reproduces stable (x,y) ordering while retaining std::sort's worst-case O(n log(n)); y merges preserve the initial x order for equal y. There is no epsilon comparator, floating arithmetic, or randomized answer/runtime behavior.

### Correctness and optimality argument

Sorted equal-coordinate groups expose their two smallest original indices as adjacent; scanning every adjacent equal pair obtains the global lexicographically smallest zero-distance answer. This prepass avoids a zero-separation strip containing arbitrarily many tied pairs. On a horizontal or vertical line, an optimum must be an adjacent pair in coordinate order, so an adjacent scan settles the answer.

For the general case, recursively split the fixed x order; brute-force leaves settle their pairs and each return yields y order by a linear merge. A cross-half pair at least as good as the current answer lies within the closed x strip and closed y-distance window. Both filters use <= (implemented by rejecting >), so equal-distance pairs remain eligible for the original-index tie policy. Each half has no pair closer than the distance before its merge; the standard two half-square packing argument bounds the candidate count by a constant. Tightening the shared global distance during the scan cannot invalidate an earlier exclusion. Each level is linear after the initial O(n log(n)) sort. All comparisons and squared distances are exact under the checked span precondition.

The implementation follows the repository's archived divide-and-conquer recurrence but reworks its arithmetic domain, no-answer behavior, stable sorting, duplicate handling and ties. It avoids the archived finite INF64 sentinel, 64-bit squaring/subtraction overflow and unspecified closest-pair ordering. Original archived bytes are unchanged.

## Circles

**Complete:** circle-boundary/line and circle-boundary/circle-boundary intersections; point tangents, outer and inner common tangents; circumcircle, incircle; point and filled-disk containment; centers through two points at a specified radius; filled-disk lens area; area/perimeter, arc length, oriented sector area and circular-segment area. All operations use O(1) time and storage. There are no dynamic allocations in the header and no dispatch/benchmark threshold to tune.

### Contracts and correctness

- `CircleApprox` stores `dpoint c` and a finite nonnegative `long double r`. A radius-zero boundary and disk both denote the singleton center. This is a separately named approximate API; finite inputs/intermediates/results are required. Nonzero divisors and geometric distinctions must survive rounding. As in P007, construction classification uses computed signs with no hidden epsilon; near tangency and near-collinear triangle centers are not certified. Membership queries alone accept an explicit nonnegative absolute **length** tolerance. Mutable fields must continue satisfying the constructor domain.
- `locate` returns -1/0/+1 for inside/tolerance-band/outside. `onBoundary` checks the band; `contains(dpoint)` includes it. `contains(CircleApprox)` means containment of closed filled disks, including internal tangency. All tolerance defaults are zero.
- `CircleIntersectionApprox.count` is 0, 1, 2 or -1 (infinitely many points), with only the corresponding prefix of the fixed two-point array meaningful. Boundary intersections do not confuse containment with boundary overlap. Coincident positive-radius circles have infinitely many points; coincident point circles have one. Line endpoints must differ. Repeated input points for radius-constrained centers give infinitely many centers if the radius is positive, and one if zero.
- `CircleTangentsApprox` contains at most two lines for the selected outer/inner family; `count == -1` means infinitely many distinct lines. Each record contains both contact points and a unit line direction. The direction stays meaningful at internal/external contacts where the two contact points coincide. A point circle defines every line through it as tangent; consequently two distinct point circles yield one line, identical point circles yield infinitely many, and inner/outer families coincide when either radius is zero.
- `circumcircleApprox` and `incircleApprox` return false for computed-collinear/repeated vertices, leaving the output unchanged. Circumcenters solve the two equal-distance equations in coordinates translated to the first vertex. Incenter side-length weights give an interior point at distance twice-area/perimeter from each side, independent of orientation.
- The line formula uses perpendicular projection followed by the Pythagorean half-chord. Subtracting circle equations gives the radical chord coordinate for circle intersection. Tangent normals solve the unit-normal equation `dot(n, c2-c1) = r1 - signed_r2`. These identities justify the constructions independently of the references' test claims.
- `arcLength(sweep)` accepts signed radians and repeated revolutions, returning nonnegative traversed length. `sectorArea(sweep)` is oriented, with negative clockwise area. `segmentArea(sweep)` accepts `[0, 2*pi]`, including major segments. A small-angle series avoids cancellation in `sweep - sin(sweep)`; its omitted term is beyond long-double rounding at the `.01` switch. Disk overlap handles disjoint/contained disks first, then sums the two chord caps via `atan2` angles.
- Exact/algebraic circle constructions and certified predicates are separate later inventory owners (`24-circle_constructions.hpp`, `36-exact_predicates.hpp`). Circle union, enclosing circles and circle-polygon clipping also retain their existing later owners. No circle-row feature is deferred.

## Rotating calipers

`ConvexCalipers` copies a strictly convex CCW cyclic integral hull, with arbitrary starting vertex, no repeated start or collinear boundary vertices. Use `convexHull(points, false)` for arbitrary point clouds. Signed integral input coordinate types are accepted with `|x|, |y| <= 10^9`; `n <= INT_MAX / 2`. Empty, singleton and distinct two-point hulls are explicit supported cases. Assertions catch the coordinate bound, repeated two-point input and nonpositive consecutive turns; simplicity/convexity remains an input precondition, not a separate validation algorithm.

Implemented: all distinct unordered antipodal index pairs including the four endpoint combinations of parallel supporting edges; diameter/maximum-distance pair with exact `lll` squared distance and lexicographically smallest sorted index pair on ties; minimum width with support witnesses; minimum-area and minimum-perimeter enclosing rectangles; minimum-area enclosing parallelogram. Box results contain CCW approximate vertices, area, perimeter and supporting edge indices. Empty diameter/width witnesses are -1 and empty boxes have `exists=false`. Singleton diameter `(0,0)` is valid and has no antipodal pairs. Segment enclosures have zero area/width and doubled segment length as perimeter. Other equal optima use the first encountered support configuration. No missing feature or handoff.

Construction and each nontrivial query use O(n) time and O(n) stored/auxiliary memory, counting the O(n) returned antipodal pairs. No sorting or quadratic fallback is hidden in a query. The constructor copies points and computes each opposite support with a monotone pointer; no queries mutate its state. `ratioLess`, `rectangleApprox` and `degenerateBox` are implementation helpers exposed by the contest-style struct.

All selection predicates and objective comparisons are exact within the stated coordinate domain. Edge components and coordinate differences have absolute value at most `2*10^9`; dot products, determinants, squared lengths and strip projection ranges are bounded by `8*10^18`. Width/area numerators are at most `6.4*10^37`. The squared half-perimeter numerator is at most `(16*10^18)^2 = 2.56*10^38`, which fits unsigned 128 bits. Cross-multiplying two objective fractions can exceed 128 bits, so selection uses continued-fraction/Euclidean comparison with positive denominators. Its word arithmetic is bounded independently of n. The `Approx` result types/methods use long-double conversion, division and square roots for metrics/coordinates; selected supports stay exact, but output coordinates and area reconstructed from vertices can lose relative accuracy on very thin hulls. No epsilon enters a support/optimum decision. This is not an exact-construction or certified floating-predicate API.

### Correctness

- Opposite support indices advance monotonically around a convex polygon. For vertex i, every antipodal partner lies between the support of its preceding edge and that of its following edge, including the second endpoint of a tied support edge. Enumerating that interval and retaining only i<j yields each unordered pair once. Every diameter pair is antipodal, so scanning these pairs suffices.
- The minimum-width strip has a hull edge on a boundary. Minimum-area rectangles have a hull edge flush with one side (the standard rotating-calipers rectangle theorem). Minimum-perimeter rectangles also have an edge flush: between support events the half-perimeter is a positive `a*cos(theta)+b*sin(theta)`, whose second derivative is its negative, so a minimum is attained at an event endpoint. Edge-aligned boxes use three monotone support pointers and exact squared/rational objective comparisons.
- For minimum parallelograms, put `D=P-P`. For a normal a let `w(a)=h_D(a)` be the strip width in its unnormalized projection. The parallelogram from normals a,b has area `w(a)*w(b)/|det(a,b)|`. Its reciprocal is `|det(a/w(a),b/w(b))|`, a determinant of two boundary points of the polar `D°`. A maximum determinant over two points of a compact convex polygon is attained by vertices: maximize each linear argument in turn. Edges of D have the merged directions of P and -P, hence the vertices of D° are exactly the distinct rays `+/-perp(e_i)/w_i`. The implementation uses e_i instead of perp(e_i), a common rotation preserving every determinant.
- Merge the two cyclic angular orders of e_i and -e_i in linear time. Same-ray parallel directions have identical normalized polar points and are deduplicated; either retained input edge gives the same strip. On this centrally symmetric convex polar polygon, the maximum of `det(q_i,q_j)=dot(perp(q_i),q_j)` is an ordinary support query. As q_i rotates, its query direction rotates, and the maximizing j advances monotonically through at most one circuit. Thus the maximum determinant and minimum parallelogram take O(n), including ties. Exact comparisons cancel the common width of q_i. The final corners intersect the two exact support bands, then convert to long double.

## Coordinate transforms

`Affine2Approx` represents the full two-dimensional affine map `p -> A * p + t`, with arbitrary real matrix coefficients stored as `long double`. It distinguishes points from displacement vectors and supports homogeneous `(x,y,w)` input; translations are multiplied by `w`, and `w` is preserved. `cartesianApprox` divides by nonzero `w`, returning false with unchanged output for directions and the algebraic zero vector. This is affine homogeneous-coordinate support; general projective homographies and 3D rigid frames have different contracts and are not claimed here.

The factories construct translations, rotations in counterclockwise radians about an optional center, independent x/y scaling about a center, orthogonal projection/reflection in a nondegenerate infinite line, and a direct similarity mapping two supplied points to two targets. Identical target points are valid and produce a constant map. Identical source points or projection/reflection endpoints violate preconditions. General coefficients also express shears and arbitrary rank-one/rank-zero maps.

Composition `f * g` applies `g` first, then `f`. The inverse returns false with unchanged output when the computed determinant is zero and permits output aliasing the input. The orientation query reports the computed determinant sign. All input, intermediate and output quantities must remain finite. These are ordinary rounded operations, without a hidden epsilon or a condition-number certificate: near singularity, inverse error can be arbitrarily amplified. Even a mathematically singular map assembled through rounded calculations (for example a projection in a slanted line) can have a small nonzero computed determinant. Exact floating predicates remain GE11's ownership. No universal numerical error bound is claimed for such ill-conditioned inputs.

The implementation follows multiplication of homogeneous 3-by-3 affine matrices, written as six coefficients to omit the fixed final row. The inverse is the 2-by-2 adjugate divided by its determinant, followed by the negative image of the translation. Unit-direction outer products yield projection; twice projection minus identity yields reflection. Dot/cross products of source and target directions produce the direct similarity. Every operation has constant time and storage.
