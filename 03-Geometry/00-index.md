# 03 Geometry — feature inventory

The nine GE01/GE02/GE23 headers are **verified**; the remaining 44 headers are **planned**. Existing notebook excerpts remain preserved **legacy references**. [P007 foundations](90-foundations.md), [P008 contracts, verification and sources](91-ge02.md), and [P009 triangle contracts](92-triangle.md) define the implemented domains and exact/floating policy. Basic/Advanced/Esoteric are inventory tiers, not directories; unselected rows remain separate work.

The feature contracts include named research variants. Sources are starting points with the precise read scope below, not proof that every variant is implemented or every cited paper has been read. For a selected row, settle algorithm/domain/precondition details and verification before marking it complete.

## Numeric, topology and validation contracts

- Integer predicates are exact on stated coordinate bounds; account for intermediate degree before selecting `__int128` or arbitrary precision. Division-based constructions return exact rationals/algebraic values or a separately named approximate result.
- Floating predicates/constructions have an explicit error/tolerance policy. Never use epsilon equality in sorting/map order. Exact predicate signs do not make approximate intersections exact; the two guarantees stay separate.
- Intersection/feasibility results distinguish empty, point, segment/line/plane overlap, coincident and unbounded states. Define endpoint openness, zero-length objects, lower-dimensional input and output orientation.
- Polygon APIs state simple versus self-intersecting input, holes, winding/fill rules and whether touching components are valid. A geometric subdivision owns coordinates/events; Graphs owns combinatorial planar embeddings/duals. Geometry nearest/range APIs reuse Data Structures range engines where appropriate.
- Predicate kernels can be implementation prerequisites regardless of Esoteric classification. Contest-profile geometry uses scalar code; accelerated arithmetic may be called through Core under the shared policy.
- Validate sweeps against brute force on small sets, topology against independent constructions, and invariants such as area/volume conservation. Include repeated/collinear/coplanar points, vertical/coincident segments, cocircular/cospherical sets, exact boundary contacts, holes, reversed orientation, huge coordinates and zero-area/volume results.
