# Session checklist

How to run the work on this library; the package list below is rendered by `plan.py` (other agents follow `AGENTS.md`). Order is the schedule `plan.py rank` keeps (`00-Guidelines/13-Plan/00-index.md`).

## Workflow

Start one fresh session per task with the preset of its work:

- Core full types (`01-Core` non-mini headers, packages tagged `fable`): `claude --agent core-session --effort high`, or `--effort xhigh` for a package of size XL (the brief prints the command)
- Everything else, sweeps included: `claude --agent contest-session --effort high`
- To start without the cached experiment ids (user decision 2026-11-11), put `python3 .claude/launch.py` in place of `claude` in either command ([00-harness-audit.md](00-Guidelines/13-Plan/Docs/00-harness-audit.md), Launcher).
- Parallel packages: `python3 '00-Guidelines/13-Plan/plan.py' ready --max 3` picks ready packages from different folders; launch each with `--worktree <name>` added. New worktrees branch from `origin/master` by default (`worktree.baseRef`), so push `master` before launching them. Only one session at a time is in a testing or mutation step (`/package` steps 5 and 6, `/finish` step 5); the others implement, document or wait (user decision 2026-11-12, `00-Guidelines/10-decisions.md`).
- Packages with several batches run one batch per session under its batch id (`/package`, Batches); `/package Pxxx` names the next one.
- Contributors (`CLAUDE.md`, Git) claim a package before `/package` with the commands its brief prints.

| Skill | Use it | Afterwards |
|---|---|---|
| `/setup-check [ubuntu or arch]` | On a new machine or clone, or after a toolchain change: required and optional tools with their floors and install commands | Install what it lists, then rerun |
| `/package Pxxx` (or `next`, or a batch id) | Implement or continue a package; `/plan-status` shows progress and the next one | `/finish` |
| `/prune Pxxx` | Remove the same-context forms and second implementations `duplicates.md` lists for a verified package | `/finish` |
| `/duplicate-sweep [02 04 …]` | After many new headers: list same-context forms and second implementations in `duplicates.md` | Answer its `ask` items, then `/prune` each verified package it names (`/package` handles planned ones) |
| `/omission-sweep [02 04 … or paths]` | When a folder's packages are mostly done (Mathematics early): list completeness gaps in `omissions.md`. A whole folder starts about 50 agents, so raise "Dynamic workflow size" in `/config` first | `/omission-sweep apply`, then `/package` the packages it reopened or created |
| `/speed-sweep Pxxx [verify]` (or a header path) | In a core-session, for a Core full type: compare it against the fastest Library Checker submissions and write its "Optimality gap" section; `verify` after each package stage that targets the gap | `/package` the targets it names, then commit |
| `/harness-audit [canary]` | When the status line shows `audit N new` (a scan starts by itself at the first startup after seven days) or after a client update: what changed in Claude Code's records, prompts, experiments, flags and settings, explained and marked reviewed. The canary is opt-in per clone: `git config compprog.canary true` | Re-audit P287 when it says so |
| `/pause [hours]` | Before stepping away from an open session: a handoff plus keep-alive pings (default 2 hours) | Come back and type; a new session loads the handoff |
| `/tidy [scope]` | Every ten or so packages, or after a guideline change: remove stale, restated and superseded text | Answer its questions, then commit |
| `/restyle Pxxx` | Only after the comment cap or closing-brace rule changes | Commit |
| `/finish [Pxxx or batch id]` | After `/package` or `/prune`, in a worktree or the main checkout, even with no gaps reported: closes the work in one pass with one round of questions and lands it on your yes (a contributor's stops on the claim branch) | Push `master`, or as a contributor the claim branch |
| `/merge-pr <N>` | Maintainer, in the main checkout: gate a contributor's pull request (file check, sandboxed gates, review) and land it on your yes | Run the push and `gh pr close` commands it prints |

Commits: `/finish` commits and lands `/package` and `/prune` work; other skills print their commit command. Pending one-off runs: `/omission-sweep "02-Data Structures/45-kineticheap.hpp" "03-Geometry/26-geometry3d.hpp" "03-Geometry/53-dynamicconvexhull.hpp"`, then `/omission-sweep 05`.
