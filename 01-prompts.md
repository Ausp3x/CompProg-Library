# Session Checklist

How to run the work on this library; the package list below is rendered by `plan.py` (other agents follow `AGENTS.md`). Order is the schedule `plan.py rank` keeps (`00-Guidelines/13-Plan/00-index.md`).

## Workflow

Start one fresh session per task with the preset of its work:

- Core full types (`01-Core` non-mini headers, packages tagged `fable`): `claude --agent core-session --effort high` (the brief prints the command)
- Everything else: `claude --agent contest-session --effort high`
- `/reflect`, `/tidy`, `/duplicate-sweep` and `/omission-sweep` pin Opus and `/speed-sweep` Fable in their front matter: start each in a fresh session of the matching preset (contest-session, or core-session for `/speed-sweep`), since a skill whose model differs from the session's makes that turn re-read the whole context uncached (user decision 2026-11-19).
- Parallel packages: `python3 '00-Guidelines/13-Plan/plan.py' ready --max 3` picks ready packages from different folders; launch each with `--worktree <name>` added. New worktrees branch from the local `HEAD` (`worktree.baseRef: "head"` in `.claude/settings.json`), so unpushed commits on `master` carry over. Sessions test and mutate in parallel: the memory gate queues their runs, and only timing takes the machine alone (`05-testing.md`, Memory Safety; user decision 2026-11-26).
- A verified package with open follow-ups (`[!]` below) stays verified and is ready work: `/package Pxxx` runs only its follow-ups (`plan.py follow-up`, `00-Guidelines/13-Plan/00-index.md`).
- Process batch, about every ten packages: `/reflect`, a review of `00-Guidelines/23-Sweep Ledgers/process.md`, then `/tidy`. Guidelines, skills, agents, hooks and `CLAUDE.md` change only there or by a user decision (`01-principles.md`, Scope Discipline).
- Packages with several batches run one batch per session under its batch id (`/package`, Batches); `/package Pxxx` names the next one.
- Contributors (`CLAUDE.md`, Git) claim a package before `/package` with the commands its brief prints.

| `/tidy [scope]` | In the process batch, after `/reflect`, or after a guideline change: remove stale, restated and superseded text from the units changed since its last run | Answer its questions, then commit |
| `/restyle Pxxx` | Only after the comment cap or closing-brace rule changes | Commit |
| `/finish [Pxxx or batch id]` | After `/prune`, or when `/package` left something open, in a fresh context (`/clear` first) in the worktree or the main checkout: closes the work in one pass with one round of questions and lands it when nothing stays open (a contributor's stops on the claim branch) | Push `master`, or as a contributor the claim branch |
| `/merge-pr <N>` | Maintainer, in the main checkout: gate a contributor's pull request (file check, sandboxed gates, review) and land it on your yes | Run the push and `gh pr close` commands it prints |

Commits: `/package` lands its own work when nothing stays open, and `/finish` lands the rest and `/prune` work; other skills print their commit command.
