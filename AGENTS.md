# CompProg Library (Entry for Non-Claude Agents)

Read `CLAUDE.md`: everything in it applies, with the Claude Code features it relies on replaced as below. What Claude Code does automatically, do by hand.

- **Models.** Ignore the session presets (`claude --agent`, `/model`, the launch command `plan.py show` prints), the model guard and the status line. Where `CLAUDE.md` or a skill's or agent's front matter names Fable, use your tool's strongest model, and the Fable main-session rules in `CLAUDE.md` apply to you; where it names Opus, use your strongest general model. Read each effort level as your tool's reasoning-effort setting. Where a step records the session model (`finish-log.tsv`), write your tool and model.
- **Rules.** Read `00-Guidelines/01-principles.md` always and, before touching a file, the guide `00-Guidelines/00-index.md` lists for it.
- **Startup and compaction.** At startup run `python3 .claude/hooks/resume.py startup </dev/null`: it prints the newest `/pause` handoff with the git state, or nothing. When your tool compacts or restarts during a skill, rerun that skill's `!` command lines (the package brief, `/finish`'s facts with its ledger) to restore what the compaction hook would.
- **Skills.** Run one only when the user asks for `/name args`. Follow `.claude/skills/<name>/SKILL.md`, running each `!` command line yourself with `$ARGUMENTS` replaced by the arguments, `${CLAUDE_PROJECT_DIR}` by the repository root and `${CLAUDE_SESSION_ID}` by nothing. Of the front matter only `model` and `effort` matter (Models). Inside the skills:
  - AskUserQuestion: ask in one message, at most four questions, each with its options and your recommendation first, and wait for the answers.
  - `run_in_background`: use your tool's background mode, or a timeout of at least ten minutes; never poll with `sleep`.
  - `/package` step 1, and every skill step that refers to it: skip `harness.py --selftest`, which always fails outside Claude Code, and the comparison with the session's model; keep every other check of the brief. `harness.py --experiment` prints `none`; record it as printed.
  - `/pause`: run its facts command with `0` and write the handoff; skip the keep-alive pings, which only keep Claude's prompt cache warm.
  - `/finish` step 1 asks for a fresh context: start a new session where it says `/clear`.
  - `/finish` step 7 and `/package` step 13, which lands the same way: in place of ExitWorktree, run `python3 '00-Guidelines/13-Plan/worktree.py' '<worktree path>' --finish` from the main checkout; in place of EnterWorktree, work in the worktree path.
  - `/reap`, also the last step of `/package` and `/finish`: it ends only processes Claude Code started, so stop your own background jobs before running it.
  - `/omission-sweep` step 2: in place of the Workflow tool, run by hand the prompts `.claude/skills/omission-sweep/scan.js` builds, each as a separate `@researcher` returning the JSON its schema names: per manifest item the research prompt, then the library and source lens prompts on its candidates. A candidate's decision is the two lenses' shared verdict, otherwise `ask`.
  - `/harness-audit` audits Claude Code itself: skip it.
- **Subagents.** `@researcher`, `@reviewer` and `@speedscout` run with `.claude/agents/<name>.md` as their instructions, limited to its `tools` (read-only agents edit nothing); a skill's general-purpose agents get the brief its step gives. Run each in a fresh context with only the inputs the step names: your tool's subagent, or else a new session whose report you bring back. Never review your own work in the context that wrote it.
- **Scratchpad.** Make the session scratchpad with `S="/tmp/claude-$(id -u)/$(git rev-parse --show-toplevel | sed 's/[^A-Za-z0-9]/-/g')/$(python3 -c 'import uuid; print(uuid.uuid4())')"; mkdir -p "$S"` and give its path to every subagent; `/reap` deletes it once it has been unchanged for 24 hours.
- **Parallel worktrees.** In place of `--worktree <name>`, run `git worktree add -b 'worktree-<name>' '.claude/worktrees/<name>' HEAD` from the main checkout (on `master`, as Claude Code's `worktree.baseRef: "head"` does), with the package or batch id as `<name>`, and start the session in that folder.
- **Hooks.** Obey the hook rules in `CLAUDE.md` yourself and run `python3 '96-Local Testing/03-consistency.py'` after each batch of edits to a Markdown, header, module or plan file. Of those hooks only the git pre-commit hook (`CLAUDE.md`, Start Here) works outside Claude Code: enable it when `/setup-check` warns.
