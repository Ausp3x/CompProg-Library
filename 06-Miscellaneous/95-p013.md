## Performance evidence

The [fast-I/O benchmark script](../96-Local%20Testing/06-Miscellaneous/90-fastio_benchmark.py) and [record](../96-Local%20Testing/06-Miscellaneous/90-fastio_benchmark.json) compare complete parse/transform/format/flush pipelines with independently verified output bytes. The record includes CPU/compiler/flags, seeds, one warmup, five repetitions, buffer sizes, memory and small/common/large input distributions. On the recorded i9-11900H, the default 64 KiB buffers took 25.280 ms versus 61.330 ms for 500,000 small integers and 46.135 ms versus 94.234 ms for full-width values with mixed whitespace, compared with `fscanf`/`fprintf`.

These are warmed-file shared-host observations, not universal speed or timing guarantees. Current source/benchmark hashes match the record. Other owned algorithms use justified constant, linear or logarithmic standard/shared implementations without tuned dispatch thresholds or speedup claims. No Barrett/Montgomery backend is introduced.

## Scope and remaining work

No owned implementation feature is left incomplete. Randomness and hashing are noncryptographic; hashing is not a universal collision guarantee. Scalar distinct permutation ranks require n≤20, while Lehmer digits support larger permutations; multiset scalar ranks require the exact total to fit `ulng`. These are explicit API domains, not undisclosed overflow behavior.

Sequence algorithms, general/partial permutation enumeration, advanced random sampling/hash families, mmap/system-call I/O and parallel binary search retain separate ownership. Their planned status is unchanged. No automatic online submission or judge acceptance claim was made. No P013 handoff remains open; the package checkbox is backed by the completed evidence above.
