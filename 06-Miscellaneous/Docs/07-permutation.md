# 07-permutation.hpp — Evidence

`07-permutation.hpp` (batch MI02, package P013) provides k-th lexicographic steps; bijection algebra (inverse, composition, powers, cycles, cycle type, construction from cycles, sign, order); applying a permutation to a value array; exact Lehmer digits; bounded scalar ranks and ranks of any length reduced into a ring; the linear-time Myrvold–Ruskey rank and unrank; exact multiset rank, unrank and counts; the modular count of multiset arrangements below a target; exact and modular counts of a cycle type; and two one-problem compositions (fewest rounds of disjoint swaps, collecting rounds). The Trotter–Johnson order is the Esoteric row 59 (`59-permutation_orders.hpp`), and the largest permutation with k inversions, a standalone greedy, is the Esoteric row 60 (`60-permutation_problems.hpp`, user decision 2026-11-17). Single lexicographic steps are `std::next_permutation` and `std::prev_permutation`. The header reuses `02-Data Structures/02-fenwick.hpp` for order statistics, `05-Mathematics/05-combinatorics.hpp` `multinomialExact` for multiset totals and `06-bit_operations.hpp` `BitOps::select` for the scalar unrank. Dependencies: P002 (template), P006 (Fenwick) and P012 (combinatorics), all verified.

## Contracts

### Domains

A mapping permutation is a `vector<int>` holding each integer of `[0,n)` exactly once, with `n <= INT_MAX`; `p[i]` is the image of `i`. The convention says nothing about moving array values to or from indices; an application chooses that interpretation explicitly. The empty permutation is valid. `isPermutation` is a total validity predicate; the algebra and distinct-ranking operations assert their bijection and domain preconditions. Stated auxiliary-space bounds exclude that check's `n`-bit `vector<bool>`, which exists only while assertions are enabled (so `kthNextPermutation` uses O(min(n,21)) words under `NDEBUG` and O(n) bits otherwise).

| `isPermutation(p)` | Whether `p` is a bijection on `[0,n)` and its size fits `int`. | O(n) / O(n) |

| `permutationPower(p,k)` | `p` composed with itself `k` times; negative powers use its inverse, zero gives identity. Every signed 64-bit exponent is supported, including `LNG_MIN`. | O(n) / O(n), plus O(n) returned storage |
| `cycleType(p)` | `a` of size `n+1` with `a[k]` the number of `k`-cycles of `p` (fixed points in `a[1]`), so `a[0] = 0` and Σ k·a[k] = n. Empty gives `{0}`. | O(n) / O(n) |
| `permutationFromCycles(n,cycles)` | The permutation with `p[c[j]] = c[j+1]` and `p[c.back()] = c[0]` for each listed cycle, the inverse of `permutationCycles` in any cycle order and rotation. The cycles must partition `[0,n)`, singletons included; each element is asserted in range and unused, and the result is asserted to be a permutation. | O(n) / O(n) |
| `permute(a,p)`, `inversePermute(a,p)` | For a value array `a` of any element type and a permutation `p` of the same size: `b[i] = a[p[i]]` (gather, maspypy `rearrange`) and `b[p[i]] = a[i]` (scatter). Each undoes the other, and `permute(a,p)` agrees with `permutationCompose(a,p)` on integer labels. `permute` needs only copy construction. | O(n) / O(n) returned |
| `swapRoundSort(p)` | The fewest rounds of pairwise disjoint position swaps that sort `p` when applied round after round (CSES 1698, Swap Round Sorting): none for the identity, one when `p` is an involution, otherwise two. Each swap `(i,j)` has `i < j`; swaps within a round are listed by cycle. | O(n) / O(n) |
| `collectingNumbers(p)` | The number of left-to-right passes that collect `0, 1, ..., n-1` in order (CSES 2216, labels lowered by one): `1 + #{v : pos(v+1) < pos(v)}`, 0 for the empty permutation. | O(n) / O(n) |
| `permutationRankLinear<T>(p)`, `permutationUnrankLinear(n,rank,out)` | The Myrvold–Ruskey bijection between permutations and `[0,n!)`, not lexicographic (suisen `PermutationHash`, SymPy `rank_nonlex`). Rank for any `n` in ring `T` (needs `T(int)`, `+=`, `*`, `*=`): exact in a wide enough type, modulo 2^64 for `ulng`, the residue for `mint`. Unrank for any `n >= 0` from a `ulng` rank: false exactly when `rank >= n!`, leaving `out` unchanged, so for `n > 20` every rank succeeds. | O(n) / O(n) |
| `cycleTypeCount(a,out)`, `cycleTypeCountMod<M>(a)` | The number of permutations of `[0,n)` with `a[k]` cycles of length `k`, `n = Σ k·a[k]`: `n!/∏(k^a[k]·a[k]!)` (OI Wiki 置换的型). `a` is a type vector as `cycleType` returns it, possibly trimmed or with trailing zeros: `a[0] = 0` when present, every `a[k] >= 0` and `n <= INT_MAX` (asserted). The exact form returns false above `ulng`, leaving `out` unchanged; the Mod form works in a field type `M` in which 1..n are units. An empty vector or all zeros gives 1. Under `NDEBUG`, a negative `a[k]` for `k >= 1` or an `n` above `INT_MAX` gives false (exact) or 0 (Mod); `a[0]` has its own assertion and the counts never read it. | O(n + size(a)) / O(1); Mod O(n + size(a) + log(mod)) / O(n) |
| `kthNextPermutation(p,k)` | `p` a permutation of `[0,n)` (asserted), any `lng` offset including both extremes. Replaces `p` by the permutation of lexicographic rank `(rank(p) + k) mod n!`; returns true iff `0 <= rank(p) + k < n!` (no wrap). For `k = ±1` this matches `std::next_permutation`/`prev_permutation`, including the wrap. `n = 0`: true iff `k = 0`. | O(n + min(n,21)^2) / O(min(n,21)) |
| `permutationCycles(p)` | Disjoint cycles ordered by smallest element, each starting at its smallest element and following `p` (`c[j+1] = p[c[j]]`); fixed points are singleton cycles; the empty permutation gives no cycles. | O(n) / O(n), plus O(n) returned |
| `permutationSign(p)` | `+1` or `-1`, `(-1)^(n - cycles)`, equal to `(-1)^(inversions)`. | O(n) / O(n) |
| `permutationOrder(p,out)` | Smallest `t >= 1` with `p^t = id`, the lcm of the cycle lengths. False iff it exceeds `ulng`, leaving `out` unchanged. Empty gives 1. For example, cycles of the first 16 primes (n = 381) overflow. | O(n) / O(n) |
| `permutationOrderMod<T>(p)` | The same lcm evaluated in `T` as a product of maximal prime powers `T(q^e)`. Exact for any `T` that represents it (`lll` for small `n`, a big integer), the residue for `mint`/`ModInt`. `T` needs `T(int)` and `*=`; wrapping types such as `ulng` give the order mod 2^64. | O(n) / O(n) |
| `permutationLehmer(p)` | `d[i]` is the number of smaller values to the right of `p[i]`. Exact for any supported `n`. | O(n log(n+1)) / O(n), plus O(n) returned storage |
| `permutationFromLehmer(d)` | Decode digits satisfying `0 <= d[i] < n-i`; invalid digits violate a precondition. | O(n log(n+1)) / O(n), plus O(n) returned storage |

| `permutationUnrank(n,rank,out)` | Requires `0 <= n <= 20` (asserted inside the guard that returns false under `NDEBUG`, leaving `out` unchanged). False exactly when `rank >= n!`, preserving `out`. Empty `n=0,rank=0` succeeds. | O(n) / O(1), plus O(n) returned storage |
| `permutationRankMod<T>(p)` | The same lexicographic rank for any `n`, evaluated in ring `T` (needs `T(int)`, `+=`, `*`, `*=`): exact in a wide enough type, the residue for `mint` (Luogu P5367), modulo 2^64 for `ulng` (equal to `permutationRank` for `n <= 20`). `permutationRankModNaive<T>` gives the same value from the naive digits. | O(n log(n+1)) / O(n); Naive O(n²) / O(n) |

| `multisetPermutationRankMod<M>(values,target)` | Number of distinct arrangements of `values` lexicographically smaller than `target`, an arbitrary `int` sequence of any length (a proper prefix is smaller, equality is not counted, labels absent from `values` are allowed), in a field type `M` (`mint`, `mintmini` or another prime modulus above `n`) in which 1..n are units. It needs `M(int)`, `*`, `*=`, `+=` and `/`; a non-unit fails `M`'s own inverse assertion. Codeforces 1648C. Ranking and algebra APIs use their documented integer orders, not a custom comparator; compress other ordered labels first.

The scalar distinct rank bound is intentional: `20! = 2432902008176640000` fits in `ulng` and `21!` does not. Lehmer digits give a scalable exact rank without arbitrary-precision dependencies or a twenty-item limit, and their lexicographic order matches permutation order. Multiset scalar ranks are bounded by the exact multinomial, not by length: a million equal values have one ordering, `C(67,33)` fits in `ulng` and `C(68,34)` does not. Count overflow and an out-of-range rank both report false; a caller that must tell them apart computes `multinomialExact` of the multiplicities first.

No input is mutated except the permutation `kthNextPermutation` advances and successful output parameters. There is no persistent cache or global state. Allocation limits still apply to the theoretical `int` size domain. Arbitrary-precision scalar multiset ranks are not provided. Partial permutations, constrained generation and circular equivalence enumeration are separate enumeration problems, not variants of these full-permutation APIs.

Correctness:

- Algebra: inverse and composition follow their pointwise definitions. Every bijection partitions into disjoint cycles; on a cycle of length `m`, power `k` advances by `k % m` (a signed remainder, so the minimum exponent is never negated). Each vertex is visited a constant number of times, so mapping operations are linear, matching the output lower bound.
- `kthNextPermutation`: the Lehmer digits of the last `m = min(n,21)` positions depend only on that suffix's relative order and are the low mixed-radix digits (radices 1..m) of the rank. Adding `k` digit by digit with carries in `{-1,0,1}` gives new low digits, a carry `c` and a leftover quotient `a`; since `21! > 2^63 > |k|`, `a = 0` and `|c| <= 1` when `n > 21`. For `c = +1`, sorting the suffix descending and calling `std::next_permutation` on the whole array increments the prefix rank and leaves an ascending suffix, returning false exactly on wrap; `c = -1` is symmetric. For `n <= 21` any nonzero `c` or `a` is a wrap and the same step resets to the first or last order. The suffix is then rebuilt by selecting the `d[i]`-th smallest remaining value, giving rank `(rank + k) mod n!`.
- Cycles, sign, order: a `seen` array visits each vertex once; a cycle of length `L` contributes `L - 1` transpositions; the order of disjoint cycles is the lcm of their lengths. The checked version computes `res / gcd(res, L) * L` in `ulll` and stops at the first value above `ulng` (lcm is monotone). The modular version factors each distinct length by trial division (at most `sqrt(2n)` distinct lengths summing to `n`, so O(n^(3/4)) trial work), keeps the maximal prime power per prime and multiplies those in `T`.
- `cycleType`, `permutationFromCycles`: the `seen` walk visits each element once and counts its cycle's length. Building from cycles sets each image once, and the asserts reject an element listed twice or out of range, so a passing input is a set of disjoint cycles covering `[0,n)`, which is the cycle decomposition of the result.
- `permute`, `inversePermute`: direct from the definitions; since `p` is a bijection, the scatter writes every position once.
- `swapRoundSort`: a round of disjoint swaps is an involution, so one round sorts `p` iff `p` is an involution (all cycles of length at most 2), and the identity needs none. Every permutation is a product of two involutions: on a cycle `c` of length `m >= 3` (`p[c[j]] = c[j+1]`), the first round is the reflection `c[j] ↔ c[m-j]` (j = 1..⌊(m-1)/2⌋) and the second the reflection `c[j] ↔ c[m+1-j]` together with `c[0] ↔ c[1]`. Applied in that order they move the value at each `c[j]`, which is `c[j+1]`, one step along the cycle to its sorted position `c[j+1]` (the reflections `j ↦ -j` and `j ↦ 1-j` mod m compose to `j ↦ j+1`). Cycles are disjoint, so their swaps combine into the same two rounds.
- `collectingNumbers`: a pass collects `v+1` right after `v` exactly when `v+1` stands to the right of `v`, so every `v` with `pos(v+1) < pos(v)` starts a new pass, and nothing else does.
- Myrvold–Ruskey: `unrank` swaps `p[k-1]` with `p[rank mod k]` for `k = n..2` from the identity, consuming one mixed-radix digit per step; `rank` undoes those swaps from the top, reading the digit `s = p[k-1]` and maintaining the inverse so each swap is O(1). Digit vectors in bases `n, ..., 2` are in bijection with permutations (each step fixes the value at position `k-1` among `k` choices), so rank and unrank are inverse bijections onto `[0,n!)`; a nonzero quotient after the last digit is exactly `rank >= n!`.
- `cycleTypeCount`: for each length `k`, choose the `k·a[k]` elements in `C(rem, k·a[k])` ways, then arrange them into `a[k]` unlabelled `k`-cycles in `∏_{j=1..a[k]} (jk-1)!/((j-1)k)!` ways (the smallest unused element starts a cycle and orders `k-1` followers among the `jk-1` others), which is `(k·a[k])!/(k^a[k]·a[k]!)`. Every partial product counts partial structures and never decreases, so the first overflow of `ulng` means the total overflows. The Mod form evaluates `n!·∏ inv_fac[a[k]]·inv(k)^a[k]` with `inv(k) = inv_fac[k]·fac[k-1]`, skipping zero counts so that every index stays at most `n`.
- Lehmer digits: a Fenwick tree holding one per available label gives each digit as a prefix count; decoding selects the `(d[i]+1)`-th remaining label. These are inverse bijections between permutations and valid mixed-radix digit vectors, whose order matches lexicographic order.
- Scalar ranks (`n <= 20`): the labels fit one 32-bit mask, so the digit of `p[i]` is `p[i]` minus the used labels below it (`popcount` of the used mask under `p[i]`), and unrank picks the `d[i]`-th unused label with `BitOps<uint>::select`, both O(1) per position. Rank evaluates the digits in bases `n,...,1` and unrank divides in reverse, storing the digits in the output vector before replacing them; a nonzero leftover quotient is exactly an out-of-range rank. Every intermediate fits under `n <= 20`. KACTL `IntPerm.h` uses the same mask technique for its non-lexicographic order.
- `permutationRankMod`: rank = Σ d[i]·(n-1-i)!, accumulated from the back with a running factorial in `T`, so only ring operations are needed; both rank forms share this sum (`permutation_detail::rankFromDigits`).
- Naive forms: `d[i]` counts the j > i with `p[j] < p[i]` by definition; decoding keeps the unused labels in increasing order, so the `d[i]`-th of them (zero-based) is the label with exactly `d[i]` smaller unused labels, the definition read backwards.
- Multiset total: `Multiset` takes `multinomialExact` of its multiplicities, exact or false above `ulng` (contract and proof in [05-combinatorics.md](../../05-Mathematics/Docs/05-combinatorics.md)); a false total makes rank and unrank fail before any block arithmetic. `distinctPermutationCount` returns that total; zero there means overflow, since a true count is at least one.
- Multiset rank/unrank: with `r` positions left, the arrangements beginning with a label of remaining multiplicity `c` form a contiguous block of exactly `W*c/r`. Ranking adds the blocks of smaller labels; unranking `k` selects the first cumulative multiplicity `s` with `W*s/r > k` (order-statistic target `floor(k*r/W)+1`) and recurses. Products fit `ulll`. Fenwick queries count remaining multiplicities, and an ordered frequency map groups labels from the const input in O(n log(m+1)) without copying or sorting it.
- `multisetPermutationRankMod`: an arrangement is smaller than `target` iff it agrees on a prefix of length i and then has a smaller label, or (when `target` is longer than `n`) it equals the first `n` labels of `target`. With the first i labels of `target` placed and `r` positions left, the current count `W = r!/∏ c!` is updated as in the exact rank; the arrangements continuing with a smaller label number `W·(remaining labels below target[i])/r`, read from a Fenwick tree over the multiplicities. The walk stops when `target[i]` has no remaining copy (no longer prefix exists), adds one when all `n` labels are placed and `target` continues, and adds nothing when `target` ends first. Division by `r <= n` uses `inv_fac[r]·fac[r-1]` from factorial tables built with one division, defined because 1..n are units.

### permutation_detail

None of these is public API. `cycleLengths(p)` returns the distinct cycle lengths in increasing order from `cycleType` (O(n) time and space; asserts a permutation). `factorialTables<M>(n)` returns `0!..n!` and their inverses with one division (O(n + log(mod))), shared by both modular counts. `cycleTypeSize(a)` asserts `a[0] = 0` and returns Σ k·a[k] clamped to `INT_MAX + 1`, which a negative `a[k]` for `k >= 1` also returns. Both counts assert that the size is at most `INT_MAX` inside the guard that returns false or 0, so the sum cannot overflow, a negative count fails the same assertion, and nothing reaches the counting loops past a violated precondition (`a[0]` is asserted separately and never read). `Multiset` groups a value list into sorted distinct `keys` and their `count`s with an ordered map and stores the exact multinomial `total` from `multinomialExact`, 0 when it exceeds `ulng`; O(n log(m+1)) time and O(m) space for `m` distinct labels.

## Sources

Inspected 2026-09-28 (Asia/Manila) unless dated otherwise. The algorithms are implemented independently; Fenwick and `multinomialExact` are shared local dependencies, and no external code was copied.

- [cppreference, `std::next_permutation`](https://en.cppreference.com/w/cpp/algorithm/next_permutation.html): lexicographic successor and wrap, comparator requirements, duplicate example and linear worst-case work. The independent reviewer also inspected installed libstdc++16 `stl_algo.h` and the saved Competitive Programmer's Handbook §5.2, pp.49–50, for standard enumeration semantics.
- [Lehmer code](https://en.wikipedia.org/wiki/Lehmer_code), sections “The code” and “Encoding and decoding”: inversion digits, radix bounds, the lexicographic rank interpretation and selection among remaining labels. The Fenwick implementation follows these invariants rather than the article's quadratic illustrative encoding.
- [NIST DLMF §26.4(i), equation 26.4.2](https://dlmf.nist.gov/26.4#E2), version 1.2.8 released 2026-09-15: the multinomial factorial formula and its product of binomial coefficients, with empty and one-group conventions. The cited Comtet and Abramowitz–Stegun texts were not reviewed.
- [Permutation](https://en.wikipedia.org/wiki/Permutation#Permutations_of_multisets), “Permutations of multisets” and the cycle and order sections: repeated-value semantics, multinomial count and cycle decomposition. Partial and circular variants were identified as separate enumeration scopes and are not claimed here.
- Saved KACTL `IntPerm.h` (checked by the independent reviewer): its integer numbering is not order-preserving and has narrower bounds, so it is not an oracle; its used-value mask with one `popcount` per position is the technique the scalar `permutationRank` adopted in MI02, with lexicographic digits.
- Completeness sweep 2026-10-07 (`@researcher`): [maspypy kth_next_permutation](https://raw.githubusercontent.com/maspypy/library/main/seq/kth_next_permutation.hpp) and [factorial_digit_system](https://raw.githubusercontent.com/maspypy/library/main/seq/factorial_digit_system.hpp) (suffix factorial digits with carries; maspypy covers distinct values only and gives a short count on overflow, while this header wraps modulo `n!` like `std::next_permutation`), [suisen permutation](https://suisen-cp.github.io/cp-library-cpp/library/util/permutation.hpp), [maspypy cycle_decomposition](https://raw.githubusercontent.com/maspypy/library/main/seq/cycle_decomposition.hpp) (dynamic; Data Structures scope), [KACTL IntPerm.h](https://github.com/kth-competitive-programming/kactl/blob/main/content/combinatorial/IntPerm.h). The checked-plus-modular order contract follows the researcher's recommendation; no fetched source states one.
