# 012-enumeration.hpp — Evidence

`012-enumeration.hpp` (batch MI15, package P015) provides visitor-based traversals of combinations (lexicographic, revolving-door Gray and cool-lex), multicombinations, compositions (parts at least 1, or at least 0), subsets, mixed-radix products and Gray products; set bits, submasks, fixed-popcount submasks, supermasks, subset masks, mask-submask pairs, fixed-popcount masks (numerical or cool-lex order) and Gray masks; integer partitions (by largest part, or into exactly `m` parts), set partitions (all, or into exactly `k` blocks), pairings and labelled trees; combination rank and unrank in lexicographic and revolving-door order; and combination rank in cool-lex order. It reuses the verified MI02 `BitOps` and the C01 template (P002), and is independent contest-profile code.

## Contracts

### Traversals (All `forEach*`)

Every traversal takes a visitor returning `true` to continue. A `false` result stops immediately, even at the final output, and the traversal returns `false`; `true` means normal completion. Vector arguments are borrowed immutable state valid only during the callback: copy to retain an output, and do not mutate a radix vector through another alias while traversing it. Exceptions propagate; no global state survives a call. Visitor work and retained copies are additional to the stated bounds. No traversal returns a total output count, which could overflow a fixed-width integer.

| API | Order, domain and boundary semantics |
|---|---|
| `forEachCombination(n,k,visit)` | Nonnegative `int` dimensions. Increasing index vectors in lexicographic order; `k>n` emits nothing, `k=0` one empty vector. Repeated input values stay distinct positions. |
| `forEachGrayCombination(n,k,visit)` | Same domain and objects as `forEachCombination`, in Knuth's revolving-door order `Γ(n,k)`: `Γ(n,0)` is the empty vector, `Γ(n,n)` is `[0,n)`, otherwise `Γ(n,k)` is `Γ(n-1,k)` followed by the reverse of `Γ(n-1,k-1)` with `n-1` appended to each vector. `visit(indices, removed, added)` receives `(-1,-1)` first; every later vector differs from the previous one by removing `removed` and inserting `added`. `k>n` emits nothing. |
| `forEachMulticombination(n,k,visit)` | Nondecreasing index vectors with replacement, lexicographic; `n=0<k` emits nothing, `k=0` one empty vector. Never forms an overflowing `n+k-1`. |
| `forEachComposition(n,k,visit)`, `forEachWeakComposition(n,k,visit)` | Compositions of `n` into exactly `k` parts, each part at least 1 (`forEachComposition`, `C(n-1,k-1)` of them) or at least 0 (`forEachWeakComposition`, `C(n+k-1,k-1)`), as part vectors in lexicographic order: `(1,...,1,n-k+1)` or `(0,...,0,n)` first, and `(n-k+1,1,...,1)` or `(n,0,...,0)` last. `n,k>=0` asserted; `k=0` emits one empty vector when `n=0` and nothing otherwise; `n<k` emits no strict composition. Parts never exceed `n`, so any `int n` is safe. Added by user decision 2026-11-27. |
| `forEachCombinationCoolLex(n,k,visit)` | The `k`-subsets of `[0,n)` in Ruskey and Williams' cool-lex order, as the 0/1 vector `bits` of size `n` (`bits[i]` is position `i+1` of their string), with no word limit. Same order as `forEachCombinationMaskCoolLex`, which handles `n<=width`; the first string is `1^k 0^(n-k)` and the last `1^(k-1) 0^(n-k) 1`. `n,k>=0` asserted; `k>n` emits nothing, and `k=0` emits the all-zero vector once. Added by user decision 2026-11-27. |
| `forEachSubset(n,visit)` | Nonnegative `int n`, no machine-word limit. Binary subset order with selected indices stored in **decreasing** order; the empty set comes first, and `n=0` emits it once. |
| `forEachProduct(radices,visit)` | Nonnegative radices, at most `INT_MAX` dimensions; last digit fastest. Any zero radix gives no output; no dimensions gives one empty tuple. Every radix is validated, even after a zero. |
| `forEachGrayProduct(radices,visit)` | Same domain, reflected mixed-radix order. `visit(digits, changed)` reports the changed digit, initially `-1`; consecutive outputs change exactly one digit by one. Not promised cyclic. |
| `forEachSetBit(x,visit)` | `visit(i)` for each set bit `i` of the unsigned word `x`, ascending; `x=0` emits nothing. |
| `forEachSubmask(mask,visit)` | Descending submasks including the mask and zero, by canonical `BitOps::prevSubmask`. |
| `forEachSupermask(mask,n,visit)` | Ascending supermasks of `mask` inside the low `n` bits, from `mask` to `2^n-1`, by canonical `BitOps::nextSupermask`; asserts `0<=n<=width` and `mask<2^n`. |
| `forEachCombinationSubmask(mask,k,visit)` | The `k`-bit submasks of `mask` in ascending numerical order; `k>popcount(mask)` emits nothing, `k=0` emits `0` once; asserts `k>=0`. |
| `forEachSubsetMask<U>(n,visit)` | All low-`n` masks in numerical order. |
| `forEachSubmaskPair<U>(n,visit)` | `visit(mask, sub)` for every `sub` inside `mask < 2^n` (`3^n` calls): masks ascending as `forEachSubsetMask`, each mask's submasks descending as `forEachSubmask`. Same domain as `forEachSubsetMask`. |
| `forEachCombinationMask<U>(n,k,visit)` | Fixed-popcount low-`n` masks in numerical (colex) order, by canonical `BitOps::nextCombination`, which differs from the lexicographic order of vector combinations. `k>n` emits nothing. |
| `forEachCombinationMaskCoolLex<U>(n,k,visit)` | The same masks as `forEachCombinationMask`, in Ruskey and Williams' cool-lex order: bit `i` of the mask is position `i+1` of their bit string `b_1...b_n`, the first mask is `2^k-1`, and each next mask rotates right by one position the shortest prefix that ends in `010` or `011`, or the whole string when none exists. The last mask is `2^(k-1)-1 + 2^(n-1)`. Domain as `forEachCombinationMask`, `n=width` included; `k>n` emits nothing, and `k=0` emits `0` once. Added by user decision 2026-11-27. |
| `forEachGrayMask<U>(n,visit)` | Binary reflected Gray masks; `visit(mask, changed_bit)` receives `(0,-1)` first. |
| `forEachIntegerPartitionParts(n,m,visit)` | Partitions of `n` into exactly `m` positive parts, as nonincreasing vectors of size `m`, in colexicographic order (lexicographic in `a[m-1]...a[0]`), from `(n-m+1,1,...,1)` (Knuth's Algorithm H). `n,m>=0` asserted; `m>n` emits nothing, and `m=0` emits one empty vector when `n=0` and nothing otherwise. At most `m` parts: conjugate `forEachIntegerPartition(n, m)`, or run this for each `j<=m`. Added by user decision 2026-11-27. |
| `forEachIntegerPartition(n,[max_part,]visit)` | Partitions of `n>=0` into positive parts at most `max_part` (default `n`; `max_part>=1` when `n>0`, larger values clamped to `n`). Parts are nonincreasing; partitions come in reverse lexicographic order from the greedy `[max_part,...,max_part,rest]` to all ones. `n=0` emits one empty partition. |
| `forEachSetPartition(n,k,visit)` | The set partitions of `[0,n)` into exactly `k` blocks, `S(n,k)` of them, as restricted growth strings with `max(a)=k-1`, in lexicographic order (the subsequence of `forEachSetPartition(n)` with `k` blocks). `n,k>=0` asserted; `k>n` emits nothing, `k=0` emits one empty string when `n=0` and nothing otherwise. |
| `forEachPairing(n,visit)` | `0<=n<INT_MAX`. For even `n`, every perfect matching of `[0,n)`, `(n-1)!!` of them; for odd `n`, every matching that leaves exactly one element unpaired, `n!!` of them. `visit(mate)` receives `mate[u]`, the partner of `u` or `-1`. Order: lexicographic in `mate` with `-1` ranked as `n`, so the smallest free element takes its partners in increasing order and stays unpaired last. `n=0` emits one empty vector. |
| `forEachLabeledTree(n,visit)` | `n>=1` (asserted). The `n^(n-2)` labelled trees on `[0,n)` in lexicographic order of their Prüfer codes. `visit(edges)` receives `n-1` pairs `(child, parent)` of the tree rooted at `n-1`, in Prüfer removal order: `edges[i].first` is the `i`-th leaf removed, and the last pair's parent is `n-1`. `n=1` emits one empty list and `n=2` the one edge `(0,1)`. |
| `forEachSetPartition(n,visit)` | Set partitions of `[0,n)` as restricted growth strings `a` (`a[0]=0`, `a[i]<=1+max(a[0..i))`; `a[i]` is the block of element `i`, blocks numbered by first element) in lexicographic order. `n=0` emits one empty string. The block count is `max(a)+1`. |

Boundedness without assertions: when `NDEBUG` removes an assertion, a violated precondition returns at once or throws `std::length_error` from a negative vector size. The early returns cover mask widths outside `[0, width]` (through `enumeration_detail::validWidth`), a supermask base with bits outside the low `n`, negative `k` for fixed-popcount masks and for `k`-block set partitions, negative `n` for subsets, multicombinations and integer partitions, `n` outside `[0, INT_MAX)` for pairings, and negative arguments to compositions, exact-part partitions and vector cool-lex combinations. On 2026-11-27 a scratch `-O1 -DNDEBUG -fsanitize=address,undefined` build made each of the tester's 66 assertion-probe calls once, with a visitor that would stop a runaway after `10^7` outputs. Every call ended at once without a sanitizer report: 60 returned, and 6 threw `std::length_error` (negative `k` for combinations, multicombinations and revolving-door combinations, negative `n` for set partitions, `n=0` for labelled trees, and negative `k` for Gray unranking).

Mask APIs support the unsigned 8–128-bit words of `BitOps`, with `0<=n<=word width` and nonnegative `k`. They test the last value before stepping, so full-width enumeration needs no unrepresentable `2^width` counter or shift. Early stopping makes prefixes of enormous traversals practical.

### combinationRank, combinationUnrank

`combinationRank(n,a)` returns the zero-based position of the strictly increasing vector `a` (elements in `[0,n)`, `k=a.size()`) in `forEachCombination(n,k)` order; `combinationUnrank(n,k,rank)` is its inverse and returns a new vector. Domain: `0<=k<=n` with `C(n,k)<2^64`, so every rank fits `ulng`. Violations (overflowing `C(n,k)`, unsorted or out-of-range elements, `rank>=C(n,k)`) are assertions.

Correctness: the combinations below `a` that agree on `a[0..i)` and put some `v` in `(a[i-1], a[i])` at position `i` number `sum_v C(n-1-v, k-1-i) = C(n-1-a[i-1], k-i) - C(n-a[i], k-i)` by the hockey-stick identity; summing over `i` gives the rank. Unranking picks at each position the largest `q` whose count does not exceed the remaining rank, by binary search, since the count increases in `q`. Every binomial used, `C(t,b)` with `t<=n`, `b<=k`, `t-b<=n-k`, is at most `C(n,k)`, so none overflows inside the domain. `enumeration_detail::binom` multiplies `C(t-b+j-1,j-1)*(t-b+j)/j` exactly in `ulll` and stops once the value exceeds `2^64-1` (each step at least doubles it), so the entry check costs at most 64 steps. Cost: `O(k * min(k, n-k))` for rank and a `log(n)` factor more for unrank; inside the domain `min(k,n-k)<=33`.

### grayCombinationRank, grayCombinationUnrank

Added on 2026-11-26 by user decision. `grayCombinationRank(n,a)` returns the zero-based position of the strictly increasing vector `a` in `forEachGrayCombination(n,k)` order, and `grayCombinationUnrank(n,k,rank)` is its inverse. The domain and assertions are those of `combinationRank`.

Correctness: by the recurrence, the combinations whose largest element is `c` occupy positions `[C(c,k), C(c+1,k))` of `Γ(n,k)`, in the reverse of the order `Γ(c,k-1)` gives their other elements. Hence `rank_k = C(c_k+1,k) - 1 - rank_{k-1}`, which unrolls to Knuth's eq. (30), and the rank is accumulated from `a[0]` upward. Unranking picks the largest `c` with `C(c,i+1) <= rank` by binary search and maps the offset into the reversed block. Each binomial `C(t,b)` used has `t-b <= n-k` and `b <= k`, so it is at most `C(n,k)`; the costs are those of `combinationRank` and `combinationUnrank`.

### combinationRankCoolLex

Added on 2026-11-27 by user decision. `combinationRankCoolLex(n,a)` returns the zero-based position of the strictly increasing vector `a` in `forEachCombinationCoolLex(n,k)` order (equivalently `forEachCombinationMaskCoolLex`). The domain and assertions are those of `combinationRank`, and the cost is `O(k*(min(k,n-k)+1))`. No unrank is provided. The correctness argument is under Correctness and Costs of the Traversals.

### Correctness and Costs of the Traversals

Lexicographic combinations increment the rightmost movable index and restore the smallest increasing suffix. The subset vector is a binary counter: trailing low selected indices are removed and the first absent index appended. Product carries and Gray-direction reversals skip unit radices; for radices at least two, carries and reversals have geometrically decreasing frequencies, so overhead per output is amortized constant after linear setup. Gray masks toggle the trailing-zero bit of the new binary index, equivalent to `i ^ (i >> 1)`. Supermasks step `((sup | ~free) + 1) & free | mask`, a binary counter over the free bits.

Integer partitions use Zoghbi–Stojmenović ZS1. Let `h` be the last part above one. If it is two, it becomes one and a one is appended; otherwise it drops by one to `r`, and the freed amount (one plus the trailing ones) is rewritten as copies of `r` followed by the remainder. A cap `max_part` only changes the start, because the reverse lexicographic successors of the greedy partition are exactly the partitions with parts at most the cap. Each written part above one is later the `h` of a distinct step before it can be rewritten, ones are written at most one per step, and pops never exceed pushes plus `n`, so the cost is `O(n + out)` amortized with or without a cap.

Partitions into exactly `m` parts run Knuth's Algorithm H (pre-fascicle 3B p. 2) in zero-based form. A bound check `j<m` replaces the sentinel `a_{m+1}=-1`, and `m<2` is handled before the loop, since Knuth assumes `n>=m>=2`. Knuth explains on p. 3 why the order is colex: the next partition increases the smallest `a_j` that can grow without changing `a_{j+1}...a_m`, which is possible exactly when `a_j<a_1-1`, and it sets `a_2=...=a_j` to the new `a_j`. Every value is at most `n`, so there is no overflow. Knuth states that the total running time is at most a small constant times the number of outputs, plus `O(m)`. His proof comes later in §7.2.1.4 and was not read. On every `n<=70` and every `m`, the loops of steps H4 and H6 took at most 1.85 iterations per `out+m` (scratch count, 2026-11-27), which supports the `O(m+out)` amortized bound.

Compositions take the lexicographic successor of the part vector with the sum fixed. Increase the rightmost position `i<k-1` that has more than the minimum to its right, then make the suffix its smallest completion: minimum parts, with the remainder in the last part. When the last part exceeds the minimum, `i=k-2` and only two parts change. Otherwise the only part above the minimum to the right of `i` is the rightmost such position `h` below `k-1`, so `i=h-1`. Its excess less one moves to the last part, and `h` becomes `h-1`, since every position from `h` on is then at the minimum. Keeping `h` makes each step `O(1)` (loopless).

Set partitions increment the rightmost position below its prefix maximum plus one and zero the suffix (Knuth's Algorithm H in lexicographic form), keeping the prefix maxima in a second array. A step changing position `i` costs `O(n-i)` and happens at most `B(i+1)` times; since `B(m-1)/B(m) = O(log(m)/m)`, the sum is `O(B(n)) = O(out)`, so `O(n + out)` amortized.

Revolving-door combinations dispatch on the measured crossover (Benchmarks): Bitner, Ehrlich and Reingold's loopless Algorithm 2 when `k > 3(n-k+1)`, Knuth's Algorithm R otherwise. Both produce `Γ(n,k)`, so the order does not depend on the branch. Algorithm R runs in zero-based indices, with `n` as the sentinel above the last index. Its loop stops at the first index `j` it can move, alternating step R4 (decrease) and R5 (increase) by the parity of `k`, so a move changes at most two positions and the removed and added elements follow from them. Knuth proves that the order is lexicographic in the alternating sequence `(c_k, -c_{k-1}, c_{k-2}, ...)` and so equals `Γ(n,k)`. R4 runs only at indices of `k`'s opposite parity and never at `j=k`, so R5 reads at most the sentinel. `k=0`, `k=1` and `k=n`, which Knuth's statement excludes (`n>k>1`), run correctly once the climb also stops at `j=k`; the tester checks them.

Algorithm R's climbs total exactly `C(n,k-1)-1` loop iterations over a whole run for `2<=k<=n`; an exhaustive count confirmed this for every `n<=24`. The recurrence explains it. The run on `Γ(n,k)` is first the run on `Γ(n-1,k)`, whose final failing climb of `k-1` iterations becomes the climb that moves the top element. Then comes the run on the reversed `Γ(n-1,k-1)`, in which each step climbs to the same index as its forward counterpart, and whose final failing climb grows from `k-2` to `k-1` iterations. So `S(n,k) = S(n-1,k) + S(n-1,k-1) + 1`, with `S(n,1) = 0` and `S(n,n) = n-1`, which `C(n,k-1)-1` satisfies. The claim that a reversed step climbs to the same index rests on the exhaustive count, not on a separate proof. Per output this is below `C(n,k-1)/C(n,k) = k/(n-k+1)`, which is at most 3 where the branch runs, so Algorithm R is constant amortized there.

The loopless branch keeps BER's bit string `g`, focus pointers `tau` and count `t` (the number of selected elements below the focus, p. 520), shifted to zero-based indices. `g[j]` is element `j`, and every stored value, the end marker `n` included, stays within `[0,n]`; the one-based form overflows `int` at `n=INT_MAX`. The branch builds `g` and `tau` before the first output, in `O(n) = O(k)` time since `n < 4k/3` there, and then finds the changing bit in `tau[0]` without a loop, so every gap between outputs is `O(1)`. The paper gives no proof for Algorithm 2: p. 520 says one "can be constructed along the lines" of its proof for Algorithm 1. Its claim is that Algorithm 2 visits the weight-`k` strings in reflected binary Gray code order, and that order is `Γ(n,k)`. The reflected code on `n` bits lists the code on `n-1` bits with the top bit 0, then the same list reversed with the top bit 1, and keeping the strings of weight `k` gives exactly the `Γ` recurrence. Each step changes two bits, and each case updates only the one or two positions of the sorted index vector that hold the changed elements. Correctness therefore rests on the paper's claim and on the tests. The tester checks the resulting vectors and `(removed, added)` pairs against the `Γ` recurrence for every `n<=14` and every `k`, which covers both branches on both sides of the threshold, and at `n=100` for `k=98..100`. The 2026-11-27 review compared 510 further cases with `n<=30` (145 of them in the loopless branch), plus `(200,197)`, `(200,198)`, `(1000,998..1000)`, `(64,60)` and `(80,75)`, with no mismatch or sanitizer report.

Fixed-popcount submasks run Gosper's successor on the bits of `mask`: adding the lowest set bit of `sub` inside `mask` (`((sub | ~mask) + low) & mask`) clears the lowest run of `sub` and sets the next bit of `mask` above it. The other `run - 1` bits of that run return as the lowest `run - 1` bits of `mask`, which `mask & lowMask(select(mask, run - 1))` gives in `O(1)`. Mapping the bits of `mask` monotonically onto `[0, popcount(mask))` turns this into Gosper's step, so the order is ascending. When the run reaches the top bit of `mask`, no bit is set and the traversal ends, including on a full-width wraparound. `forEachSetBit` is the `countr_zero`/`clearLowBit` loop, and `forEachSubmaskPair` composes `forEachSubsetMask` and `forEachSubmask`.

Cool-lex masks run the word-level form of Ruskey and Williams' order (their `Word(s,t)`, p. 11, which they credit to Knuth). With the bit string stored low bit first, `x & (x+1)` clears the leading 1s of the string, `p = r ^ (r-1)` masks the shortest prefix ending in `01`, and the bit `d` just after that prefix selects their Lemma 6, `σ(b) = b + c`, or Lemma 7, `σ(b) = b - c`. The update `x + (p & x) - sat(d-1)` performs both without a branch, where `sat(d-1)` is `d-1`, or 0 when `d=0`. Their loop stops when bit `n` becomes set, which needs `n<width`. This version stops after visiting the last string, `1^(k-1) 0^(n-k) 1`, instead. The only strings whose shortest `01`-prefix reaches bit `n-1` are that last string and the first, `1^k 0^(n-k)`, whose step doubles `x` without passing bit `k<n`. So no step ever needs bit `n`, and `n=width` works. `k=0`, which their algorithm excludes, emits `0` once. The same p. 3 remark names `1^t 0^s` and `1^(t-1) 0^s 1` as the only strings with no prefix ending in `010` or `011`.

The vector form `forEachCombinationCoolLex` runs their `Loopless(s,t)` (pp. 8–9) with their `x` and `y` shifted to zero-based `i` and `j`. Both start at `k-1`, and from the second string on `j` is the first 0. Each step clears `b[i]` and sets `b[j]` (one or two transpositions, their Lemma 1), and the test `b[i+1]=0` separates the two interfaces of their Figure 4, where the first also sets `b[i+1]` and clears `b[0]`. The paper argues these cases and the updates of `x` and `y` informally on p. 8, so correctness rests on that argument and the exhaustive and streamed tests, as for Bitner–Ehrlich–Reingold. The paper's `Branchless(s,t)` was not adopted: a reviewer's scratch measurement on 2026-11-27 gave 5.8–7.1 ns per output against 1.1–1.8 ns for `Loopless(s,t)`. The loop ends after the last string, when `i` reaches `n-1`. Every index stays below `n`, so the delay is `O(1)` with no word limit.

`combinationRankCoolLex` evaluates their Theorem 2 (p. 11), whose proof was read. With one-based elements `c_1<...<c_t` and `r` the first index with `c_r>r`, the rank is `C(c_r,r) - 1 + Σ_{j>r} (C(c_j-1,j) - 1)`, and 0 when there is no such `r` (the first string). The `j`-th element is at most `n-k+j`, so each binomial is at most `C(n-1,k)` or `C(n,k)` and none overflows inside the `C(n,k)<2^64` domain. The scan for `r` and the binomials cost `O(k*(min(k,n-k)+1))`.

Pairings are a depth-first search over a sorted dancing-links list of the free elements, with a phantom element `n` when `n` is odd (pairing with it means unpaired). Level `d` removes the smallest free element `u` and then its partner, and on backtracking relinks the partner and takes the next free element after it. Relinking in reverse order restores the sorted list, so partners come in increasing order and the phantom comes last. In the search tree, every level with `2r` free elements has `2r-1` children, so internal nodes number at most the leaves times `1 + 1 + 1/3 + 1/15 + ... < 3`. Each node costs `O(1)`, which gives `O(n + out)` amortized.

Labelled trees compose `forEachProduct` over `n-2` digits of radix `n` (Cayley's bijection with Prüfer codes) with the linear Prüfer decoding: `degree[v]` is one plus the occurrences of `v`, a pointer scans upward for the next unused leaf, and a vertex whose degree drops to one below the pointer becomes the next leaf at once. Vertex `n-1` is never removed, so every pair is `(removed leaf, its neighbour)`, which is `(child, parent)` toward `n-1`. Each tree costs `O(n)`, the size of its edge list.

Set partitions into exactly `k` blocks take the lexicographic successor among strings whose missing blocks still fit: the rightmost `a[i]` below the tail with `a[i] <= top[i-1]` and `a[i] < k-1` is incremented, and the suffix becomes its smallest completion. Below the tail the current string already leaves room for its missing blocks (`k-1-top[i] <= n-1-i`), and an increment never raises the prefix maximum by more than one, so no position below the tail fails the fit test, and the loop does not check it. That completion is zeros up to `t = n-k+1+top[i]`, then the forced tail `a[j] = j-n+k`, each tail value a new block. Tail values depend only on `j`, so positions at or after both the old and the new tail start already hold them and are not rewritten. No tail position can be incremented (it exceeds its prefix maximum), so the scan starts just below the tail.

Cost: in the tree of extendable prefixes, a non-tail node has at least two children when `k>=2` (`0` and `top+1`, or every block once all `k` are open). The non-tail nodes therefore number at most the leaves plus `n`. A step scans and rewrites only non-tail positions of the old leaf it leaves and the new leaf it enters below their common prefix. Each node is entered and left once, so the total is `O(n + out)`, constant amortized delay (`k=1` is one output after an `O(n)` scan). Measured with `-O2` on 2026-11-26: 2.4 ns per output for `n=2000, k=1999` (1,999,000 outputs), 2.9 ns for `n=300, k=298` (996,828,625 outputs), and 4.1–6.3 ns for `(24,2)`, `(16,3)`, `(14,5)` and `(13,7)`. Consecutive outputs differ in 1.03–2.00 positions on average across `n<=80`.

Costs: lexicographic combinations and multicombinations `O(k)` state and worst-case `O(k+1)` delay; revolving-door combinations `O(k)` state, `O(1)` delay above the dispatch threshold and amortized constant delay below it; cool-lex combinations `O(n)` state and `O(1)` delay; compositions `O(k)` state and `O(1)` delay; pairings `O(n)` state and amortized constant delay; labelled trees `O(n)` state and `O(n)` delay; set partitions into `k` blocks `O(n)` state and amortized constant delay; set bits, fixed-popcount submasks and mask-submask pairs constant state and delay; subsets `O(n)` state and amortized constant delay; products `O(d)` state and setup and amortized constant delay; masks constant state and delay (cool-lex included); partitions by largest part `O(n)` state and amortized constant delay; partitions into exactly `m` parts `O(m)` state and amortized constant delay. No recursion or precomputed output list.

## Limits and Handoffs

- `forEachGrayCombination` has `O(1)` delay only in its loopless branch. Below the threshold Algorithm R is constant amortized, and a single step can climb up to `k` positions.
- The threshold `k > 3(n-k+1)` was tuned on the i9-11900H only. Between ratios 2 and 3.5 the two branches are within this machine's run-to-run noise, so the exact cut inside that band is not resolved (Benchmarks). The threshold was kept by user decision 2026-11-27.
