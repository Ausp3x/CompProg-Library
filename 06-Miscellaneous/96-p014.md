### Contracts and costs

All sequence and matrix dimensions are less than `INT_MAX`. Sum/weight element types are integral with at most 64 bits, including the full signed and unsigned 64-bit domains. New sums use `lll`; sequence magnitudes are below `2^95`, and rectangular magnitudes below `2^126`, so their exact mathematical sums and implemented intermediates fit signed 128 bits. Keys can be nonnumeric copyable types with a pure strict weak ordering. Functions borrow and preserve their input. Returned indices are zero-based; ordinary ranges/rectangles are half-open. Witness ties are deterministic but otherwise arbitrary.

### Correctness arguments

A subarray ending at `r` maximizes `prefix[r]-prefix[l]`; maintaining the smallest earlier prefix gives the exact nonempty optimum and its endpoints. The bounded variant keeps precisely eligible starts `[r-hi,r-lo]`. A newer smaller prefix dominates an older larger one for every later end where the older start remains eligible; expiration and dominance remove each entry once. Two running prefix accumulators avoid retaining the whole input's prefix array.

A circular nonempty optimum is either ordinary or the complement of a proper nonempty minimum-sum interval. The minimum is obtained by maximizing negated widened elements; excluding a full-array minimum avoids an illegal empty complement. If the full interval is a minimum, every proper complement is nonpositive; any nonnegative ordinary element dominates it, while if all elements are negative the best singleton dominates longer wrapped sums. The empty-allowed zero case is handled explicitly. Rectangle scanning pairs boundaries only in the smaller dimension; collapsing each band to exact column/row sums and solving its one-dimensional optimum enumerates every nonempty rectangle.

Patience tails retain the best final key for each achieved length; predecessor indices reconstruct a valid optimum. Counting and weighted variants process indices in order and query the shared SegmentTree over smaller ranks (strict) or no-greater ranks (nonstrict). Counts add only disjoint predecessor ending-index sets with optimal length; each occurrence extends once, hence index-distinct counting. Weighted transitions compare the best predecessor with starting anew at the current item; negative predecessors cannot improve a sum. Shared Fenwick prefix counts report how many earlier keys are strictly greater for inversion counting.

For hereditary window validity, maximal right endpoints never decrease when the left endpoint advances. A failed extension cannot become valid by extending farther, and removing the left endpoint preserves validity. Each end advances at most `n` times. Nonnegative sum limits satisfy this property; arbitrary signed sums do not and are rejected by the concrete adapter. In ascending two-sum, a sum too small excludes that left element against every remaining right element, and a sum too large excludes that right element against every remaining left element. Shared extrema deques retain nondominated, unexpired candidates under their documented tie choices.

Boyer–Moore removes pairs of different classes; a strict majority cannot disappear. Misra–Gries removes groups of `k` distinct classes; at most `floor(n/k)` such groups can be removed, so a value above the threshold must remain. Neither surviving-candidate count proves actual frequency. Both APIs perform a complete second verification pass and return only true answers, with exact original counts. The `map` bounds key lookup cost by `log(min(n,k)+1)`; across decrement scans every visited counter unit is charged to an earlier insertion/increment, so scanning has total linear work.

## Interval algorithms (MI03)

`09-interval_algorithms.hpp` is an independent implementation of static intervals, endpoint sweeps, point stabbing and interval scheduling. There was no interval implementation in the inspected `06-Miscellaneous/97-Legacy` excerpts to migrate. No external implementation code was copied.

### Domains and API

All input intervals require `l <= r`, use full-width signed `lng` endpoints and default to `[l,r)`. `IntervalDomain::Continuous` interprets them as subsets of the real line; `Integer` interprets them as subsets of the integers. Every function defaults to Continuous. Mixed open/closed endpoints are supported independently per interval. Input vectors are not mutated. Interval count is at most `INT_MAX`.

Queries and point witnesses use `lll` **doubled coordinates**: `3` denotes `1.5`. Query coordinates may be any `lll`; continuous point-query APIs cover integer/half-integer points, and integer queries at odd doubled coordinates return zero. Endpoints themselves remain `lng`; arbitrary rational/floating endpoints or arbitrary real-valued point queries are outside this exact API. Integral endpoints guarantee that all nonempty intersections contain an integer or half-integer representative, so this point representation does not restrict the stabbing/scheduling/maximum-overlap optimizations.

| API | Contract |
|---|---|
| `Interval::bounds`, `empty`, `contains` | Constant time. `bounds` returns inclusive doubled bounds on the representative grid, not the actual real endpoints: continuous `(0,1)` maps to `{1,1}`. Integer bounds additionally restrict representatives to even doubled coordinates. Reversed endpoints assert. |
| `mergeIntervals` | Return sorted maximal union components, omitting empties. Continuous touching components merge iff at least one includes the shared endpoint; integer adjacent values merge, and integer output intervals are closed. |
| `intervalUnionMeasure` | Exact continuous length or integer cardinality. Return `lll`; the complete `lng` integer domain has cardinality `2^64`. |
| `intervalEvents` | Return `(x,phase,id,delta)` events sorted by coordinate, phase, original ID. Phases are 0 remove open right, 1 add closed left, 2 remove closed right, 3 add open left. Process a whole phase group: after phase 1 active membership is at `x`; after phase 3 it is immediately right of `x`. Empty intervals contribute nothing. Integer intervals first normalize to their closed integer hull; only integer coordinates represent integer membership. |
| `maximumIntervalOverlap` | Return maximum coverage and an exact doubled-coordinate witness. A zero count denotes absence and gives no witness. Integer witnesses are even. |
| `intervalStabbingCounts` | Count intervals containing each supplied doubled query point, preserving query order. |
| `minimumIntervalStabbing` | Minimum point set hitting every interval, increasing doubled coordinates. Empty input succeeds with no points; any empty input interval makes the task impossible and returns `possible=false` with no partial witness. |
| `maximumIntervalSchedule` | Maximum-cardinality pairwise disjoint subset, original indices. Empty intervals are sets disjoint from every set and are all selected first in input order; nonempty selections follow finishing order. |
| `weightedIntervalSchedule` | Maximum exact weight with an empty schedule allowed, any `lng` weights, sum in `lll`, and original-index witness. Select all positive-weight empties first; omit zero/negative empties. Nonempty witness follows finishing order; equal-value DP choices skip the later finish-order item. |

All batch operations take `O(n * log(n + 1))` time and `O(n)` storage including materialized output/workspace. Stabbing queries additionally use `O(q * log(n + 1))` time and `O(q)` returned storage. Event output has at most `2*n` records. Weighted sums fit signed 128 bits because at most `INT_MAX` signed-64-bit weights are added. Endpoint conversions, adjacency, lengths and doubled arithmetic widen before computing; no signed endpoint increment/decrement overflows. These are ordinary comparison-sort contest algorithms, with no hardware specialization or unmeasured performance claim.

### Correctness and optimality

For continuous integral endpoints, any nonempty intersection either contains a common closed integer endpoint or contains the half-integer just above its greatest lower endpoint. Thus intersecting original intervals is equivalent to intersecting their closed representative-grid bounds. Integer normalization yields exactly the first and last included integer. This justifies using the same exact compatibility comparisons for both domains while keeping union topology domain-specific.

Sorting by left endpoint and extending the current merged component maintains its exact union; an emitted gap cannot be filled by any later left endpoint. Summing disjoint component lengths/cardinalities counts the union exactly. Sweep phases remove excluded right endpoints before observing the point and introduce excluded left endpoints only afterward; closed endpoints are present at the observation. Integral endpoint spacing makes `x+1/2` a valid representative immediately after an event coordinate. Sorted start/end arrays count starts at or before a point minus ends strictly before it.

Earliest-finish greedy maximizes cardinality by replacing an optimal schedule's first item with the earliest-finishing item, which cannot obstruct later items. For stabbing, process increasing representative right endpoints and choose the greatest feasible representative of the first unhit interval. Moving any optimal hit for that interval right to this representative preserves its hits among all remaining intervals. Repetition proves minimum cardinality; empty input sets distinguish infeasibility from an empty successful answer.

Weighted scheduling sorts nonempty intervals by right bound and binary-searches the compatible predecessor prefix. Every optimum either omits the current item or takes it plus an optimum of that prefix, giving `dp[i+1] = max(dp[i], weight[i] + dp[pred[i]])`. Saved choices reconstruct that recurrence iteratively. Empty sets are independent of all choices and contribute precisely their positive weights. The sort/binary-search/linear-DP implementation has the appropriate `O(n * log(n))` static comparison-based cost and `O(n)` witness storage.

## MI03: offline queries

`10-offline_queries.hpp` implements `OfflineThreshold<K>`, `offlineSweep`, `OfflineRangeThreshold<K>` and `offlineRangeCount`. Input sizes fit `int`; keys need only a strict weak comparator, with no arithmetic or native equality. Descending order and comparator equivalence classes are supported. Queries accept strictly earlier keys, or earlier/equivalent keys when `inclusive=true`. Index ranges are half-open and may be empty. The range-count result retains the input query order.

The sweep sorts update indices by `(key, original index)` and query indices by `(key, strict before inclusive, original index)`. Its invariant is that the applied updates form exactly the eligible prefix of sorted updates for the current query. Strict queries at a tie run before updates at that key; inclusive queries run afterward. Each update is applied once at most. Input key arrays remain unchanged; updates beyond the last query are unused. Captured state belongs to the caller and must be initialized before each call. Query callbacks must observe rather than change accumulated update state, and callbacks must preserve input keys and comparator ordering. Exceptions propagate with no rollback guarantee. Callback arithmetic/lifetime costs and contracts belong to the caller.

Sorting costs `O(n * log(n + 1) + q * log(q + 1) + n + q)` time and `O(n + q)` workspace, plus callback costs. The concrete count adapter activates each eligible array index once in the existing `Fenwick<int>`; querying `[l,r)` gives the exact count. It adds `O((n + q) * log(n + 1))` time and `O(n)` workspace; every counter is between zero and `n`, so the full stated size domain fits `int`. No duplicated range-query engine or global cache is introduced.

Sources inspected 2026-09-28: [OI Wiki, 离线算法简介](https://oi-wiki.org/misc/offline/) (page revision 2026-05-13), for known-in-advance query reordering and the distinct roles of CDQ, parallel binary search and Mo; [CP-algorithms, Fenwick Tree](https://cp-algorithms.com/data_structures/fenwick.html) (page revision 2026-08-07), for point activation and range-sum costs. Code is independently implemented using the already-verified repository Fenwick. The sum-specific adapter only needs the additive commutative group; the source's opening general-group description is not adopted as permission to perform arbitrary noncommutative Fenwick updates.

Arbitrary interleaved updates/deletions, rollback time decomposition, parallel binary search, CDQ and Mo remain with their existing owners (`20-parallelbinarysearch.hpp`, `21-cdq.hpp`, Data Structures range-query families and Graphs dynamic connectivity). The generic sweep can collect weighted sums or witnesses through caller callbacks without adding another backend.

## MI14: sorting and selection

`11-sorting_selection.hpp` supplies explicit integer-specialized sorts and small standard-library adapters. `std::sort`, `std::stable_sort`, and `std::nth_element` remain the defaults for ordinary comparison problems. No inferred threshold switches algorithms: callers select the specialized integer domain or stability contract deliberately. Container sizes fit `int`. Predicates/projections are pure and depend on element values, not storage addresses or current positions; comparators are strict weak orders. Exceptions propagate, with no rollback guarantee after mutation begins.

| API | Contract | Cost |
|---|---|---|
| `countingSort(a,lo,hi)` | In-place ascending integral values, inclusive `lo<=value<=hi`, non-`bool` signed/unsigned types through 128 bits; `lo<=hi` and `hi-lo+1<=INT_MAX` even for empty input. Integer duplicates are indistinguishable. | `O(n+k)` time, `O(k)` auxiliary counters, `k=hi-lo+1`; empty input returns without allocating counters |
| `stableCountingSort(a,alphabet,key)` | Stable records by integer keys in `[0,alphabet)`, `alphabet>=0`; zero alphabet only for empty input. Non-`bool` integral key types through 128 bits. Exactly one projection per element. Copy-constructible/move-assignable records, no default constructor required. | `O(n+alphabet)` time and space; one record buffer, `n` cached integer keys and alphabet counters |
| `radixSort(a,key=std::identity{})` | Stable ascending full-width signed/unsigned 8–128-bit non-`bool` keys. Copy-constructible/move-assignable records, no default constructor required. A pure projection can be called repeatedly. | `O(n+d*(n+256))` time, `O(n+256)` space, `d<=sizeof(key)` varying bytes; fixed 256-counter stack table |
| `stablePartition(a,pred)` | Standard stable true/false partition, returns first false index `0..n`; stability within both groups, including all-true/all-false/empty. Standard move construction/assignment and value-swapping requirements. | Exactly `n` predicates; `O(n*log(n+1))` moves worst case, `O(n)` with sufficient temporary buffer; up to `O(n+log(n+1))` auxiliary space |
| `quickSelect(a,k,cmp)` | `0<=k<n`; returns a copy of the zero-based kth value in comparator order and partitions the mutated array as `std::nth_element` specifies. Duplicates are allowed; ties and order inside each partition are unspecified. Standard move/swap requirements plus result copy construction. | Average `O(n)` comparisons; GNU introselect heap fallback gives `O(n*log(n+1))` worst case and `O(1)` auxiliary storage in the inspected implementation |

All operation costs count a comparison, projection, copy or move as constant; larger record/user-function costs multiply the relevant work. Stable counting and radix sorts replace vector storage and invalidate retained references/iterators. Counting, partition and selection mutate values in existing storage. Radix avoids an output buffer for fewer than two values or entirely equal keys; it skips any byte constant across the whole input, including internal constant bytes. No signed shifts or overflowing signed range subtraction are used.

### Correctness and implementation choices

Converting a signed `b`-bit key to its unsigned representation and flipping bit `b-1` maps signed order monotonically onto `[0,2^b)`. Unsigned keys use the identity mapping. Counting-domain width is checked through unsigned 128-bit rank subtraction **before** adding one, so even full signed/unsigned 128-bit endpoints cannot overflow the validation. Reconstruction advances the original value only when another bucket exists, so it never increments beyond the maximum endpoint.

Stable counting computes each bucket's exclusive prefix offset. Scattering records in original order increments only their own bucket cursor, preserving equal-key order. LSD radix uses that stable scatter from low byte to high byte; by induction each pass orders by the bytes already processed, retaining their order within equal new digits. A globally constant byte cannot change relative order, so skipping it is exact. Cached counting keys also make its one-projection-per-record contract explicit.

Partition and selection deliberately call the standard algorithms. Selection has no Monte Carlo answer risk and introduces no random seed: the inspected GNU median-of-three introselect implementation is deterministic. Its average bound is not an adversarial linear-time guarantee. After a logarithmic partition-depth budget it invokes heap selection, bounding the worst case by `O(n*log(n))`. Equal keys obey the comparator-equivalence partition contract without a unique-rank witness requirement. Stable partition can fall back to recursive rotations when temporary-buffer allocation is insufficient; the wrapper preserves that behavior.
