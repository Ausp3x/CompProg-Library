## Performance evidence

[Benchmark driver](<../96-Local Testing/05-Mathematics/90-foundations_benchmark.py>), [C++ workload](<../96-Local Testing/05-Mathematics/90-foundations_benchmark.cpp>) and [record](<../96-Local Testing/05-Mathematics/90-foundations_benchmark.json>) contain CPU/compiler/flags, workloads, memory models, one warmup and five samples with medians. Inputs are deterministic. Construction includes allocation; segmented base setup is measured separately from reusable interval queries. Prime outputs are checked outside timing, and timed streaming retains an ordered checksum. No universal timing gate is applied.

On this i9-11900H host, dense tables through 2,000,000 took medians of 6.11 ms for the compact packed-bit reference, 5.10 ms for byte Eratosthenes, and 6.06 ms for linear SPF. Linear SPF supplies additional factor-query data, so the costs are not presented as identical features. Their stored table costs are roughly one bit, one byte, and four bytes per integer respectively, plus prime vectors.

For a low interval of length 2,000,000, plain/odd/wheel-30 streaming measured 12.22/5.08/7.71 ms. Near `10^12`, the same span with 32,768-integer blocks measured 39.16/56.50/85.62 ms; 262,144-integer blocks measured 21.58/13.80/21.23 ms. Thus block setup and base scanning matter at high endpoints. Plain, odd and wheel modes remain explicit choices, with a compact odd default and configurable block size. The record includes short/common/large intervals, both endpoint scales and 1,024-integer blocks. No specialized reduction backend or ISA-specific Mathematics code was introduced. Standard arithmetic, search and counting routines have algorithm/evaluation-count justification rather than a machine-specific optimization claim.

## API migration and remaining scope

The segmented-sieve constructor now consistently means **`[L,R)`**. Use `SegmentedSieve::fromClosed` for old closed intervals; it rejects an unrepresentable exclusive maximum endpoint. Divisor sums now use `lll`. There were no active dependent call sites to migrate. Legacy originals remain untouched in `OLD` and `97-Legacy`.

`ModFac` remains available. Its empty with-replacement count is corrected to `combiWR(0,0)==1`. Factorial tables require a prime modulus and `n<mod`; large-index Lucas-theorem/composite counting remains in MA26, while Lucas *numbers* are implemented here. Inverse tables/CRT and general primality/factorization remain with their existing later owners. Enormous segmented queries still require square-root base-prime storage; documentation reports that cost and the tested high-endpoint limits.

There is no unfinished owned P012 feature or verification gap requiring a handoff. Separate planned inventory families remain planned. No online submission or online-acceptance claim was made.
