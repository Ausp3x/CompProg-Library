## 1. Legacy Tarjan/BridgeAlgo t_in and low are never checked against an independent oracle

- **Kind:** test-gap
- **Location:** `96-Local Testing/04-Graphs/09-bridges_articulation_tester.cpp:149`
- **Skeptics unable to refute:** 3 of 3
- **Detail:** The only check on the legacy diagnostics is `legacy.low == tarjan.low && legacy.t_in == tarjan.t_in`. BridgeAlgo::build constructs a Tarjan internally (header line 143) and copies its fields, so this comparison always holds and checks nothing independently. Tarjan builds its own graph through lowlink_detail::graph, which drops loops and reorders edges, so the oracle-checked lowlink(g) results on the original graph do not cover these fields. 93-lowlink.md says t_in and low keep 'their stated meanings', and its feature map row 'Legacy adapters / reset' says diagnostics are checked. Tarjan is an inventory-row operation, so its public fields need an independent oracle. Fix: in runCase, rebuild the legacy graph (or call lowlink_detail::graph(g.n, adj)) and require that tarjan.t_in is a permutation of [0,n) and that tarjan.low[u] matches the independent descendant/back-edge minimum already used in result() at lines 93-100. Alternatively, call result()'s DFS-diagnostic block on that graph with Tarjan's arrays.
- **Repro:** Copy the headers and the tester to /tmp/mut. In /tmp/mut/04-Graphs/09-bridges_articulation.hpp line 127, replace `t_in = std::move(out.tin); low = std::move(out.low);` with `t_in = out.low; low = out.tin;`. Then run `g++ -std=gnu++20 -O2 -o /tmp/mut_t '/tmp/mut/96-Local Testing/04-Graphs/09-bridges_articulation_tester.cpp' && /tmp/mut_t --mode full --seed 1`. Output: `PASS lowlink seed=1 mode=full cases=3651 checks=1450532`. The mutant passes.

## 3. Precondition asserts run inside the binary-lifting getLCA hot loop

- **Kind:** style
- **Location:** `04-Graphs/07-lca.hpp:92`
- **Skeptics unable to refute:** 3 of 3
- **Detail:** 03-cpp.md says: "Judges run with assertions enabled. An assertion ... must stay out of hot inner loops; check preconditions once at the entry of an operation." Line 92 calls the public Forest::isAncestor on every jump level: `for (int j = l; j >= 0; --j) { if (!isAncestor(up[u][j], v)) ...`. isAncestor (line 38-40) calls check(u) and check(v), which are two asserts, and also compares component[] again. Codeforces builds without NDEBUG, so each LCA query pays about 4*(log n + 1) extra bounds comparisons. getLCA has already checked u and v at entry and has already confirmed both are in the same component. Fix: use an unchecked interval test inside the loop, for example `t_in[w] <= t_in[v] && t_out[v] <= t_out[w]` through a small helper with no assert. Keep the checks in public isAncestor.
- **Repro:** Compile without -DNDEBUG and call getLCA(u,v) on a 200000-vertex random tree. Each of the about 18 loop iterations runs check(up[u][j]) and check(v), which are assert(0<=x&&x<n), even though getLCA already validated u and v on line 88.

## 8. functionalOrbit re-checks the successor bound on every Floyd step

- **Kind:** style
- **Location:** `04-Graphs/11-functionalgraph.hpp:18`
- **Skeptics unable to refute:** 3 of 3
- **Detail:** Low severity. This is the only rule finding, and no correctness defect was found. The `step` lambda runs `assert(-1 <= next[u] && next[u] < n)` every time it is called. It is called from all four pointer-advancing loops (lines 21, 24, 27 and 29), so on the Codeforces judge, which has no NDEBUG, the check runs inside the hot loop. 00-Guidelines/03-cpp.md says: "An assertion must not change an operation's asymptotic cost and must stay out of hot inner loops; check preconditions once at the entry of an operation." Checking the whole vector at entry would raise the cost from O(tail + cycle_length + 1) to O(n), and the contract (lines 11-12 and 94-functionalgraph.md) already says the valid successor domain is the caller's responsibility. Fix: keep the entry checks on `next.size()` and `start`, drop the per-step assert from `step`, and reword the 'Only reached endpoints are checked' comment and the doc paragraph. Then update the `orbit-bad-next` probe in the tester, or remove it.
- **Repro:** Rule quote above. With NDEBUG off, `functionalOrbit(next, 0)` on a 200,000-vertex cycle evaluates the assert about 4 * 200,000 times (Floyd phase about 3n steps, plus one lap of n steps).
