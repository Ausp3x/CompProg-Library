## 3. Closing-brace rule violated: seven function bodies end with a lone `}`

- **Kind:** style
- **Location:** `06-Miscellaneous/12-enumeration.hpp:25`
- **Skeptics unable to refute:** 3 of 3
- **Detail:** 03-cpp.md: "Closing braces: a multi-line block ends on the line of its last statement, `return res;}`. This applies to control blocks, function bodies and lambda bodies, and nests: `}}`." Each traversal's last statement is a `while (true) { ... }` loop. The loop's closing brace is attached to its last statement, but the function body's brace is left alone on the next line. This happens at lines 25, 41, 56, 83, 101, 118 and 142. Sibling headers such as 13-knapsack.hpp and 08-sequence_algorithms.hpp nest these as `}}}`. Fix: fold the brace into the preceding line, e.g. line 24 `for (int j = i + 1; j < k; ++j) { a[j] = a[j - 1] + 1; }}}`, line 40 `fill(a.begin() + i, a.end(), x);}}`, line 55 `a.push_back(i);}}`, line 82 `++a[active[j]];}}`, line 100 `changed = active[j]; a[changed] += dir[j];}}`, line 117 `++x;}}`, line 141 `... x = BitOps<U>::flip(x, changed);}}`.
- **Repro:** rg -n '^\}$' '06-Miscellaneous/12-enumeration.hpp'  -> 25,41,56,83,101,118,142

## 5. Detail helpers validate and Optimizer have no complexity comment

- **Kind:** style
- **Location:** `06-Miscellaneous/13-knapsack.hpp:20`
- **Skeptics unable to refute:** 3 of 3
- **Detail:** 00-Guidelines/03-cpp.md says: "One comment line directly above every struct and free function except template and debug code: `// T: O(...), M: O(...)` ...". knapsack_detail::validate (line 20) is a non-template free function with no comment at all. knapsack_detail::Optimizer (line 28) is a non-template struct; its comment on lines 26-27 describes behaviour but gives no S/Q/M bounds. The public KnapsackDP and ValueKnapsackDP comments cover the cost, and other headers in this folder (for example permutation_detail::Multiset and interval_detail) also skip comments on detail helpers. So this is a low-severity finding about following the rule as written. Fix: put `// T: O(n), M: O(1)` above validate. Above Optimizer, add an S/Q/M line that matches the KnapsackDP bound with W = limit, for example `// S: O((W + 1) * (n + 1 + sum(log(c_i + 1)))), Q: O(1), M: O(W + 1) (trace O(n * (W + 1)))`.
- **Repro:** sed -n '19,30p' '06-Miscellaneous/13-knapsack.hpp'

## 8. Complexity comments use mu and lambda without defining them, and separate M with ';' instead of ','

- **Kind:** style
- **Location:** `06-Miscellaneous/14-cyclefinding.hpp:22`
- **Skeptics unable to refute:** 3 of 3
- **Detail:** The complexity comments above floydCycle (lines 22-23) and brentCycle (lines 51-52) say `// T: O(mu + lambda) successor/equality calls on success, O(budget + 1) on` / `// exhaustion; M: O(1) states.` 00-Guidelines/03-cpp.md (Complexity comments) only allows the standard symbols n, m, k, q, V, E, w, b, L, S and out, and says "Define any other symbol in the same comment." Neither comment defines mu or lambda. Line 27 mentions 'tail/period' but never ties those words to the symbols. The rule also gives the form `// T: O(...), M: O(...)` with a comma, but here M comes after a semicolon on a continuation line. Fix: write e.g. `// T: O(mu + lambda) calls on success (mu = tail, lambda = least period), O(budget + 1) on exhaustion, M: O(1) states.` in both places. This is documentation only; the bounds themselves are correct.
- **Repro:** Run `rg -n 'mu|lambda' '06-Miscellaneous/14-cyclefinding.hpp'`. The only hits are the two `// T: O(mu + lambda)` lines, so neither symbol is defined anywhere.

## 9. Multi-line if block in brentCycle closes with '; }' instead of ';}'

- **Kind:** style
- **Location:** `06-Miscellaneous/14-cyclefinding.hpp:65`
- **Skeptics unable to refute:** 3 of 3
- **Detail:** Lines 63-65 are a multi-line `if (power == length) { ... }` block, and its last line ends `power = power > ULLONG_MAX / 2 ? ULLONG_MAX : 2 * power; }` with a space before the brace. 00-Guidelines/03-cpp.md (Style) says: "Closing braces: a multi-line block ends on the line of its last statement, `return res;}`." The space-inside form `{ work(); }` is only for single-line blocks. Every other multi-line block in this header (lines 19, 43, 47, 67, 72) already uses `;}`. Fix: change the end of line 65 to `2 * power;}`. This is cosmetic and does not change behavior. Sibling headers such as 07-permutation.hpp break the same rule, but that is outside this package.
- **Repro:** Run `sed -n 63,65p '06-Miscellaneous/14-cyclefinding.hpp'`. Line 65 ends in `2 * power; }`.
