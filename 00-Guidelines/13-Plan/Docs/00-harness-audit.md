## Design

- **Sources.** The transcript is the hook's `transcript_path`, a subagent's own `<session>/subagents/agent-<agent_id>.jsonl` when the hook carries `agent_id`, else the session of `$CLAUDE_CODE_SESSION_ID`. The global config follows the client's own rule, read from the 2.1.322 release (its `.claude.json` half confirmed by the strip test): a legacy `.config.json` in the config folder (`$CLAUDE_CONFIG_DIR`, else `~/.claude`) when it is a non-empty file, or an empty writable one while the new file is missing; else `.claude.json` (`.claude-custom-oauth.json` under `CLAUDE_CODE_CUSTOM_OAUTH_URL`) in `$CLAUDE_CONFIG_DIR`, else in the home folder. Only the last 1 MiB of a transcript is parsed, and the last 16 MiB when a larger record (a big tool result) hides the newest reply, which past that is a `blind reply` warning; JSON nested deeper than Python parses counts as a broken line; the client re-appends its `atis-latch`, `agent-setting` and `last-prompt` records every few calls, so they stay in it. `.credentials.json` is never opened. The guard's state (`.claude/hooks/.state/harness/`) lives in the main checkout, found through a linked worktree's `.git` file (a bare repository's worktree keeps its own), so hooks and `--selftest` agree whichever checkout a session runs in.
- **Experiment.** The newest `atis-latch` of the main transcript (empty: none), its key from the slot with the same id; without a latch the newest slot of the model (context suffix dropped) and entrypoint, and `none` with a note when there is neither. A latch without `atis` or with a non-hex value is a `blind` issue.
- **Mappings.** Any object in the newest slot of the model and entrypoint (else the newest slot of any model) whose keys and values are all model ids, whatever its key; one mapping the current model warns. A model id is `claude-<words>-<1–2 digits>(-<1–2 digits>)*` or the older `claude-<digits>-<words>`, with an optional 8-digit date and context suffix such as `[1m]`, so betas (`claude-code-20250219`) and family keys (`claude-fable`) are not ids. Objects keyed by model ids with other values are noted as unknown shapes.
- **Allowed set**, read at every check: `models` in `packages.json`, the `model:` of `.claude/agents/*.md` and `.claude/skills/*/SKILL.md`, and `models` in `.claude/harness.json` (`claude-haiku-5-5`, for built-in agents that run on Haiku, such as Explore). A `packages.json` or front-matter value that is not a model id (an alias) is reported, never allowed; a `harness.json` entry is an exact id of any shape, so Bedrock and Vertex ids (`us.anthropic.claude-opus-5-5-v1:0`, `claude-opus-5-5@20261101`) can be allowed (user decision 2026-11-11).
- **Model check.** The newest non-synthetic reply's served model (`message.model`) against its requested one (`requestedModel`, else the newest `model` attachment before it), both against the allowed set, and the newest request's `params.model` against it; a model value that is not a string is off the set. A dated snapshot of the requested model (`claude-opus-5-5-20261101` for `claude-opus-5-5`) is refused as off the set until the allowed set names it, and then passes the mismatch check too, so `harness.json` is its remedy (user decision 2026-11-11). The hooks return a deny as soon as a model check fails, before the slower checks. These checks run first and on their own: any later check that raises on input of unknown shape becomes a `blind checks` warning (and an `errors.log` line), and a failed heartbeat write is logged, so neither can switch the guard off. The main-thread hooks and the live status line also read every subagent transcript of the session that changed since the last read, since a subagent's last reply (usually its hand-back) reaches its file only after its SubagentStop hook ran (user decision 2026-11-11). They keep its newest reply and request (`subagents.json`, merged on every write) and check them against the current allowed set, so allowing a model clears a pending failure, until a main-thread PreToolUse refuses a call for that reply, once per reply (the status line marks such a failure `sub`); a subagent's own hooks check only its thread, and the report and `--experiment` leave the state alone. All output is redacted before it is cut to length and has control characters turned into spaces, so a label never leaks part of a secret or splits the status line.
- **Request settings** of the request that produced the newest reply (warnings only, user decision): its effort against the union of the chosen efforts (user decision 2026-11-11) — the `--effort` of the Claude Code process (`/proc/$CLAUDE_PID/cmdline`, live session only), every `/effort` command of the session (kept in `effort.json` once seen, so none scrolls out of the tail), `effortLevel` and `modelSettings.<model>.effortLevel` in the settings, the running skill's front matter, a per-turn effort that differs from the session's, and a subagent's own `meta.json` or front-matter effort; for a transcript other than the live session the session effort the reply records counts as chosen. The session agent's front matter is no source, since the client ignores it for a main session (CLAUDE.md, Models and delegation). `CLAUDE_EFFORT` is deliberately not a source: it is the effort the client applies, which a server-side default would move with the request. `thinking` and `context_management` against `request.expect` in `harness.json`, `max_tokens` against `CLAUDE_CODE_MAX_OUTPUT_TOKENS` when set, any change of those three between the tail's requests of the same source and model, any params field other than `model` that names a model (a fallback list), and any field missing from `request.fields`. A missing `model`, `max_tokens`, `thinking`, `context_management` or effort is a `blind` issue.
- **Hide-from-user text.** Attachments without file, typed-prompt or local-hook content (`path`, `files`, `filename`, `prompt`, `hookName` and similar keys, also one level down), `system` records and the slot's strings are matched against instructions to hide something from the user ("don't mention … to the user", "without telling the user", "hide … from the user"; "do not tell the user to …" is an instruction, not hiding). Each match is reported by location and a 12-hex hash of its normalized sentence (the match alone when the sentence runs over 200 characters to either side; at most 20 matches per text, so a long run-on text stays fast), never its text; `accepted_texts` in `harness.json` silences a reviewed hash (user decision 2026-11-11), and the guard keeps the session's sightings in `.state/harness/<session>/hide.json`.
- **Hooks off.** A true managed key naming hooks (`allowManagedHooksOnly`, `disableAllHooks`) in `/etc/claude-code/managed-settings.json`, `managed-settings.d/`, the macOS or Windows managed folder of the running platform or the cached `remote-settings.json` and `policy-limits.json`, or a true `disable…Hooks` key in the user, project or local settings.
- **Hooks** (`.claude/settings.json`): `harness.py hook` on PreToolUse `*`, Stop, SubagentStop, UserPromptSubmit and SessionStart `startup|resume|clear`, timeout 10 s, failing open on its own errors into `.state/harness/errors.log`. PreToolUse writes the call's check to `.state/harness/<session>/<tool_use_id>` and `last.json`, then denies the call and stops the turn (`continue: false`, `stopReason`, `permissionDecision: deny`, naming the models and the files that allow one) on any model issue; otherwise it shows each new warning once per session as `systemMessage`. Stop and SubagentStop warn about a model failure of the newest reply on disk, and record whether it follows the last user record and which tools it called (`stop.json`, user decision 2026-11-11); a turn's final reply is written after them, so UserPromptSubmit warns about it when the next prompt is sent, before the model runs (user decision 2026-11-11). Every guard text avoids the hide-from-user phrasing, so the guard never flags its own messages. SessionStart shows the warnings outside the terminal entrypoint (`CLAUDE_CODE_ENTRYPOINT` other than `cli`), where no status line runs. When the served-model check fails, the message lists that reply's tool calls (tool names and repo-relative file paths, no command text) and points to `/rewind` (user decision 2026-11-11). PostToolUse and PostToolUseFailure `*` run the context-integrity check of the output alone, reading no transcript; PreToolUse and UserPromptSubmit add its input rewrites, ask and prompt warning (Context integrity).
- **Status line.** `exp <first 6 hex digits>` after the cache part, then one `⚠` item per warning in this order: `map`, `model` (mismatch, off-list), request setting, `blind`, `guard idle` (the newest finished tool call has no heartbeat), `hide-text`, `hooks-off`, `client` newer than `audited_version`. A harness failure shows `⚠ harness error` and leaves the rest.
- **Format drift.** A global config that is not a JSON object is drift. `slot_format` holds the global config to the cache format this audit found: a `clientDataCacheSlots` object of slots with a numeric `at`, string `model` and `entrypoint` and an object `data` whose `atis` is absent, null, empty or hex and whose `experimentKey` is absent, null or a string. A config without the container has no slots yet, unless the latch shows an id that no slot can then hold (a renamed container, user decision 2026-11-11). Each departure is a `⚠ slots format` warning that names this package for a re-audit, and without a latch the experiment becomes `unknown`, which `--experiment` prints instead of a false `none`.
- **`--selftest`** passes when the effective settings run `harness.py hook` on PreToolUse and PostToolUse for every tool and on Stop, SubagentStop, UserPromptSubmit and SessionStart, no setting can disable hooks, the allowed set is not empty and the session's newest heartbeat (`last.json`, whatever the tool ids look like) is at most 120 s old (the Bash call that runs the self-test fires PreToolUse first). Claude runs it as a command, so it reports an inactive guard even with hooks off.
- **Launcher** (user decision 2026-11-11): `python3 .claude/launch.py [claude arguments]` removes `atis` and `experimentKey` from every slot of the global config under the client's own lock directory (`.claude.json.lock`, as its proper-lockfile saves use), writing atomically with the mode kept, then execs `claude`. It writes nothing, says why on stderr and still launches when the lock stays held over 2 s or cannot be created, the file is unreadable or a symbolic link (replacing a link would leave the ids in its target), or the format drifted: not a JSON object, a `slot_format` problem, or a removed id still found in another value of the config (user request 2026-11-11: a format change leaves the launcher inactive and asks for a re-audit of this package). A failed write leaves the config and no temporary file behind (`the global config could not be written`), and a lone surrogate in the config, which JavaScript writes, is kept as an escape. An internal error, a broken `harness.py` included, also launches and asks for a re-audit; no global config means nothing to strip. On 2026-11-11 the user's config matched the format and held no copy of its ids.
- **Package record.** `/package` step 1 runs the self-test and stops on FAIL (`/finish` step 1 repeats it); step 8 writes `harness.py --experiment` beside the latest run's date in the evidence; `/finish` step 7 appends it as the `experiment` column of `finish-log.tsv`, which `context_usage.py --split` groups by. The 32 earlier landings keep their rows byte-identical, since the file merges with `merge=union` (user decision 2026-11-11), and their experiments, read from the latches of their `/finish` sessions (every latch before 11-06 is empty), are recorded here: `20ad9e294a99b4cb -` for P263, `10b5eb02098330f1 claude_code_turnstone_plinth_experiment` for P274–P276, `none` otherwise.

## Weekly scan (SUP29)

User decisions 2026-11-11:
- a weekly scan in every clone, for each user's own `~/.claude`;
- the canary opt-in per clone and off by default, with the settings below kept as Claude chose them (thresholds, budget, timeout, tolerance, the dsu and manacher tasks, the `compprog.canary` switch);
- a plain `/harness-audit` scan never runs the canary (`--no-canary`);
- `NEEDED` holds only the keys every record of their type carries;
- redaction also covers GitHub, AWS key-id, Slack and JWT token shapes, and `texts.json` is pruned.

- **Sources.** The transcript folders of the clone in `<config folder>/projects`, named by the client's rule (every character other than a letter or digit becomes `-`): the main checkout's exactly, a top-level folder's alone or followed by `-…` (sessions started in a subfolder, and through `.claude` every `.claude/worktrees/<x>`, deleted ones included), and each worktree `.git/worktrees/*/gitdir` lists; a sibling clone such as `…-Library-2` is not one of them. Main transcripts, then each `<session>/subagents/*.jsonl`. Also the global config (Design, Sources), `cache/model-catalog/*.json`, `cache/changelog.md`, `session-env/*`, every settings layer (`harness.py` `layers`) and the names under the project's `.claude`. `.credentials.json` is never opened.
- **Fingerprint.** Record sections, each item with its count and first and last record time: record types, attachment types, system subtypes, keys per record type, message keys, the `model` attachment's key paths, usage key paths, `input_transformations` (type and reason), cache-miss reasons, stop reasons, betas, request param paths and `path=value` pairs other than betas (the records hold no messages, system or tools), query sources, served and requested models, efforts (request, reply, per-turn), latches, client versions, request shapes, prompt paragraphs per client version (`api-request-shape` system blocks and tool descriptions split at blank lines, and tool schemas, hashed after digits, hex runs and secrets are normalized) and injected texts (attachments without file, prompt or hook keys, as `harness.py` scans them). Snapshot sections, each item with a value: top-level global-config keys with their types, GrowthBook flags (value hashes) and their prompt texts (strings of at least 40 characters with a space; every string of a flag or slot, however short, to twelve levels deep as `harness.py` reads strings, is scanned for hide-from-user text), `tengu_amber_tally` flattened, experiment assignments and variations (`cachedExperimentData` `experimentId v<variationId>`, and each slot's id and key), slot fields, keys and prompt texts, file and directory names (two levels, four under `projects/`, ids and digits normalized, and the entries of folders of per-session or per-item files such as `session-env`, `todos`, `file-history` or `shell-snapshots` reduced to `<item>` and their extension), environment variable names of the settings `env` blocks and `session-env` files (never values), managed or policy keys that could disable hooks or set the model or effort (`model`, `effortLevel`, `availableModels`, `modelSettings`, `alwaysThinkingEnabled`, `hooks`, `agent`, any key naming hooks, `env` names with MODEL, EFFORT, THINK, OUTPUT_TOKENS or HOOK) with `harness.py`'s hooks-off keys, and the model catalog with its aliases (`provider_alias_targets`); every snapshot key and value and every record item is redacted before it is stored. Metrics: the per-experiment table, cache writes per day and thread, tool-output sizes, compactions and hide-text sightings.
- **Per-experiment table** (SUP28's measurement, kept per scan): replies once per message id (a later record of the same reply adds only its larger usage), keyed by the newest latch before the reply (a subagent's by its session's latch when the subagent was read, since subagent transcripts hold none), served model, reply effort and thread; mean output and thinking tokens and the change against the `none` row of the same model, effort and thread.
- **Findings**, removed fields a SUP28 check needs first (`needed`: the record types, keys, message keys, request params, the `model` attachment and its `identity.modelId`, `clientDataCacheSlots` and slot fields that `harness.py` reads and every record of their type carries; an optional key such as `attributionSkill` or `rendered` is a plain diff when gone). A record item is removed when it was seen in the week before the previous scan's newest record and not in the week before the newest record now; a snapshot item when it is gone. Then the section diffs (`diff`), the tally (`tally`), GrowthBook and slot prompt texts (`texts`, quoted), prompt paragraphs (`prompts`: new within a client version already seen, or for a new version the paragraphs new and gone against the newest older one, quoted), new injected texts of an attachment type with fewer than 20 distinct texts (more is session data such as git status, listed in the report only), the client version with the cached changelog entries since the previous newest version (`client`), hide-from-user texts by `harness.py`'s rule and hash with their sentence (`hide`, silenced by `accepted_texts`), automatic compactions read since the last scan below 90% of `autoCompactWindow` (`compaction`), a 1-hour share of cache writes below 99% per thread since the last scan (`cache`), a tool whose output was saved to a file below 90% of its largest earlier inline result and of its smallest earlier saved one (`toolcap`), every managed item (`managed`), an alias whose default target lies outside the allowed set while the set names a model of its family (`alias`), and the canary's (`canary`). The first scan is the baseline: no diff, prompt, injected or client findings. A finding that recurs at every scan takes its id from its subject: `hide` from the sentence hash, `cache` from the thread and the share in 5% steps, `toolcap` from the tool and the size in KB, `managed` from the item and its value, `alias` from the alias and its target. So once reviewed it stays reviewed until its subject changes. Every other finding hashes its kind, title and lines, and arises once, from the diff against the previous scan or the bytes read since it. An unreviewed finding stays in each later scan, with the time of the scan that found it, until it is reviewed.
- **Output** in the main checkout's `.claude/harness-audit/`, git-ignored since it holds account data: `cache.json` (per transcript, keyed by a digest of its path, which holds the session id: its size, mtime, read offset, head hash, parse state with message and tool ids digested, and summary), `texts.json` (the quoted texts, secrets redacted, only those the newest and the previous fingerprint quote), `history/<UTC time>.<µs>.json` (the last 100 fingerprints), `findings.json`, `report.md`, `status.json`, `reviewed.json`, `usage.json` and `canary/`. A transcript whose size and mtime are unchanged is not opened; one that only grew is read from its offset, a line without its newline being left for the next scan; one that shrank or whose head changed is read again. The summary of a transcript Claude Code deleted (`cleanupPeriodDays`) stays, so its items and metrics outlive it. Every report line and finding is redacted (`harness.py` `redact`: e-mail addresses, UUIDs, `sk-` keys, `msg_`/`req_`/`toolu_` ids, GitHub, AWS key-id and Slack tokens, JWTs). A record time after the scan (5 minutes of skew allowed) counts as no time, so it never becomes the newest record.
- **One scan at a time**: an `flock` on `scan.lock`, which ends with its process; a second scan prints `another scan is running` and writes nothing.
- **Trigger.** The startup SessionStart hook (`source: startup`, not resume or clear) starts `harness_audit.py scan --due` as a detached process when `status.json` is missing, over seven days old or past a canary retry time, and never under `CP_HARNESS_AUDIT_CHILD` (the canary's own sessions); `--due` checks again under the lock. The status line shows `audit N new` while the newest scan has unreviewed findings, and records the plan usage of its status JSON in `usage.json` (on a change, else every five minutes) for the canary. `/harness-audit` runs the scan without the canary, has Claude explain the new findings and marks them reviewed. A scan saves its cache, texts, fingerprint, findings, report and status before any canary runs, and the last three again after it; a failed scan's status drops a pending canary retry, so it waits a week.
- **Canary** (opt-in per clone: `git config compprog.canary true`). With the scan, when its last run is over seven days old or on `scan --canary`: for each task of `canary` in `harness.json` (dsu and manacher: two verified contest headers with fast oracle testers), a scratch copy of the main checkout's HEAD (`git archive`) loses the task's header and is then committed as a repository of its own, so its Claude hooks and validator run as in a clone and no git command can restore the header (signing and git hooks off; a failed git step fails the task); then `claude -p` at the exact model id and effort (`--output-format json --permission-mode acceptEdits --no-session-persistence --max-budget-usd 3`, `CP_HARNESS_AUDIT_CHILD=1`) is asked to write it; the task's tester in full mode is the oracle. A task passes when claude exits 0, the header exists, `git status` of the copy shows no other tracked file changed and the tester passes. A task whose header or tester path resolves outside the copy is not run; damaged claude output, a tester timeout or any other error fails that task alone, and the run is still recorded (a damaged line of `runs.jsonl` is skipped). The first run in which every task ran with claude exiting 0 is the baseline; a lower pass rate, a task failing that passed in it, or more than 1.5 times its tokens is a finding. It skips (retried an hour later) while the freshest usage record (the status line's, else the client's `cachedUsageUtilization`) is older than an hour or shows the 5-hour usage above 50% or the 7-day above 80% (`max_five_hour`, `max_seven_day`); in a fresh record a window past its reset counts 0. Each run records tokens by type, list-price cost, the 5-hour usage before and after (its change only from a usage record taken after the run started, else none), and a credit estimate from `tengu_amber_tally` (Canary cost).

## Context integrity (SUP30)

User decisions 2026-11-11: detect instruction-like content in untrusted context, keep provenance and neutralize it where the existing hooks allow, automatically, with no new skill, command or setting; then every limit's fix (the separate MCP output key dropped, since the repository uses no MCP server) and Bash output kept note-only.

- **Trust boundary.** Claude Code delivers its own `<system-reminder>` texts as `attachment` records, never inside tool output: across this clone's five newest transcripts, 0 of the tool results whose tool was known held one in its content, against 23 attachment types that do (the 4 Bash hits were `rg` over this repository's documents). A wrapper tag in a tool response is therefore data from the tool's source. The system prompt, CLAUDE.md, memory and attachments never pass through a hook that can change them and are never touched.
- **Provenance.** Trusted, never scanned: AskUserQuestion, ExitPlanMode, EnterPlanMode, Skill, ToolSearch, Edit, Write, MultiEdit, NotebookEdit and TodoWrite (the user's answers, Claude Code's catalog, the repository's skills, Claude's own writes), an Agent response's `prompt` and `description` (Claude's own text echoed; a Bash response's `bashEditDiff` is scanned and noted, since a command can write downloaded text into a file: user decision 2026-11-11), and Read, Grep, Glob and LSP when every path (relative ones against the hook's `cwd`, none meaning `cwd`) lies inside the checkout or its main checkout and `git check-ignore` ignores none (`in_checkout()`, run only once content was flagged): a pull request's `.claude/worktrees/PR<N>`, `96-Local Testing/.judge-cache/` and `.claude/harness-audit/` stay untrusted, and so does every path when git fails. Escaped: WebFetch, WebSearch, Agent, Task and SendMessage. Noted: every other tool (Bash, `mcp__*` until a live MCP check shows the client applies `updatedToolOutput` to it, user decision 2026-11-11; file tools elsewhere, tools unknown today) and every failed call.
- **Detection** (`scan()`): blocks first. A tag is `strong` when its name or a part is a harness word (`system`, `reminder`, `instructions`, `antml`, `human`, `assistant`, `function_results` and the like), `weak` when it holds `-`, `_`, `:` or `.` or a role word, `plain` when it is any other name that is no HTML, SVG or MathML element, and no wrapper otherwise. Tags pair with a stack (depth 64), so nesting resolves to the outermost flagged block and partial overlaps widen it. A closed block counts when `strong`, when `weak` around text addressing the model (`DIRECT`: the `AIM` set below, `you must …`, `from now on`, `system prompt`, a line opening with `IMPORTANT:` in capitals) and when `plain` around text aimed at the model (`AIM`); a `strong` or `weak` tag left open reaches the end of its paragraph or its parent's close and counts by its text; a `strong` stray closing tag counts. Tag names drop invisible characters (zero-width ones, joiners, direction marks, invisible operators) and read Unicode dashes and the soft hyphen as `-`, and attributes may have any length (they end at the next `<` or `>`, so matching stays linear); a blank line, also a diff's `+` or `-` one, ends a paragraph. Documentation counts for nothing: code spans and fenced blocks (an open fence runs to the end), a tag after a backslash, a lone tag with a quote on both sides (`"<system-reminder>"`; such tags still pair, and a quoted pair counts by its text as a `weak` one, user decision 2026-11-12; a block inside a quoted string, as JSON from `gh` or an API holds it, counts), and an opening tag glued to a word unless its name holds `-` (`List<String>`, `(?P<system>`; no identifier holds `-`, so a glued `x<system-reminder>` counts, and a glued one-word tag still shows through its closing tag as a stray). Then up to 20 unwrapped directives per string outside the blocks, code and quotes: the `AIM` kinds `hide` (the hide-from-user pattern), `ignore` (`ignore … previous instructions`), `persona` (`you are now`, `pretend you are`), `system` (`new system prompt`, `developer mode`) and `model` (Claude, the assistant, the AI or an AI agent `must …`), and `role` for a `Human:` or `Assistant:` line.
- **Cost.** `DIRECT` runs on an ASCII-lowercased copy (offsets kept) only in windows around trigger words found by one cheap pass, and serves the prose lines too, since it leads with `AIM`'s named alternatives; matches and paragraph breaks are looked up by bisection; possessive code-span and fence patterns keep backtick and tilde runs linear. At most 8 MiB per response (one budget however many strings it holds: user decision 2026-11-11), 20,000 tags and 64 open tags per string, and `DIRECT` searched in at most 1 MiB of windows per string (`WINDOW_CAP`, user decision 2026-11-11), so 8 MiB of trigger words scans in under 1 s. The prose patterns compile at their first use, so a hook call that scans nothing pays nothing for them.
- **Output hooks** (`integrity()`, PostToolUse and PostToolUseFailure `*`): escaped tools get every non-markup tag inside a flagged block rewritten to `&lt;…&gt;` through `updatedToolOutput`, the response's shape and every other character kept; prose lines are only noted; noted tools keep their output byte-identical, since Claude may edit or diff it; a failed call's error is noted, since it cannot be replaced. Each flagged output adds one `additionalContext` line naming the tool, the counts, up to 8 tag names and the prose kinds, never the text, and updates the session's `integrity.json` (count per tool, the turn's flag, the newest escaped call, WebFetch hosts fetched) under an `flock` on `.integrity.lock`, so parallel tool calls' hooks lose no update (16 parallel runs kept 14 to 16 counts in 5 trials without it). Escaping is final: escaped output has no tag left to flag. The record is fail-open: a lock another process holds is passed by after 1 s (50 non-blocking tries), and a record that cannot be written (read-only or full state folder) is lost while the escape, note and prompt warning still go out.
- **Input hooks** (`pre_integrity()`, PreToolUse): blocks Claude copied into an Agent, Task or SendMessage prompt are escaped and `PREFIX` goes before every WebFetch prompt, through `updatedInput`; the prefix asks the fetch's model to quote text on the page that addresses an AI inside `<page-instructions>` tags (a harness-shaped name, so the output hook escapes and notes it). In a turn whose tool output was flagged, an outward call asks the user (`permissionDecision: ask`): a Bash command naming a network program (`curl`, `wget`, `gh`, `ssh`, `rsync` and others, or `git push`, `fetch`, `pull`, `clone`, `remote`, `ls-remote`, `submodule`, `send-email`) anywhere in it, or code an interpreter or shell gets whose network use the command does not show (flags then `python3 -c`, `-m`, `-` or `<<`, `node -e`, `perl -E` and the like, `bash -c` or `-lc`, a pipe into an interpreter or shell with no script named, such as `| sh`, `eval`, `source <(…)` and `/dev/tcp` or `/dev/udp`; `python3 sol.py < in.txt`, `cat in | python3 sol.py` and a script by path do not ask; network programs match anywhere in the command, user decision 2026-11-11, and git's remote verbs only as its subcommand, after global flags with their arguments, quoted ones included; widened by user decision 2026-11-12: a `~/` path or `\` before a program name, `|&`, `sudo`, `env`, `nice`, `nohup`, `timeout` and like wrappers after a pipe, and flags taking one argument such as `-X dev` or `-O extglob`; every loop of the pattern is possessive or unambiguous, so a 200,000-character command takes under 0.1 s), WebSearch, a WebFetch to a host not fetched before in the session, and any MCP tool. The next prompt clears the flag; a model-guard deny comes first.
- **Prompt warning** (UserPromptSubmit): flagged blocks holding a harness-shaped tag, also one nested in another block, in a typed or pasted prompt are named to the user in a `systemMessage`, beside a model-guard warning when both apply; the prompt is never changed or blocked, and prose is not checked, since the prompt is the user's intent.
- **Status line and drift.** `⚠ integrity N` counts the session's flagged outputs (one `systemMessage` per session at PreToolUse); `⚠ blind integrity` reports a PostToolUse or PostToolUseFailure payload without the `tool_response` or `error` the check reads, and `⚠ integrity escape` an escaped call whose result reached the transcript unescaped (Claude Code's own `<persisted-output>` wrapper aside), which the transcript shows because it stores the replaced output (observed 2026-11-11), so a client that stops applying `updatedToolOutput` is seen at the next check. `--selftest` requires the PostToolUse and PostToolUseFailure hooks.
- **`/merge-pr`** (`instructions()` in `merge_pr.py`, step 1): every block or prose line of a changed text file of the pull request whose lines include an added one is listed as `INSTRUCTIONS` (path, first added line, label), and the user confirms each is meant before checkout, since a landed file is trusted context. `added()` reads the diff as bytes split at newlines only (a lone carriage return or a non-UTF-8 byte moves no count) and by its hunk counts, so an added line starting with `++ ` is no file header, unquotes the paths git quotes and fixes the `a/` and `b/` prefixes whatever the user's `diff.noprefix`; a file is binary, as git decides, when a NUL lies in its first 8000 bytes; `decisions()` uses it too (SUP19's code, fixed here by user decision 2026-11-11). The scan is uncapped (`scan(cap=False)`: no 8 MiB, tag, window or line limit, only the 64 open tags), so a file already holding 20 directives or 20,000 markup tags hides no new one. ## Limits

- The served model of a reply is checked only once the reply is on disk: after its tool calls ran, and for a turn's or a subagent's last reply after the Stop or SubagentStop hook (Verification of the hook timing). A text-only reply is already shown when the next prompt warns about it, and a subagent's last reply has already reached the main thread when its failure refuses the next main-thread call.
- Only the model the API reports in `message.model` can be checked; a server that serves another model under the requested name is invisible.
- Tool results and `api-request-blob` records (the text actually sent) are not scanned for hide-from-user text, since they hold prompts, file, command and web content; a server text that reaches the model only there is not seen. The scanner's recall is shown on synthetic fixtures only: no hide-from-user text occurs in this project's transcripts.
- The effort check accepts the union of the explicit choices, so a choice that a later one replaced still passes; when nothing was chosen explicitly the effort is not checked.
- Mappings are found by the model-id shape, so a slot mapping Bedrock or Vertex ids is not recognized.
- That a UserPromptSubmit `systemMessage` stays out of the model's context is assumed from the SessionStart and PreToolUse result, not observed.
- No session has run in a linked worktree yet; the state-folder rule is tested on a synthetic worktree layout.
- The launch flag is readable only where `/proc` shows the Claude Code process (Linux, the platform `/setup-check` supports); without it the explicit choices (agent, settings, commands, skills) remain.
- A front-matter alias such as `model: opus` is reported, not resolved.
- `--selftest` needs `$CLAUDE_CODE_SESSION_ID`, which Claude Code sets for the commands it runs; from a terminal it fails.
- The launcher's strip lasts until the server's next slot fetch.
- Weekly scan: the removal rule needs a week of records on both sides, so a field dropped less than a week before a scan is reported by a later one. Prompt paragraphs that hold session data (the memory index, the environment) change with it, so a `prompts` finding within a client version may name local text; the explanation in `/harness-audit` tells them apart. A subagent's replies take its session's latch at the time the subagent was read. Tool-output caps are inferred from the sizes the client prints, not read from the client. A compaction is judged against the current `autoCompactWindow`, not the one in force then. A `cache` finding takes a new id whenever a thread's share crosses a 5% step, and a `toolcap` one at each new low. Transcript folders are found by the naming rule alone, and the lock needs `flock` (Linux and macOS).
- Canary: the 5-hour usage change it records includes any session running meanwhile, and its `tengu_amber_tally` credit estimate weights every token type alike, which the table does not state. Usage is read from the status line's record, so a start with no record from the past hour skips, and the retry comes with the first session start an hour or more later.
- Context integrity changes only tool input and output, the two things a hook may replace. A typed or pasted prompt is warned about (blocks only), never changed; the system prompt, CLAUDE.md, memory and attachments (Claude Code's reminders, @-mentioned files, hook output) are counted by the audit after the fact only, and compaction summaries not at all. An instruction already in context is flagged, never removed.
- Bash output, failed calls and files read outside the checkout or git-ignored are only noted, so the block stays in context beside the note, which is advisory context, not enforcement. The ask after a flag reads only the command line: a script run by path, or a program outside the lists, that reaches the network passes; the flag lasts until the next prompt; the record's lock needs `fcntl` (Linux and macOS), and elsewhere, or past a 1 s wait, parallel runs can lose a count.
- WebFetch's output is its small model's answer, not the page: the prefix asks that model to quote what addresses an AI, but an injection it follows, or restates without tags, is not seen, and the fetch's own model is outside the hooks.
- Detection is structural and heuristic: a plain one-word tag counts only around text aimed at the model, past 1 MiB of trigger-word windows a string's text is no longer read, so weak, plain and quoted blocks, unclosed tags and prose lines there are missed (strong blocks and stray tags still count), homoglyph names (a Cyrillic `ѕ`) are not normalized, a directive outside the `AIM` and `DIRECT` phrasings is missed, and an unquoted harness-shaped block in documentation is flagged (its text kept). Past 8 MiB per response, 20,000 tags, 64 open tags or 20 directives per string (the hooks) nothing more is seen.
- In auto mode, each rewrite of a call auto mode reviews (Agent, Task, SendMessage) costs one refused call, which Claude resends with the hook's input.
- The audit does not rescan tool results read before SUP30, and counts Bash reads of SUP30's own files, which quote attack strings. Untracked, unignored files inside the checkout are trusted like tracked ones; `/merge-pr` lists only a pull request's added lines.
- Shown on fixtures only: the ask after a flag (no outward call followed a flagged output live), MCP output (no server connected), the PostToolUseFailure note, Agent, Task and SendMessage output escaping, the prompt warning, `integrity N`, `blind integrity`, `integrity escape`, file-tool provenance and the fail-open paths. Observed live: the Bash note (also in a subagent), WebFetch and WebSearch escaping, the WebFetch prefix and the Agent prompt rewrite (Live checks).
- Known one-step evasions, kept since each rule prevents documentation false positives: an unclosed fence hides everything after it, a tag after a backslash is skipped, and a one-word tag around text that is not aimed at the model counts for nothing. Web components (`<app-root>You must enable JavaScript…</app-root>`) are flagged, and so are a quoted harness tag holding text in code (`s = "<system-reminder>x</system-reminder>"`) and a quoted pair around text addressing the model in documentation. The network ask matches program names anywhere (`rg -n mail docs` asks after a flag) and misses forms outside its lists (another wrapper, an alias, a script by path). On a hostile 8 MiB response the scan takes up to 0.7 s, besides a `git check-ignore` of up to 5 s for file tools.
