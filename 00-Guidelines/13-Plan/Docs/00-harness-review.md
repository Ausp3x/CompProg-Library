## Contracts

### Settings (`.claude/settings.json`, `.claude/settings.local.json`)

- `worktree.baseRef: "head"`: new worktrees, including `--worktree` sessions and isolated subagents, branch from the local `HEAD` (inside a worktree, that worktree's `HEAD`), so unpushed commits on `master` carry over and nothing needs a push first. `01-prompts.md` (Workflow) and `AGENTS.md`, whose manual recipe now branches from `HEAD`, say so.
- `skillOverrides`: claude-api, dataviz, artifact-design, artifact-diagramming, artifact-capabilities, run, init, schedule, plugin-authoring and security-review are `"user-invocable-only"` (hidden from Claude, `/name` still runs them); workflow-authoring and update-config are `"on"`. Reason (user decision 2026-11-19): the skill listing took about 14,000 characters a session for 27 skills, and claude-api loaded itself 5 times at about 105–114 KB each, while none of these serves library work.
- `enableArtifact: false` turns the Artifact tool off for every session of the project; no file can turn it back on.
- `syncClaudeAiSkills: false` sits in `.claude/settings.local.json` (git-ignored), since the key's scope is user, local or managed and a project value is ignored. It applies to this clone only; another clone sets it in its own local or user settings. In local settings Claude Code stops loading the synced skills but does not move them to `~/.claude/skills/.trash/`.
- `includeGitInstructions` stays on, so sessions keep the git status snapshot.

### Hooks

- **PreCompact** (`resume.py precompact`, no matcher, timeout 60 s): stdout becomes instructions for the compaction summary, which Claude Code caps at 10,000 characters per hook; the script keeps under 9,000. It names the target (the batch or package id of the session's last typed `/package`, `/prune` or `/finish` call, else the branch or worktree name, through `gaps.py`'s `target()`), says which of the two named it (the typed command that gave the argument, cut to 80 characters so the later lines always fit), names the skill to resume and asks for its step number and the exact next step, gives the `/finish` ledger path (existing or not yet written; no line without a target or ledger) and the keep and drop lists of `CLAUDE.md` (Compact Instructions). It always exits 0: exit 2 would block the compaction, and a failure prints nothing. It shares `last_command()` and `ledgers()` with the `compact` SessionStart mode; `/pause` (`pause.py`) uses `last_command()` too.
- **Notification** (`notify.py`, matcher `permission_prompt|idle_prompt`, timeout 10 s): a notification titled `Claude Code · <name>` with the body `<why>[: <message>]`, where the name is the newest `custom-title` record in the transcript, read backwards in 1 MiB chunks (set by `--name` or `/rename`; Notification input carries no title) and otherwise the checkout folder with its branch, and the reason is "waits for your permission", "waits for your input" or "needs attention". The notifier is `notify-send --app-name=Claude Code` on Linux, `terminal-notifier` (else `osascript`'s `display notification`) on macOS, and a toast through `powershell.exe` with the Windows PowerShell app id on Windows and WSL (detected by `WSL_DISTRO_NAME` or a `microsoft` kernel release). It is silent when the notifier is missing, fails or hangs, and on malformed input; its git calls (2 s each) and the notifier (8 s) share a 9 s deadline inside the hook's 10 s; Claude Code ignores this hook's exit code. Claude Code fires these types only when the user seems away: `permission_prompt` after about six seconds without a keystroke, `idle_prompt` once `messageIdleNotifThresholdMs` (user scope in `~/.claude.json`, default 60000; the user set 30000 on this machine, user decision 2026-11-23) passes after a reply with no keypress, click or terminal focus change since it ended and no background agent running (Claude Code 2.1.330's code).
- **Click to focus** (user decision 2026-11-23): in the terminal of VS Code or an editor built from it (`TERM_PROGRAM=vscode`: Insiders, VSCodium, Cursor) a click on the notification brings forward the editor window holding the session's folder. The editor is the one whose `product.json` sits four folders above its git extension's askpass script (`VSCODE_GIT_ASKPASS_MAIN`); its non-empty string keys `nameShort` (settings folder), `applicationName` (launcher) and `urlProtocol` (toast link) are used, and a key it lacks disables the step that needs it instead of falling back to VS Code's value, so a click never opens another editor. Without a readable `product.json` VS Code's values apply. The folder is the deepest window folder in that editor's `storage.json` (`windowsState`; Linux under `$XDG_CONFIG_HOME` or `~/.config`, macOS under `~/Library/Application Support`, Windows under `%APPDATA%`, WSL in every Windows user's roaming folder, keeping this distribution's `vscode-remote://wsl+<distro>` windows) containing the working directory, else the main checkout (`git rev-parse --git-common-dir`), so a linked worktree's session finds its checkout's window. Opening a folder that a window already holds focuses that window. On Linux, when `notify-send --help` lists `--action` (libnotify 0.7.10), the hook starts a helper in its own session with `CP_REAP_KEEP=1` and returns: the helper shows the notification with a default action (`--action=default=Open`), waits up to 600 s, then sends SIGINT so that notify-send closes it, and on a click runs the launcher (from the editor's own `bin` folder, else `PATH`) on the folder. The launcher gets the hook's environment without the variables of the Claude Code session (`CLAUDE*`, `CP_USER`, `CP_REAP_KEEP`, `AI_AGENT`), inherited activation tokens and `VSCODE_*` other than `VSCODE_IPC_HOOK_CLI`, since a window it opens takes that environment. No activation token is requested: KWin raised the window without one at its default and its High focus-stealing prevention level alike (Limits). On macOS `terminal-notifier -execute "open -a <the .app bundle holding the editor> <folder>"`, or `open -b com.microsoft.VSCode` without a `product.json`; on Windows the toast's protocol launch `<urlProtocol>://file/<folder>`, on WSL `<urlProtocol>://vscode-remote/wsl+<distro><folder>`. The toast's XML is ASCII without quote marks (other characters as `&#N;`), since PowerShell also ends a single-quoted string at U+2018 to U+201B. The design follows public notifiers that open the folder to focus its window (`framerslab/claude-notify-hook`, `moozeeli/claude-notify`, `SeanTong11/wsl-tmux-notifier`; GitHub, read 2026-11-23 through search summaries only).
- **SessionEnd** (`reap.py --own`, matcher `prompt_input_exit|logout|other`, timeout 20 s, never `--scratchpads`): when a session exits it ends what its own Bash tool shells left running and what ended sessions left, and deletes stale test temporaries. It skips `clear` and `resume`, after which the session's work goes on. SessionEnd hooks share a 1.5 s budget, which a per-hook `timeout` raises up to 60 s (`CLAUDE_CODE_SESSIONEND_HOOKS_TIMEOUT_MS` overrides it). The 20 s cover the measured runtime (Benchmarks) plus reap's 5 s SIGTERM and 2 s SIGKILL waits. Hook commands carry `CLAUDE_PID` (Claude Code docs, environment variables), which `--own` uses to find its session. The command runs the project's own `reap.py`, and when that is missing (a worktree `/finish` removed, or one without the file) the main checkout's, found by cutting the nearest `/.claude/worktrees/…` from `CLAUDE_PROJECT_DIR` (`${d%/.claude/worktrees/*}`).
- **PreModelSwitch** (`harness.py hook`, no matcher, timeout 10 s; Claude Code v2.1.251 or later): `model_switch()` denies a `to_model` that is not a string whose base id (context suffix removed) is in the allowed set the model guard uses (`allowed()`), with the guard's HOW sentence as the reason. The hook checks `to_model` itself and registers without a matcher, since a target without a canonical name runs every hook whatever its matcher. An allowed switch gets no output, so Claude Code's own "Switch model?" confirmation, which names the warm cache it drops, is the only warning: the brief's warm-cache message was dropped (user decision 2026-11-23), because a hook's message shows only after the user has confirmed the switch. Like the rest of the guard it fails open on its own errors; the PreToolUse guard still refuses the next tool call of a session on an off-list model. `--selftest` requires the registration for every model (no matcher or `*`), since a narrowed matcher lets an off-list target with a canonical name skip the hook.
- **Push and submit guard** (user decision 2026-11-23): `.claude/githooks/pre-push` runs `shell.py push`, and `04-submit.py`'s `main()` calls `shell.py`'s `claude_shell()`. Both refuse when `CLAUDE_CODE_CHILD_SESSION=1` and `CP_USER` is not `1`. This closes `sh -c "git push"` and `g=git; $g push`, which `shell.py pre` let through. `CLAUDE_CODE_CHILD_SESSION` and not `CLAUDECODE` is the key, since IDE integrated terminals set `CLAUDECODE` too. A `!` command the user types shares the Bash tool's environment exactly: all 89 variables, compared by hash on 2026-11-22. So the user prefixes their own push or submission inside a session with `CP_USER=1` (`CLAUDE.md`, Git). `shell.py pre` now also runs for the Monitor tool, whose commands carry the same environment and pass Bash's permission rules; only Bash commands get its snapshot. It refuses any command whose text names `CP_USER`, `CLAUDE_CODE_CHILD_SESSION`, `--no-verify` or a value for `core.hooksPath` (`GUARD_TEXT`; reading the key stays allowed). The refusal covers any mention, a grep or a documentation edit included, and Claude handles such text with the Edit, Read and Grep tools (user decision 2026-11-23). The push commands printed for the user (`plan.py`'s claim line, `merge_pr.py`'s landing message, `/finish` step 7) read `CP_USER=1 git push …` (user decision 2026-11-23); the private sources repository's push needs no prefix, since its git directory sets no `core.hooksPath`. `pre`'s `git push` check skips the options of `env` and `sudo` (`env -u NAME`, `sudo -u root`), and `GUARD_TEXT` also refuses removing `core.hooksPath` (`--unset`, `unset`, `--remove-section core`) and `env -i` or `env -`, which would clear the environment the guards read. The deny reason points to the Read, Grep and Edit tools for such text.
- **Git's own files** (2026-11-23, closing a limit at the user's request; the text refusal's width decided without the user): `guard.py` refuses Edit, Write and NotebookEdit of any path whose resolved form passes through a `.git` file or folder in any case, in any repository, since `.git/config` names the hooks folder that guards pushes and commits. `GUARD_TEXT` also refuses a command naming `.git/config`, `.git/hooks` or a worktree's `config` under `.git/worktrees/` in any case, with repeated slashes or `/./`, and a git config include (`include.path`, `includeIf.`), which could point git at another config file. Like the rest of `GUARD_TEXT` it refuses a command that only mentions such a path; git commands that read or change the repository through git itself are unaffected.

### Status Line and Agents

- The status line's cache part gains `miss N` from `prompt_cache.misses` once that is an integer above 0 (a bool shows nothing).
- `@researcher` sets `omitClaudeMd: true` (v2.1.271 or later): it starts without the user, project and local CLAUDE.md files, since its procedure and the delegation prompt name every file it reads. `@reviewer` and `@speedscout` keep CLAUDE.md for its scratchpad and memory rules. No agent sets `maxTurns`, since a cut review is worse than a long one.
- `@reviewer`'s report ends with a `Not verified` section listing each claim it could not check, with the reason, or `none`. `/package` (step 10) and `/finish` (step 2) say that a brief to `@reviewer` names what to review, never what not to flag. A cross-model reviewer waits until `finish-log.tsv` measures review yield.
- The `model:` pins of `/tidy`, `/duplicate-sweep`, `/omission-sweep` (Opus) and `/speed-sweep` (Fable) stay; `01-prompts.md` (Workflow) says to start each in a fresh session of the matching preset, since a skill whose model differs from the session's makes that turn re-read the whole context uncached.

## Limits

- The push and submit guard stops Claude only where it does not set `CP_USER`, clear or unset `CLAUDE_CODE_CHILD_SESSION` or bypass the hooks itself. `pre` refuses the spellings `GUARD_TEXT` names, but an encoded command (built from parts, `env -S`, a script file), a path into `.git` reached another way (`cd .git && …`, `$(git rev-parse --git-dir)/config`, a hard link, which `guard.py` cannot tell from another file) and a push from a shell Claude Code did not start (another terminal) are not guarded.
- Verified live on 2026-11-23: a Monitor command reaching `pre` (refused); the user's `!` push with the override (passed) and without it (refused by `pre-push`); `/model claude-sonnet-5-5` refused with the HOW message; `/model claude-fable-5-2` showing Claude Code's own "Switch model?" dialog first, which the user declined, so no hook message could have shown; an automatic compaction at 367k tokens whose summary kept SUP32, `/finish`, its step and the ledger path, which `resume.py precompact` prints for that transcript (the transcript does not store hook output); the idle notification arriving about 60 s after a reply while the user stayed in another window, and none while they watched the terminal; on KDE Plasma under Wayland a click on the popup raising the VS Code window of this checkout from behind another window, from another tab and from another window, with and without an activation token at KWin's default and its High focus-stealing prevention level (the user's setting restored after); on Windows 10 Enterprise build 26300 in a virtual machine, a toast that `toast()`'s script shows under the PowerShell app id with a title in curly quotes, silent without an error while the user's notifications were off and shown once they were on, its protocol launch (`ms-settings:display`, since that machine has no VS Code) opening on a click; SessionEnd on `/exit` of a main-checkout session ending the `setsid nohup sleep 901` its `!` command left; a fresh `contest-session` listing workflow-authoring and update-config to the model but none of the ten hidden skills, and having no Artifact tool.
- Click to focus is unverified on macOS and WSL (no such machine here; only the argv is tested), and on Windows only the toast and its protocol launch ran, without VS Code: the `vscode://` link and the window lookup there are tested by argv only. On Windows and WSL VS Code first asks whether to let an external application open the path (`security.promptForLocalFileProtocolHandling`, `security.promptForRemoteFileProtocolHandling`, on by default; its checkbox allows it from then on). Under GNOME's or another compositor's focus rules than KWin's the raise is unverified. `osascript` notifications take no click action. A helper ended by `/reap` or the SessionEnd hook before its 600 s leaves its notification in the history, where a click does nothing. When two windows hold the folder, the editor picks the one it raises.
- The editor is found only through `VSCODE_GIT_ASKPASS_MAIN`, which VS Code's git extension sets while `git.enabled` and its terminal authentication are on; without it VS Code's values apply, so another editor's window is not found and its launcher is not run (Cursor's terminal then gets VS Code's `code`, as before). A portable installation (`data` folder) or `--user-data-dir` keeps `storage.json` elsewhere, a `.code-workspace` window has no folder entry, and a UNC or symlinked folder may not match the working directory; each falls back to the main checkout. On WSL the Windows users are read from `/mnt/c/Users` only.
- Unverified in a live session: the 30 s threshold (it applies from the next session), and SessionEnd after `/finish` removed a worktree, where `CLAUDE_PROJECT_DIR` then points is undocumented; the command's fallback to the main checkout is tested by bash on stub files.
- `syncClaudeAiSkills` is per clone, and `skillOverrides` lists bundled skills by name: a renamed or new bundled skill is listed again until it is added.
- The PreModelSwitch hook fails open on its own errors, and Claude Code does not run it for switches it makes itself (fallback, resume); the PreToolUse guard covers both.
- A transcript without a custom title is read whole, backwards in 1 MiB chunks (68 ms in all for an 8.3 MB one, Benchmarks); the shared 9 s deadline does not cut it.
