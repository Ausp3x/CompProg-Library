## Contracts

### Settings (`.claude/settings.json`, `.claude/settings.local.json`)

- `worktree.baseRef: "head"`: new worktrees, including `--worktree` sessions and isolated subagents, branch from the local `HEAD` (inside a worktree, that worktree's `HEAD`), so unpushed commits on `master` carry over and nothing needs a push first. `01-prompts.md` (Workflow) and `AGENTS.md`, whose manual recipe now branches from `HEAD`, say so.
- `skillOverrides`: claude-api, dataviz, artifact-design, artifact-diagramming, artifact-capabilities, run, init, schedule, plugin-authoring and security-review are `"user-invocable-only"` (hidden from Claude, `/name` still runs them); workflow-authoring and update-config are `"on"`. Reason (user decision 2026-11-19): the skill listing took about 14,000 characters a session for 27 skills, and claude-api loaded itself 5 times at about 105–114 KB each, while none of these serves library work.
- `enableArtifact: false` turns the Artifact tool off for every session of the project; no file can turn it back on.
- `syncClaudeAiSkills: false` sits in `.claude/settings.local.json` (git-ignored), since the key's scope is user, local or managed and a project value is ignored. It applies to this clone only; another clone sets it in its own local or user settings. In local settings Claude Code stops loading the synced skills but does not move them to `~/.claude/skills/.trash/`.
- `includeGitInstructions` stays on, so sessions keep the git status snapshot.

### Hooks

- **PreCompact** (`resume.py precompact`, no matcher, timeout 60 s): stdout becomes instructions for the compaction summary, which Claude Code caps at 10,000 characters per hook; the script keeps under 9,000. It names the target (the batch or package id of the session's last typed `/package`, `/prune` or `/finish` call, else the branch or worktree name, through `gaps.py`'s `target()`), says which of the two named it (the typed command that gave the argument, cut to 80 characters so the later lines always fit), names the skill to resume and asks for its step number and the exact next step, gives the `/finish` ledger path (existing or not yet written; no line without a target or ledger) and the keep and drop lists of `CLAUDE.md` (Compact Instructions). It always exits 0: exit 2 would block the compaction, and a failure prints nothing. It shares `last_command()` and `ledgers()` with the `compact` SessionStart mode; `/pause` (`pause.py`) uses `last_command()` too.
- **Notification** (`notify.py`, matcher `permission_prompt|idle_prompt`, timeout 10 s): a notification titled `Claude Code · <name>` with the body `<why>[: <message>]`, where the name is the newest `custom-title` record in the transcript's last MiB (set by `--name` or `/rename`; Notification input carries no title) and otherwise the checkout folder with its branch, and the reason is "waits for your permission", "waits for your input" or "needs attention". The notifier is `notify-send --app-name=Claude Code` on Linux, `terminal-notifier` (else `osascript`'s `display notification`) on macOS, and a toast through `powershell.exe` with the Windows PowerShell app id on Windows and WSL (detected by `WSL_DISTRO_NAME` or a `microsoft` kernel release). It is silent when the notifier is missing, fails or hangs, and on malformed input; its git calls (2 s each) and the notifier (8 s) share a 9 s deadline inside the hook's 10 s; Claude Code ignores this hook's exit code. Claude Code fires these types only when the user seems away: `permission_prompt` after about six seconds without a keystroke, `idle_prompt` once `messageIdleNotifThresholdMs` (user scope in `~/.claude.json`, default 60000; the user set 30000 on this machine, user decision 2026-11-23) passes after a reply with no keypress, click or terminal focus change since it ended and no background agent running (Claude Code 2.1.330's code).
- **Click to focus** (user decision 2026-11-23): in VS Code's terminal (`TERM_PROGRAM=vscode`) a click on the notification brings forward the VS Code window holding the session's folder. That folder is the deepest window folder in VS Code's `storage.json` (`windowsState`; read on Linux and macOS) containing the working directory, else the main checkout (`git rev-parse --git-common-dir`), so a linked worktree's session finds its checkout's window. Opening a folder that a window already holds focuses that window. On Linux, when `notify-send --help` lists `--action` (libnotify 0.7.10), the hook starts a helper in its own session and returns: the helper shows the notification with a default action (`--action=default=Open`), waits up to 600 s, then sends SIGINT so that notify-send closes it, and on a click runs `code <folder>`. When `--help` also lists `--activation-token-fd` (libnotify 0.8.8; older versions exit on the unknown option), the token the daemon hands over goes to `code` as `XDG_ACTIVATION_TOKEN` and `DESKTOP_STARTUP_ID`. `code` gets the hook's environment without the variables of the Claude Code session (`CLAUDE*`, `CP_USER`, `AI_AGENT`), inherited tokens and `VSCODE_*` other than `VSCODE_IPC_HOOK_CLI`, since a window it opens takes that environment. On macOS `terminal-notifier -execute "open -b com.microsoft.VSCode <folder>"`; on Windows the toast's protocol launch `vscode://file/<folder>`, on WSL `vscode://vscode-remote/wsl+<distro><folder>`. The toast's XML is ASCII without quote marks (other characters as `&#N;`), since PowerShell also ends a single-quoted string at U+2018 to U+201B. The design follows public notifiers that open the folder to focus its window (`framerslab/claude-notify-hook`, `moozeeli/claude-notify`, `SeanTong11/wsl-tmux-notifier`; GitHub, read 2026-11-23 through search summaries only).
- **SessionEnd** (`reap.py --own`, matcher `prompt_input_exit|logout|other`, timeout 20 s, never `--scratchpads`): when a session exits it ends what its own Bash tool shells left running and what ended sessions left, and deletes stale test temporaries. It skips `clear` and `resume`, after which the session's work goes on. SessionEnd hooks share a 1.5 s budget, which a per-hook `timeout` raises up to 60 s (`CLAUDE_CODE_SESSIONEND_HOOKS_TIMEOUT_MS` overrides it). The 20 s cover the measured runtime (Benchmarks) plus reap's 5 s SIGTERM and 2 s SIGKILL waits. Hook commands carry `CLAUDE_PID` (Claude Code docs, environment variables), which `--own` uses to find its session.
- **PreModelSwitch** (`harness.py hook`, no matcher, timeout 10 s; Claude Code v2.1.251 or later): `model_switch()` denies a `to_model` that is not a string whose base id (context suffix removed) is in the allowed set the model guard uses (`allowed()`), with the guard's HOW sentence as the reason. The hook checks `to_model` itself and registers without a matcher, since a target without a canonical name runs every hook whatever its matcher. Otherwise, when `prompt_cache_warm` is true, it returns a `systemMessage` saying that the switch drops the warm cache, with the re-sent tokens (a positive integer `context_tokens`) and cost (a finite non-negative `estimated_cache_write_usd`) when given; it never returns `allow`, so Claude Code's own warm-cache confirmation still shows. Like the rest of the guard it fails open on its own errors; the PreToolUse guard still refuses the next tool call of a session on an off-list model. `--selftest` requires the registration for every model (no matcher or `*`), since a narrowed matcher lets an off-list target with a canonical name skip the hook.
- **Push and submit guard** (user decision 2026-11-23): `.claude/githooks/pre-push` runs `shell.py push`, and `04-submit.py`'s `main()` calls `shell.py`'s `claude_shell()`. Both refuse when `CLAUDE_CODE_CHILD_SESSION=1` and `CP_USER` is not `1`. This closes `sh -c "git push"` and `g=git; $g push`, which `shell.py pre` let through. `CLAUDE_CODE_CHILD_SESSION` and not `CLAUDECODE` is the key, since IDE integrated terminals set `CLAUDECODE` too. A `!` command the user types shares the Bash tool's environment exactly: all 89 variables, compared by hash on 2026-11-22. So the user prefixes their own push or submission inside a session with `CP_USER=1` (`CLAUDE.md`, Git). `shell.py pre` now also runs for the Monitor tool, whose commands carry the same environment and pass Bash's permission rules; only Bash commands get its snapshot. It refuses any command whose text names `CP_USER`, `CLAUDE_CODE_CHILD_SESSION`, `--no-verify` or a value for `core.hooksPath` (`GUARD_TEXT`; reading the key stays allowed). The refusal covers any mention, a grep or a documentation edit included, and Claude handles such text with the Edit, Read and Grep tools (user decision 2026-11-23). The push commands printed for the user (`plan.py`'s claim line, `merge_pr.py`'s landing message, `/finish` step 7) read `CP_USER=1 git push …` (user decision 2026-11-23); the private sources repository's push needs no prefix, since its git directory sets no `core.hooksPath`. `pre`'s `git push` check skips the options of `env` and `sudo` (`env -u NAME`, `sudo -u root`), and `GUARD_TEXT` also refuses removing `core.hooksPath` (`--unset`, `unset`, `--remove-section core`) and `env -i` or `env -`, which would clear the environment the guards read. The deny reason points to the Read, Grep and Edit tools for such text.

- `@researcher` sets `omitClaudeMd: true` (v2.1.271 or later): it starts without the user, project and local CLAUDE.md files, since its procedure and the delegation prompt name every file it reads. `@reviewer` and `@speedscout` keep CLAUDE.md for its scratchpad and memory rules. No agent sets `maxTurns`, since a cut review is worse than a long one.

## Limits

- The push and submit guard stops Claude only where it does not set `CP_USER`, clear or unset `CLAUDE_CODE_CHILD_SESSION` or bypass the hooks itself. `pre` refuses the spellings `GUARD_TEXT` names, but an encoded command (built from parts, `env -S`, a script file), an Edit of `.git/config` and a push from a shell Claude Code did not start (another terminal) are not guarded.
- The printed `CP_USER=1 git push …` form is a POSIX shell assignment (sh, bash, zsh); csh, fish before 3.1, PowerShell and cmd need their own form.
- Verified live on 2026-11-23: a Monitor command reaching `pre` (refused); the user's `!` push with the override (passed) and without it (refused by `pre-push`); `/model claude-sonnet-5-5` refused with the HOW message; an automatic compaction at 367k tokens whose summary kept SUP32, `/finish`, its step and the ledger path, which `resume.py precompact` prints for that transcript (the transcript does not store hook output); the idle notification arriving about 60 s after a reply while the user stayed in another window, and none while they watched the terminal; on KDE Plasma under Wayland a click on the popup raising the VS Code window of this checkout from behind another window; a fresh `contest-session` listing workflow-authoring and update-config to the model but none of the ten hidden skills, and having no Artifact tool.
- Click to focus is unverified on macOS, Windows and WSL (no such machine here; only the argv is tested, and no PowerShell ran the toast script), and so is whether Windows shows a toast under the PowerShell app id on every edition. On Windows and WSL VS Code first asks whether to let an external application open the path (`security.promptForLocalFileProtocolHandling`, `security.promptForRemoteFileProtocolHandling`, on by default; its checkbox allows it from then on). On Linux the token reaches `code`'s environment, but VS Code's source does not read it, so its effect is unverified: the live raise may come from KWin's focus-stealing prevention level. `osascript` notifications take no click action. A helper ended by `/reap` or the SessionEnd hook before its 600 s leaves its notification in the history, where a click does nothing. The window lookup reads only VS Code's own `storage.json` (not Insiders, VSCodium or Cursor, which also sets `TERM_PROGRAM=vscode` and gets VS Code), and on WSL and Windows it uses the main checkout. When two windows hold the folder, VS Code picks the one it raises.
- Unverified in a live session: the warm-cache message beside the built-in `/model` confirmation, the 30 s threshold (it applies from the next session), and SessionEnd running `reap.py --own` (a session's transcript does not record it), also after `/finish` removed a worktree, where `CLAUDE_PROJECT_DIR` then points is undocumented.
- `syncClaudeAiSkills` is per clone, and `skillOverrides` lists bundled skills by name: a renamed or new bundled skill is listed again until it is added.
- The PreModelSwitch hook fails open on its own errors, and Claude Code does not run it for switches it makes itself (fallback, resume); the PreToolUse guard covers both.
- The Notification title comes from the transcript's last MiB; a session renamed only earlier shows its checkout and branch.
