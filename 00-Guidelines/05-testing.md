# Library tests and benchmarks

`96-Local Testing` verifies library files. `09-Contest Testing` compares problem solutions.

## Layout and modes

- Mirror the library path: `96-Local Testing/02-Data Structures/01-dsu_tester.py` with helper `.cpp` files beside it. One Python entry per header or module; shared infrastructure in `_00_cpp_test_runner.py` (the `Builder` every C++ test build goes through, `Docs/00-parallel.md`; `03-consistency.py` rejects a library tester or runner (`01`–`07`) that runs the compiler directly, `-fsyntax-only` checks and compiler queries apart) and, for `02`–`07`, `_00_contest_runner.py`, whose per-suite differences are parameters. Tests include the real header and run from any working directory; build outputs go to a temporary directory.
- Modes: `quick` (smoke subset, seconds), `full` (every operation and configuration), `stress` (extended random, exhaustive and adversarial, seeded, with `--rounds`). Document the actual coverage of each mode; never label a truncated run `full`.
- Quick bound (user decision 2026-11-08): each build's quick run takes at most 10 s alone on the reference machine (i9-11900H), compile time apart. Over it, first find a cheaper oracle with the same checks, then smaller quick-mode inputs; full and stress inputs and oracles stay unchanged, and a check that fits only in full moves there. The runners print `TIMING <build> mode=<mode> compile=<s>s run=<s>s` per build, and `01-run.py` lists the quick builds over 10 s as a NOTE in every mode (a full or stress run from its pre-flight), never a failure, since it times them beside other suites (Benchmarks: no fixed timing gates across machines).
- `01-run.py` discovers testers by glob; quick mode runs every folder except `01-Core`, whose quick testers are listed in `QUICK`. It and `02-integration.py` run their jobs in parallel: a job that fails beside others reruns alone, and only a failure alone counts. `01-run.py` ends with a NOTE naming each suite that passed only on its rerun and each command over half its limit: a passing exit code does not clear either, and a package fixes them with a cheaper oracle with the same checks, or else a raised limit with its measured reason. So a tester writes only to per-process temporary paths, because the same tester runs concurrently with several seeds in stress mode.
- On headers whose row and owning package are both `verified`, `03-consistency.py` enforces the `03-cpp.md` closing-brace rule and, on type headers, the type-header rule, plus the brace rule on their C++ testers and benchmarks, ignoring comments, literals, preprocessor lines and initializer braces. While editing, `python3 '96-Local Testing/03-consistency.py' --braces <files>` checks any files for the brace rule, the comment cap and, on `01-Core` and `02-Data Structures` type headers, the type-header rule. In a linked worktree, ledger records of git-ignored artifacts (archive binaries and caches, benchmark logs) pass when the file is absent, so a fresh worktree validates without them; the main checkout keeps requiring them.
- Output: named tests, in-place progress on a terminal, plain lines when redirected, green PASS and red FAIL, nonzero exit on failure, explicit SKIP for missing hardware or interpreters. A failure prints seed, smallest known reproducer, operation and input, expected and actual values, configuration, command, and timeout or crash details. Failures must survive `-DNDEBUG`; never use a removable `assert` as the only oracle. Never ignore a subprocess failure.

## Memory safety

- Every tester, benchmark driver and `02-integration.py` calls `_00_memory_cap.ensure()` at start (the shared runners do it on import; `03-consistency.py` rejects an entry point that does not). It runs the entry point in a transient systemd user scope capped at 4096 MB by default (`CP_TEST_MEMORY_MB` overrides) with swap off, where only a runaway process is killed and the runner reports it as a FAIL. A suite that legitimately needs more memory passes `ensure(mb=...)` and records the reason and measured peak in its evidence.
- Full and stress runs first rerun the entry point in quick mode under a 2048 MB pre-flight cap (`CP_TEST_PREFLIGHT_MB`) and start only if it passes; `CP_TEST_PREFLIGHT=0` skips the pre-flight for a deliberate rerun.
- Each capped run ends with `MEMORY peak=... cap=... oom_kills=...`; evidence records the full and stress peaks.
- A suite's builds compile and run at once, at most three within its cap (`Builder.build_all`, `Builder.concurrently`), each reserving its measured peak; stress mode runs them one at a time, its peaks being unmeasured, and `_00_foundation_runner.py` runs its few seconds of tests in order. A contest suite passes `memory=` to `main` when one build, compile or run, needs over 1200 MB; a NOTE at 90% of the cap and the failure of a build the cap killed name that parameter. Run at most six heavy compiles (Core full headers, their testers and drivers) at once, fewer beside a running tester or agent. One `_00_memory_cap.py` cap covers its whole process tree (about four `-O2 -g` builds per 6–8 GB), and a build the OOM killer ends leaves no binary, so check each exists before running it.
- Ad-hoc probes, scratch binaries and one-off benchmarks run through `python3 '96-Local Testing/_00_memory_cap.py' [--mb N] -- <command>`; never run a compiled test program uncapped.
- Inputs given to an optimized (`-DNDEBUG`) build stay inside every documented domain; only the checked build's `--invalid` probes violate preconditions.

## Coverage

- Keep a feature-to-test map in the evidence document: every operation in the inventory row maps to at least one test.
- Call every operation as user code does: `friend` functions unqualified through ADL, `static` builders as `Type<T>::name`, companion functions as `TypeCompanion::name`.
- Before a same-context form or second implementation (`03-cpp.md`, One API per operation) is deleted, its test cases are reproduced against the kept operation and mapped in the feature-to-test map.
- Oracles in priority order: independent brute force, bounded exhaustive small domains, algebraic or metamorphic identities, deterministic seeded random stress, saved regressions. Agreement between full and mini or between C++ and Python is supporting evidence only, never the sole oracle. Validate the brute force itself.
- A contest operation generic over a Core type runs its cases with the mini default and with the full type. A slower algorithm and its faster counterpart check each other on their shared domain, and each keeps an independent oracle of its own.
- Cases: empty and singleton, boundaries of every documented domain, extreme magnitudes, zero and negative values, duplicates and degeneracies, disconnected graphs, self-loops and multi-edges where allowed, threshold and alignment neighbours, aliasing of inputs and outputs, repeated calls, reset and cache changes, valid no-answer inputs, and each documented precondition failure under a checked build.
- Builds: optimized GNU++20, sanitized (`-g -fsanitize=address,undefined`; the contest runner's `ASan-UBSan`, at `-O1`), `-DNDEBUG`, `LOCAL` and non-`LOCAL` when behavior differs; header alone, `98-basic`, `99-all`, mixed full and mini, two translation units; scalar and each ISA path with an explicit SKIP where the CPU lacks it; a contest suite whose results depend on floating-point contraction passes `native=True` to the contest runner for an optimized `-march=native` build in full and stress mode, as AtCoder compiles, with a SKIP where the CPU lacks FMA (user decision 2026-11-13); CPython and PyPy for Python. Every package also runs its suites in `full` mode with `CXX=g++-14` (the runners read `CXX`) as the floor check and records the result in its evidence. Every contest suite compiles with `-Wall -Wextra -Wconversion -Werror` (`_00_contest_runner.py`); elsewhere use `-Wall -Wextra -Wconversion`, and a warning is acceptable only when the bound is stated in the code. The contest runner's `checked` build (debug containers or assertions, no sanitizer) is `-O0` in quick mode, so every suite still runs unoptimized, and `-O1` in full and stress.
- A package that changes a header also runs `python3 '96-Local Testing/02-integration.py'` before it is verified, adding `--sanitizers` when an `01-Core` header changed.
- Approximate comparisons use justified absolute or relative tolerances; never compare exact big integers through floats.

## Mutation testing

- Every header a package adds or changes, Core full included, gets a campaign once its tests pass: `python3 '96-Local Testing/04-mutation.py' run <header>`. It mutates scratch copies of the working tree with mewt (pinned and installed by `04-mutation.py install`, a required tool of `/setup-check`) and escalates each mutant through the tester's quick mode and full mode on the optimized build, then full mode on the builds not yet run in full (a Core tester, which has no build option, runs quick then full), so a survivor has passed every configuration in full mode. Without mewt it prints SKIP and leaves no record. One campaign runs per machine; a second waits for it (user decision 2026-11-04). Procedure, costs and limits: `96-Local Testing/Docs/00-mutation.md`.
- Scope (user decision 2026-11-03): a header whose evidence document holds a record is mutated only on the lines changed since the recorded blob, a header without one on every line; a Core full header's whole-file campaign samples high and medium severity, and every whole-file campaign tests a seeded uniform sample of at most 500 mutants (user decision 2026-11-04). `--whole`, `--severity` and `--sample` override, and the record states the scope and sample. A run the `--budget` stopped is incomplete: resume it with the same `--workdir`.
- Each mutant's test runs in its own memory-capped scope, so a runaway mutant dies alone. A kill at that cap (three times the baseline's peak, at least 1024 MB, at most the tester's own cap) counts as caught, and so does a timeout (three times the stage baseline, at least 60 s) that recurs when the mutant is retested with its own CPU cores, since contention among concurrent tests can slow a survivor (user decisions 2026-11-04, 2026-11-09). Close each survivor with a test, then rerun with the same `--workdir`, which retests the survivors with the current tester; otherwise record it as equivalent after the five checks of the Trail of Bits procedure (type context, reachability, downstream use, semantic comparison, distinguishing input). A mutant equivalent only because the contract leaves the changed state unspecified needs the user's decision; one that differs only under `NDEBUG` past a violated precondition and still ends within the operation's bound is equivalent (user decision 2026-11-12). A mutant with identical results whose only effect is work above the stated bound but under the timeout is recorded as runtime only, with its work argument and measured ratio (user decision 2026-11-14).
- The header's evidence document keeps one `## Mutation testing` section: the `Record:` line the run prints (it names the header's git blob), the stage times, and each equivalent survivor with its argument. `04-mutation.py check` passes only while the record names the current blob and leaves 0 untested; a completed run stores the blob in git's object database so a later run can diff against it.
- Later passes (user decisions 2026-11-03 and 2026-11-04): `/finish` reruns the campaign on the lines its own fixes changed and reviews the survivors with its fix diff. `/prune`, `/restyle` and a `/package` call-site migration in another package's header rerun it on their changed lines only for a header that already holds a record; a header without one needs none from them, and the checks pass it (`check --existing`): `/finish` for headers whose evidence document another package lists and the package itself does not, `/merge-pr` for those and for every header that only `/prune` or `/restyle` commits changed. `/merge-pr` otherwise only checks.

## Extraction

- `python3 '96-Local Testing/05-extraction.py'` checks `09-Contest Testing/10-grab.py` on the library: `ops` extracts every operation of every implemented `01`–`07` row alone (`Type::member` for a struct's operation) and compiles it with `-fsyntax-only` after the template and debug headers on `$CXX` and `g++-14`, instantiating each class or function template it reaches with the first candidate arguments (`lng`, the `Sum` and `RangeAddRangeSum` presets, `ulng`; `4`; `false`) that compile after the whole header, fails on an extraction keeping code outside its header's include closure, and on a public function template whose type parameter grab must infer for want of the default `03-cpp.md` (Headers) asks for (pending outside verified rows); `testers` runs each C++ tester's quick mode in a scratch tree where every library header but the template and debug headers keeps only its quoted includes and its lines of the declarations the tester's files name from their include closures, so C++ a tester writes itself extracts too. `--mode quick` samples rows and testers; `full` takes all. Without libclang it prints SKIP. Evidence: `96-Local Testing/Docs/00-extraction.md`.
- A package that adds or changes a header also runs `05-extraction.py ops --filter <header>` and, for a C++ tester, `05-extraction.py testers --filter <tester>`, and records both in the header's evidence, so a form grab mishandles fails with the package that brings it (user decision 2026-11-07).
- Mini first (`03-cpp.md`, Core type parameters): `03-consistency.py` rejects a contest template default naming a Core full type, a mini row that lacks an operation of its full row (beside `internals:` and `missing:`) and an operation whose default form extracts a Core full header that is not scalar without a `full-only until` line in its evidence document naming it in a code span. The last check reads the cached grab index only, on the rows whose include closure is indexed, and reports how many rows wait; `05-extraction.py ops` always runs it. Findings on support targets of open 2026-11-05 batches and on rows or packages not yet verified are listed in `mini_first_pending` instead of failing.

## Benchmarks

- Separate from correctness. Record CPU, compiler and flags, interpreter, input sizes and distributions, seeds, warmup and repetition counts, medians, memory, and the compared implementation. Verify outputs inside the benchmark so the work cannot be optimized away.
- Drivers are `<NN-name>_benchmark.py/.cpp` beside the tester (`00-<stem>_benchmark.*` for a folder-wide driver). Raw logs `*_benchmark.json`/`.jsonl` are written beside the driver and are ignored by git; commit only the summary table with conditions and medians in the header's evidence document.
- Cover small, typical, large and adversarial inputs and every dispatch threshold. The Barrett/Montgomery 20% rule from principles applies outside Core. No fixed timing gates across machines.
- A speed change is adopted only on A/B evidence against the previous header in the ISA and scalar builds: cycle and instruction counts (`perf stat` or perf_event_open counters), since wall-clock varies by about 10% here. Reject a difference within noise, rule out layout effects with `-falign-functions=64 -falign-loops=32`, time a branchy kernel over a pool of random operands (one repeated pair trains the branch predictor), and re-measure a remaining gap on the final header before fixing it. Allocation, alignment and page-size changes stay judge-unverified until the user's submissions confirm them: local counters cannot see the judge's caches (Zen 3, 512 KB L2).
- A Core mini records its scaling (n, 2n and 4n against its complexity) and its speed ratio to the full type built without ISA flags.
