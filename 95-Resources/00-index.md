# Resources

Offline reading for the library. Open only the relevant reference or chapter; these copies are not verified implementations.

Maintenance: prefer the author's or project's download, keep one edition, keep original contents and notices, and record URL, retrieval date, edition and SHA-256 in [99-sources.json](99-sources.json). Files and folders use `NN-descriptive_name`, with three digits in `13-Papers` and `14-Web Pages` (user decision 2026-11-28): a book or paper is `NN-short_title-author_year` (first author's surname; the files of 2026-09-27 omit the year), a saved web page `NN-site_id-short_title` (`007-codeforces_blog_83467-queue_like_undoing.pdf`), all in lowercase `snake_case`; in those two folders the number follows the order of the requests, from the one of 2026-11-22, so several pages of one request share it; inside `11-NOI.PH Notes` the number precedes the original title. Check reuse terms before adapting or redistributing material: Agner Fog's PDFs permit local study but prohibit public mirrors. Implementation rules stay in [the guidelines](../00-Guidelines/00-index.md).

Storage: the repository is public, so a file is committed only when its reuse terms permit public redistribution; any other copy (paywalled, library access, a book) stays local in its folder, git-ignored, and so does all of `13-Papers` and `14-Web Pages` (user decision 2026-11-22). Every file here, committed or not, is backed up in the maintainer's private repository CompProg Library Sources (`https://github.com/Ausp3x/CompProg-Library-Sources`), a second git history over this folder that [00-sources.py](00-sources.py) keeps in `.git/sources`: `init` once per clone (it restores the files this clone lacks), `status`, `commit`, and the user pushes. A change that adds or replaces a resource updates it in the same session: `/finish` runs `commit` for the maintainer, also from a worktree, whose git-ignored sources it first copies to the main checkout (a linked worktree's `00-Inbox`, `13-Papers` and `14-Web Pages` are links to the main checkout's, made at session start by `.claude/hooks/resume.py`, user decision 2026-11-26, so only a local-only file elsewhere is copied), and anyone adding a resource outside `/finish` runs it by hand. A contributor's setup runs `fetch` once for the files with a download URL (`CONTRIBUTING.md`); it needs no private history and names the local-only entries without one instead of failing on them. A contributor commits only the manifest entry (title, `download_url`, SHA-256, `committed: false`), and `/merge-pr` runs `fetch`, which downloads each missing file and checks its SHA-256, before `commit`; a file that fails is asked of the user through `00-Inbox/`, where the next `fetch` takes the file with the entry's SHA-256. **Warning:** download a file only from its publisher, its author or another source you are entitled to use, and never commit, upload or share a local-only copy anywhere but the private repository.

`00-Inbox/` (git-ignored) is one folder for every session, the main checkout's (user decision 2026-11-26). It receives only the files a session asks the user for because it could not open them: the question names the folder's absolute path, and the session appends one line per request to `00-Inbox/00-requests.md`, `- YYYY-MM-DD | package or batch | title | URL | file name`, and takes only the files it requested. A session downloads into its scratchpad, never into `00-Inbox/`.

Filing (user decision 2026-11-27): every source file the work reads, placed by the user or downloaded by the session, is filed when it is first cited, in any checkout and with or without a skill. `python3 '95-Resources/00-sources.py' file <file> '<folder>/<name>' --title … --url … --cited-in <doc>` moves it into `13-Papers` (a paper, report or book) or `14-Web Pages` (a saved page) under the names above, adds its manifest entry, deletes its request line and, for the maintainer, commits it to the private repository at once. Documents cite the filed path, never a file in `00-Inbox/`. An entry's `cited_in` lists the citing documents by their paths from the repository root, one `--cited-in` each, without line numbers, which drift (user decision 2026-11-27), and each listed document names the file. `03-consistency.py` rejects a citation of an inbox file and an entry whose `cited_in` names a missing document or one that no longer names the file. `/package` and `/finish` land nothing while `00-sources.py check`, the Sources section of their facts, lists either, an inbox file placed for the work or without a request line, a copy of a filed file, a filed file without a manifest entry, or one not backed up. What the citing evidence records: [01-principles.md](../00-Guidelines/01-principles.md), Evidence.
