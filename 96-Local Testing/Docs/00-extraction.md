## Contracts

### Index

- Headers: every `0[1-7]-*/**/*.hpp` outside `97-Legacy` and the `98-`/`99-` aggregates. `01-Core/01-template.hpp` and `02-debug.hpp` are never indexed or emitted, since the contest template holds both.
- Parse: libclang with `-x c++ -std=gnu++20` and its own resource directory, found beside the loaded `libclang` library. Each header is parsed once per configuration: scalar, and `-mavx2 -mfma -mbmi -mbmi2 -mpclmul -mpopcnt -mlzcnt`. A parse error stops the index build, and grab exits 1 naming the header and its first diagnostics. libclang 23 parses every library header against libstdc++ 16 without errors.
- Units: each namespace-scope declaration (namespaces are containers) and each member of a namespace-scope struct, class, union or class template, with its extent. Aliases and typedefs are marked as such. A unit seen in both configurations is one unit.
- References: a resolved reference into a library header is a position (header, line, column), mapped to the innermost unit there. An overloaded or dependent name is kept by its spelling (`names`), and a dependent member access (`pc.inverseFactorial(i)`) by its last identifier (`members`).
- Cache: one JSON file per header in `09-Contest Testing/.grab-cache` (git-ignored), the main checkout's in every linked worktree (`main_checkout()`, user decision 2026-11-26), each record replaced atomically. Its key combines `VERSION` (the record format), libclang's version, the bytes of the header's include closure, and the constants and source of every function the analysis reads (`analysis_id`: `PROTOCOL`, `EXCLUDED`, `CONFIGS`, the directive patterns, `analyze`, `scan_lines`, `merge`, `index_header`, `resource_dir`, `library`, `stamp`). So an edited header re-indexes itself and its dependents only, and a changed analysis or libclang re-indexes everything. Each record also stores the size and modification time of every file outside the repository its parses read (libstdc++, libclang's builtin headers); a record whose stamps differ, or that has none, is rebuilt. A cold index of the 172 headers takes about 4 minutes with 6 parallel parses, and a cached load 0.7 s. `Index(build=False)` loads cached records only and lists the rest as `stale`.

### Selection and Output

- Command-line names: a name keeps its declaration whole; `Type::member` keeps that member, with its struct pruned. `Alias::member` names the member of the type an alias names (`ModInt::sqrt`) and keeps the alias too, with its type pruned, since the code spells the alias. An alias kept whole keeps its type whole (`grab mint`). A command-line name keeps every namespace-scope declaration with that spelling (Limits).
- Input types (user decision 2026-11-06): a function template kept whole keeps its input types whole, since the caller builds them (`grab dijkstra` brings `Graph` with `addEdge`). Those are the types its template parameter defaults name (`03-cpp.md`, Headers: `template<class G = Graph>`). For a type parameter without a default, of a template outside detail namespaces, the input type is the first namespace-scope type outside them that declares, base classes included, every member the template uses on an object of that parameter (`g.arcs`, `g[u]`), searched in the template's own header, then in its includes, nearest first. There is none when those members are all ones a standard sequence or the monoid protocol has (`s.size()`, `m.op`), as for a string or a problem-chosen monoid.
- Own names in file mode: no global-namespace type or alias comes whose name the file declares or `#define`s itself, however it is reached, since it would be redefined (the file's own `struct Sum` replaces the library's). A type inside a library namespace (`lichao_detail::Line`) and functions of those names still come.
- Reach: everything kept pulls in what it reaches.
  - Resolved references.
  - Dependent names, looked up among the units of the include closures of every header with kept code (in a bundle, also of every header the source includes) that C++ lookup can reach from a kept unit spelling the name. A candidate and the caller are both taken in the namespaces they belong to (an out-of-line `T ns::f(...)` belongs to `ns`). A candidate is reachable when it is written `ns::name` with `ns` its namespace or an alias of it declared in the caller's include closure, through further aliases (`::name` is the global one), or unqualified where its namespace encloses the caller's, where a `using namespace` in the caller names it, or where it is the innermost namespace of a kept type or enum (argument-dependent lookup at instantiation). So `C::mul` through a template parameter never keeps `polynomial_detail::mul`, and an unqualified `key` in one detail namespace never keeps another's. Dependent names are also looked up among the members of kept structs.
  - Dependent member names, among the members of kept structs, and the members a kept using-declaration names (`using B::add, B::prefix;` of a dependent base).
- Overload sets and specializations stay together: the same name in the same class, or in the same namespaces, an out-of-line `template<> int ns::f<int>(int)` included. An out-of-line class member's definition pairs with nothing, and no out-of-line definition is a command-line name, a `--find` hit or a suggestion of its own (`grab garner` is the CRT one).
- Pruned structs: a dependency struct keeps its head and closing line, fields, static data, typedefs and aliases, nested types, constructors (constructor templates of class templates included), destructors, conversion functions and every operator, friend operators included. It also keeps the protocol names `begin`, `end`, `rbegin`, `rend`, `cbegin`, `cend`, `size`, `empty`, `data`, `swap`, `get` and `hash`, whose uses the standard library hides. Other members come only when something reaches them.
- Monoids (user decision 2026-11-22, `WHOLE_TYPES`): a type declared in `02-Data Structures/00-monoids.hpp` is never pruned. However it is reached (a base class, an alias's target, the struct of a member, a root under `--min`), it comes whole, since a monoid's members are called through the structure it parameterizes, which grab may not see (`grab RangeAddRangeMax` had brought `Max` without `op`).
- Attached declarations: a namespace-scope operator, `std` specialization, `static_assert` or using-declaration is kept with a library type it names. An out-of-line member definition goes with its in-class declaration (and keeps its class), and an out-of-line namespace member (`convolution_detail::garner`) with its declaration, never with a type either one takes: `ShortestPathResult::relax(const GraphArc &)` comes neither with `Graph` nor with a pruned `ShortestPathResult` that never calls it. A declaration sharing a line with kept code is kept, and comment lines directly above a kept declaration go with it.
- Output: kept lines verbatim, headers in typing order, a blank line where skipped code crossed one, the system includes of every contributing header, and no quoted includes or `#pragma once`. A preprocessor conditional around kept code keeps all its directive lines and every branch line no unit covers in either configuration, such as a branch neither configuration parsed (`INFINT_SCRATCH_HEAP`). The identifiers on those lines are looked up like dependent names, so what such a branch uses is kept. `--lines` adds `#line N "header"` before each run of lines.
- File mode (`--into`, the expander, the harness): the roots are the public namespace-scope names (outside detail namespaces) that the file's identifiers spell, plus `x_detail::name` pairs, minus:
  - names the file declares itself at namespace scope, anonymous namespaces included: an identifier after another identifier or a simple template-id and followed by `;`, `=`, `(`, `{`, `[`, `,` or `)`; every later declarator of the same declaration (`int n, rng;`, `lng a = 1, dot = 2;`, not a comma inside the type's template brackets); or an identifier after `struct`, `using` and similar, but not `typename X<..>::y`. An identifier at the end of a line declares nothing, so `static DSU` / `d(5);` uses `DSU`;
  - names the file `#define`s;
  - names it uses only as locals, parameters or members: each use outside member access (`a.x`, `p->x`, `A::x`) lies in the scope of one of its declarations inside a body, a parameter list (to the end of the body or statement that follows) or a struct (`auto dfs = [&](...)` in `solve`);
  - names it spells only in member access (`s.twice()` roots no free `twice`).

  Identifiers in `#define` bodies, outside their parameters and literals, count as uses (`#define MI ModIntMini<998244353>`). `--into` keeps the roots whole, exactly as `grab <those names>` does; `--into --min`, the expander's bundles and the harness prune them like dependency structs (user decision 2026-11-06). In every file mode each kept struct also keeps the members the file's identifiers name, so a member called on a struct the file never names stays (`dijkstra(g, {0}).path(g, 2)` keeps `ShortestPathResult::path`). A solution reruns `--into` after using another library name, and with `--min` after calling another member too.
- Unknown names (user decision 2026-11-06): grab exits 1 listing up to five accepted names closest to the unknown one (difflib ratio at least 0.6, case ignored) and never substitutes one (`DUS` suggests `DSU`). A bare name is compared with top-level names, `A::b` with qualified names, members included; detail names are never suggested. Below them grab lists the three inventory rows closest to the name; `--find` searches the rows ([00-search.md](00-search.md), P263).
- `--into FILE` placement: the block between `// grab begin: <names>` and `// grab end` goes above the first global-scope declaration whose code spells one of its names, or above the one holding the first `void solve(` line, whichever comes first. A whole user namespace counts as one declaration, so the block never lands inside it, and comment lines directly above that declaration stay below the block. An existing block keeps its place unless that point lies above it. With no library names the block is removed. Copying tries `wl-copy`, `xclip`, `xsel` and `pbcopy`, and otherwise says it did not copy.
- Without libclang: SKIP on stderr. The headers that declare at namespace scope a requested name or one of its qualifiers (in file mode, an identifier the file uses and does not declare itself) are inlined whole with their include closures; template parameters, members and locals do not count.

### Expander Bundling

`bundle(source)` replaces each library include of the source with the headers its closure reaches first, in typing order: the template (and debug) header whole after `#line 1 "<header>"`, then those headers' lines of the file-mode extraction from all the included closures, with `#line` directives, then `#line <next line> "<source>"`. An include that reaches nothing new becomes a blank line, so line numbers hold, and a `#define` or `#pragma` between includes acts on the same library code as in the source. A library include inside `#if` is an error, since the headers it brings depend on the macros; so is any other quoted include outside the library. Both errors point to `--bundler oj-bundle`. An included aggregate (`98-basic.hpp`, `99-all.hpp`) stands for the headers it includes. `01-expander.py` runs the bundler in process by default; any other `--bundler` value names the oj-bundle executable.

### Harness

`05-extraction.py [ops|testers|both] [--mode quick|full] [--seed] [--sample] [--filter] [-j] [--timeout] [-v]`.

- `ops` parsing: each implemented `01`–`07` row's Operations cell (rows matching `--filter`, then sampled in quick mode) becomes (group types, operation) pairs. `;` and `,` split outside parentheses and brackets, a half-open `[l, r)` included; group heads keep their qualifiers and template arguments; `internals:` is read too. Operator entries become operator names (`+=` and `operator+=` are `operator+=`; `operator()` stays whole), and `,` inside template brackets (`StaticMatrix<T, N, M>`, a `<` after a name other than `operator`) does not split.
- `ops` resolution, in order: a group type's member `Type::op` (through an alias or a base class; `ctor` to its constructors); the group type itself when it is a nested struct or an enum, which grab keeps whole, and its text spells the operation (`Barrett32::Multiplier: value`, `SegmentedSieveMode: Odd`); a unit of that header named `op`, namespace scope first; any unit of that header named by the operation's last component (an operation listed outside its group, a `std::hash` specialization). Otherwise the entry is counted as declaring nothing (descriptive entries such as `linear vector build`). A type never stands in for an operation it does not spell.
- `ops` compiles: identical extractions compile once, with `-fsyntax-only` after the template and debug headers, on `$CXX` and `g++-14`, each under a 2048 MB cap, through ccache in files named by their content, so an unchanged extraction hits in every run.
- `ops` probes: `-fsyntax-only` instantiates only templates the code uses, and an extraction alone uses none, so each extraction also carries probes. For each class template it extracts (or whose member it extracts) and each namespace-scope function template, the probe is the first candidate `template struct X<args>;` or `&f<args>` that compiles after the whole header and `02-Data Structures/00-monoids.hpp`. Those control builds run on `$CXX` in rounds: a header's pending candidates together, then one by one where that build fails. The arguments fill the parameters before the first default: for a type `lng`, then the presets `Sum<lng>` and `RangeAddRangeSum<lng>`, then `ulng`; `4` for an integer; `false` for a `bool`; at most 12 combinations, fewest changes first. A template with a parameter of another kind is not probed. A probe naming a preset adds the preset to its extraction. So a probe fails only when the extraction dropped something. `-v` lists the templates no candidate instantiates (a callable or another parameter without a default).
- `ops` failures beyond compilation: an extraction keeping code outside its header's include closure, and a public function template of a `02`–`07` header whose type parameter grab must infer (`grab.inputs`), since `03-cpp.md` (Headers) asks for its default (pending outside verified rows). `ops` also runs the `full-only until` check.
- `testers`: each `0[1-7]-*/*_tester.py` except the `_compile_` ones, whose folder has C++ files of its prefix or whose text writes an `#include`. A scratch tree holds the tester's folder, the shared runners, the template and debug headers and every aggregate unchanged. Every other library header becomes a stub: `#pragma once`, the header's own quoted includes, then its lines of the file-mode extraction of the tester's files, so a tester that copies or scans a header's text still finds its declarations. The extraction takes the identifiers of the tester's files (Python included, literals too) within the include closures of the headers and aggregates they name. The names they declare come from their C++ code and from Python string literals holding `;`, a brace or `#include`, never from docstrings, comments or messages. The tester's quick mode runs there and caps itself. Its builds go through `Builder`, and the scratch tree's stable relative paths let an unchanged extracted source hit ccache. A failure beside others is rerun alone.

## Limits and Handoffs

- `declared()` is a heuristic; base clauses after `public`, `protected`, `private` or `virtual` are not declarations. A namespace-scope declaration it misses lets a same-named library declaration in, which then fails to compile as a redefinition, and prose that looks like a declaration keeps a name out. In the harness, Python files contribute only string literals holding `;`, a brace or `#include`.
- A command-line name keeps every namespace-scope declaration with that spelling, across headers; `Type::member` or a qualified name narrows it.
- A preprocessor branch neither configuration parses (Windows-only code, a macro nobody defines) is copied whole whenever its group is kept, never pruned, and its identifiers are matched by spelling only.
- Operations entries that name nothing their header declares are counted and checked no further; `-v` lists them. On 2026-11-07 there were 190, mostly descriptive entries and operators (`linear build`, `+=`), 126 of them identifier-like. Among rows and packages that are both verified only `kLargest` (`06-Miscellaneous/54-kbest_enumeration.hpp`, kept by the decision of 2026-10-23) remains; the 27 others were fixed (user decision 2026-11-06). The rest sit in rows not yet verified, whose packages own the fix: `aStar` in `04-Graphs/13-shortest_path_advanced.hpp`, `hankelSolve` in `01-Core/10-matrix.hpp`, and `build` in `04-Graphs/16-centroiddecomposition.hpp`, whose constructor is `ctor`.
- `ops` instantiates only default forms with the first compiling probe candidates. 236 templates (`-v` lists them) take a parameter no candidate fits (a callable, a polynomial type, a predicate); they, member templates and overload sets taken by address are checked only by `-fsyntax-only` and by the testers' extracted builds. A probe proves that an instantiation compiles, not that it computes anything.
- Input-type inference reads an undefaulted type parameter only from members used through a parameter declared `P &x`, `const P &x` or `P x` (`x.m`, `x->m`, `x[`). It never reads a constrained parameter, a lambda's own parameter that shadows it, or calls through free functions. It takes the first top-level type of the own header, then of the includes nearest first, that declares every member used. The library now defaults every such parameter (`03-cpp.md`, Headers), so the inference only guards new headers, and `ops` fails a verified row that relies on it.
- Lookup stays a superset where C++ resolves only at instantiation. A dependent member name keeps every kept struct's members of that name (`.size()` keeps `Graph::size` once `Graph` is kept), and an unqualified dependent name keeps a same-named function of any namespace holding a kept type, since argument-dependent lookup may reach it. Both add lines only inside headers the root can see: `ops` fails an extraction keeping code outside its header's include closure, and a scratch audit on 2026-11-07 (every public name alone and in file mode, pruned and whole) found none.
- Lookup forms the library does not use are not modelled: inline namespaces, a `using namespace` at namespace scope around the caller (`03-cpp.md` forbids re-exporting a detail namespace), an alias of a nested namespace resolved by its innermost name, and an out-of-line nested class or its partial specialization (`struct Outer::Inner<T *>`). Three independent reviews on 2026-11-07 probed these and the modelled forms with fixtures; the confirmed cases are in `test_lookup_rules`.
- A template default keeps its type whole: `grab dijkstra` brings all of `Graph`, and a default `mint` brings the whole mini, since the type is what a caller instantiates.
- `03-consistency.py` reads the cached index only, so its full-only check reports itself skipped while headers are unindexed; a cold index takes about 4 minutes with 6 parallel parses.
- `05-extraction.py` does not run under `ensure()`, because one 4096 MB scope cannot hold four parallel testers. Each compile it starts runs under a 2048 MB cap, and each tester caps itself.
