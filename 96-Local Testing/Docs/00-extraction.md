## Contracts

### Index

- Headers: every `0[1-7]-*/**/*.hpp` outside `97-Legacy` and the `98-`/`99-` aggregates, except `01-Core/01-template.hpp` and `02-debug.hpp`, which are never indexed or emitted: the contest template holds both.
- Parse: libclang with `-x c++ -std=gnu++20` and its own resource directory (found beside the loaded `libclang` library), once per configuration: scalar, and `-mavx2 -mfma -mbmi -mbmi2 -mpclmul -mpopcnt -mlzcnt`. A parse error stops the index build: grab exits 1 naming the header and its first diagnostics. libclang 23 parses every library header against libstdc++ 16 without errors.
- Units: each namespace-scope declaration (namespaces are containers), each member of a namespace-scope struct, class, union or class template, with its extent; aliases and typedefs are marked as such. A unit seen in both configurations is one unit. References: a resolved reference into a library header is a position (header, line, column), mapped to the innermost unit there; an overloaded or dependent name is kept by spelling (`names`), a dependent member access (`pc.inverseFactorial(i)`) by its last identifier (`members`).
- Cache: one JSON file per header in `09-Contest Testing/.grab-cache` (git-ignored), keyed by `VERSION` (the record format), libclang's version, the constants and the source of every function the analysis reads (`analysis_id`: `PROTOCOL`, `EXCLUDED`, `CONFIGS`, the directive patterns, `analyze`, `scan_lines`, `merge`, `index_header`, `resource_dir`, `library`, `stamp`) and the bytes of the header's include closure, so an edited header re-indexes itself and its dependents only, and a changed analysis or libclang re-indexes everything. Each record also stores the size and modification time of every file outside the repository its parses read (libstdc++, libclang's builtin headers); a record whose stamps differ, or that has none, is rebuilt. A cold index of the 172 headers takes about 4 minutes with 6 parallel parses; a cached load takes 0.7 s. `Index(build=False)` loads cached records only and lists the rest as `stale`.

### Selection and output

- A name given on the command line keeps its declaration whole (`Type::member`: that member, its struct pruned). `Alias::member` names the member of the type an alias names (`ModInt::sqrt`) and keeps the alias too, its type pruned, since the code spells it; an alias kept whole keeps that type whole (`grab mint`). A function template kept whole keeps its input types whole, since the caller builds them (`grab dijkstra` brings `Graph` with `addEdge`): the types its template parameter defaults name (`03-cpp.md`, Headers: `template<class G = Graph>`), and, for a type parameter without a default of a template outside detail namespaces, the first namespace-scope type outside them that declares, base classes included, every member the template uses on an object of that parameter (`g.arcs`, `g[u]`), searched in the template's own header, then its includes, nearest first; none when those are all members a standard sequence or the monoid protocol has (`s.size()`, `m.op`), as for a string or a problem-chosen monoid (user decision 2026-11-06). In file mode no global-namespace type or alias comes whose name the file declares or `#define`s itself, however it is reached, since it would be redefined (the file's own `struct Sum` replaces the library's); one inside a library namespace (`lichao_detail::Line`) and functions of those names stay. Everything kept pulls in what it reaches: resolved references; dependent names, looked up among the units of the include closures of every header with kept code (in a bundle also of every header the source includes), as argument-dependent lookup at instantiation finds them, and among the members of kept structs; dependent member names among the members of kept structs, and the members a kept using-declaration names (`using B::add, B::prefix;` of a dependent base). Overload sets and specializations (same name, same scope) stay together.
- A dependency struct keeps its head and closing line, fields, static data, typedefs and aliases, nested types, constructors (constructor templates of class templates included), destructors, conversion functions, every operator including friend operators, and the protocol names `begin`, `end`, `rbegin`, `rend`, `cbegin`, `cend`, `size`, `empty`, `data`, `swap`, `get`, `hash`, whose uses the standard library hides; other members only when something reaches them. A namespace-scope operator, `std` specialization, `static_assert` or using-declaration is kept with a library type it names; an out-of-line member definition with its class. A declaration sharing a line with kept code is kept, and comment lines directly above a kept declaration go with it.
- Output: kept lines verbatim, headers in typing order, a blank line where skipped code crossed one, system includes of every contributing header, no quoted includes or `#pragma once`. A preprocessor conditional around kept code keeps all its directive lines and every branch line no unit covers in either configuration (a branch neither configuration parsed, such as `INFINT_SCRATCH_HEAP`); the identifiers on those lines are looked up like dependent names, so what such a branch uses is kept. `--lines` adds `#line N "header"` before each run of lines.
- File mode (`--into`, the expander, the harness): the roots are the namespace-scope public names (outside detail namespaces) the file's identifiers spell, plus `x_detail::name` pairs, minus names the file declares itself at namespace scope, anonymous namespaces included (an identifier after another identifier or a simple template-id and followed by `;`, `=`, `(`, `{`, `[`, `,` or `)`, every later declarator of the same declaration (`int n, rng;`, `lng a = 1, dot = 2;`, not a comma inside the type's template brackets), or after `struct`, `using` and similar but not `typename X<..>::y`; an identifier at the end of a line declares nothing, so `static DSU` / `d(5);` uses `DSU`), minus the names it `#define`s, and minus names it uses only as locals, parameters or members: each use outside member access (`a.x`, `p->x`, `A::x`) lies in the scope of one of its declarations inside a body, a parameter list (to the end of the body or statement that follows) or a struct (`auto dfs = [&](...)` in `solve`). Identifiers in `#define` bodies, outside their parameters and literals, count as uses (`#define MI ModIntMini<998244353>`). `--into` keeps the roots whole, exactly as `grab <those names>` does; `--into --min`, the expander's bundles and the harness prune them like dependency structs (user decision 2026-11-06). In every file mode each kept struct also keeps the members the file's identifiers name, so a member called on a struct the file never names stays (`dijkstra(g, {0}).path(g, 2)` keeps `ShortestPathResult::path`); a solution reruns `--into` after using another library name, and with `--min` after calling another member too.
- An unknown name exits 1 listing up to five names grab accepts closest to it (difflib ratio at least 0.6, case ignored; top-level names for a bare name, qualified names, members included, for `A::b`; detail names never) and never substitutes one (user decision 2026-11-06: `DUS` suggests `DSU`).
- `--into FILE` puts the block between `// grab begin: <names>` and `// grab end` above the first global-scope declaration (a whole user namespace counts as one, so the block never lands inside it) whose code spells one of its names, or above the one holding the first `void solve(` line, whichever comes first (comment lines directly above that declaration stay below the block); an existing block keeps its place unless that point lies above it. With no library names the block is removed. `--find TEXT` lists qualified names containing TEXT (case-insensitive) with header and line. Copying tries `wl-copy`, `xclip`, `xsel` and `pbcopy`, else says it did not copy.
- Without libclang: SKIP on stderr, and the headers declaring at namespace scope a requested name or one of its qualifiers (in file mode, an identifier the file uses and does not declare itself) are inlined with their include closures, whole; template parameters, members and locals do not count.

### Expander bundling

`bundle(source)`: the source with each library include replaced by the headers its closure reaches first, in typing order: the template (and debug) header whole after `#line 1 "<header>"`, then those headers' lines of the file-mode extraction from all the included closures, with `#line` directives, then `#line <next line> "<source>"`; an include that reaches nothing new becomes a blank line, so line numbers hold. So a `#define` or `#pragma` between includes acts on the same library code as in the source. A library include inside `#if` raises an error (use `--bundler oj-bundle`), since which headers it brings depends on the macros. An included aggregate (`98-basic.hpp`, `99-all.hpp`) stands for the headers it includes; any other quoted include outside the library raises an error (use `--bundler oj-bundle`). `01-expander.py` runs it in process by default; any other `--bundler` value is the oj-bundle executable as before.

### Harness

`05-extraction.py [ops|testers|both] [--mode quick|full] [--seed] [--sample] [--filter] [-j] [--timeout] [-v]`.

- `ops`: each implemented `01`–`07` row's Operations cell (rows matching `--filter`, then sampled in quick mode) is parsed into (group types, operation) pairs (`;` and `,` split outside parentheses and brackets, a half-open `[l, r)` included; group heads with qualifiers and template arguments; `internals:`). Operator entries become operator names (`+=` and `operator+=` are `operator+=`, `operator()` stays whole), and `,` inside template brackets (`StaticMatrix<T, N, M>`, a `<` after a name other than `operator`) does not split. An operation resolves to a group type's member `Type::op` (through an alias or a base class; `ctor` to its constructors), else to the group type itself when it is a nested struct or an enum, which grab keeps whole, and its text spells the operation (`Barrett32::Multiplier: value`, `SegmentedSieveMode: Odd`), else to a unit of that header named `op` (namespace scope first), else to any unit of that header named by its last component (an operation listed outside its group, a `std::hash` specialization), else it is counted as declaring nothing (descriptive entries such as `linear vector build`); a type never stands in for an operation it does not spell. Identical extractions compile once, with `-fsyntax-only` after the template and debug headers, on `$CXX` and `g++-14`, each under a 2048 MB cap. `-fsyntax-only` instantiates only templates the code uses, and an extraction alone uses none, so each extraction also carries probes: for each class template it extracts (or whose member it extracts) and each namespace-scope function template, the first candidate `template struct X<args>;` or `&f<args>` that compiles after the whole header and `02-Data Structures/00-monoids.hpp` (control builds on `$CXX`, in rounds: a header's pending candidates together, then one by one where that build fails). The arguments fill the parameters before the first default: for a type `lng`, then the presets `Sum<lng>` and `RangeAddRangeSum<lng>`, then `ulng`; `4` for an integer; `false` for a `bool`; at most 12 combinations, fewest changes first. A template with a parameter of another kind is not probed. A probe naming a preset adds the preset to its extraction. So a probe fails only when the extraction dropped something. `-v` lists the templates no candidate instantiates (a callable or other parameter without a default). It fails on a public function template of a `02`–`07` header whose type parameter grab must infer (`grab.inputs`), since `03-cpp.md` (Headers) asks for its default (pending outside verified rows). It also runs the `full-only until` check.
- `testers`: each `0[1-7]-*/*_tester.py`, except the `_compile_` ones, whose folder has C++ files of its prefix or whose text writes an `#include`. A scratch tree holds the tester's folder, the shared runners, the template and debug headers, every aggregate unchanged and, for every other library header, a stub: `#pragma once`, the header's own quoted includes, then its lines of the file-mode extraction of the tester's files, so a tester that copies or scans a header's text still finds its declarations. The extraction takes the identifiers of the tester's files (Python included, literals too) within the include closures of the headers and aggregates they name; the names they declare come from their C++ code and from Python string literals holding `;`, a brace or `#include`, never from docstrings, comments or messages. The tester's quick mode runs there and caps itself; a failure beside others is rerun alone.

### Mini-first checks

`final(root)`: the targets whose findings fail, meaning verified rows of verified packages that are not support targets of open batches whose focus cites 2026-11-05; the others go to `mini_first_pending`. `core_full(root)`: non-mini `01-Core` type headers with a mini (a file or a Core inventory row, planned included), ISA code or a non-mini include (today 03, 04, 05, 07, 10, 12, 14, 16, 18, 19; `09-rational.hpp`, without any, counts as a mini). The checks' parsing (`full_type_names`, `full_defaults`, `operation_names`, `mini_first_split`) lives in `05-extraction.py` beside `core_full` and `final`; `mini_first_split` sends a strict target's findings to the errors and the rest to `mini_first_pending`. The checks: a template default in `02`–`07` spelling, anywhere in the default (`std::conditional_t<..., ModInt<7>, ...>`), a type, alias, enum or concept declared at namespace scope in a Core full header, detail namespaces included (not template parameters, members, specializations or `std::` heads); a mini row whose operation names (Mini removed, with `internals:` and the status's `missing:`) lack one of its full row's; an operation whose default-form extraction reaches a Core full header while its evidence document has no line with `full-only until` and the operation in a code span (cached index only in `03-consistency.py`, on the rows whose include closure is indexed; it reports how many rows wait). `03-consistency.py` also rejects `#define` and `#undef` in library headers other than the template and debug headers (`03-cpp.md`, Headers), since grab copies declarations, never macros.

## Limits and handoffs

- `declared()` is a heuristic (base clauses after `public`, `protected`, `private` or `virtual` are not declarations): a namespace-scope declaration it misses lets a same-named library declaration in, which then fails to compile as a redefinition, and prose that looks like a declaration keeps a name out. In the harness, Python files contribute only string literals holding `;`, a brace or `#include`.
- A command-line name keeps every namespace-scope declaration with that spelling, across headers. Use `Type::member` or a qualified name to narrow it.
- A preprocessor branch neither configuration parses (Windows-only code, a macro nobody defines) is copied whole whenever its group is kept, never pruned; its identifiers are matched by spelling only.
- Operations entries that name nothing their header declares are counted and checked no further (`-v` lists them): 190 on 2026-11-07, mostly descriptive entries and operators (`linear build`, `+=`), with 126 identifier-like names. In rows and packages both verified only `kLargest` (`06-Miscellaneous/54-kbest_enumeration.hpp`, kept by the decision of 2026-10-23) remains, after the 27 others were fixed here (user decision 2026-11-06); the rest sit in rows not yet verified (`aStar` in `04-Graphs/13-shortest_path_advanced.hpp`, `hankelSolve` in `01-Core/10-matrix.hpp`, `build` in `04-Graphs/16-centroiddecomposition.hpp`, whose constructor is `ctor`), whose packages own the fix.
- `ops` instantiates only default forms with the first compiling probe candidates: 236 templates (`-v` lists them) take a parameter no candidate fits (a callable, a polynomial type, a predicate) and are checked by `-fsyntax-only` and by the testers' extracted builds only, as are member templates and overload sets taken by address. A probe proves the instantiation compiles, not that it computes anything.
- Input types: grab infers an undefaulted type parameter only from members used through a parameter declared `P &x`, `const P &x` or `P x` (`x.m`, `x->m`, `x[`), never from a constrained parameter, a lambda's own parameter that shadows it or calls through free functions; it takes the first toplevel type of the own header, then of the includes nearest first, declaring every member used. The library now defaults every such parameter (`03-cpp.md`, Headers), so the inference only guards new headers, and `ops` fails a verified row that relies on it.
- A template default keeps its type whole: `grab dijkstra` brings all of `Graph`, and a default `mint` brings the whole mini, since the type is what a caller instantiates.
- `03-consistency.py` reads the cached index only, so its full-only check reports itself skipped while headers are unindexed; a cold index takes about 4 minutes with 6 parallel parses.
- `05-extraction.py` does not run under `ensure()`. Each compile it starts runs under a 2048 MB cap, and each tester caps itself, because one 4096 MB scope cannot hold four parallel testers.
- 194 operations (`ops`) and 205 consistency findings are pending: targets of the open 2026-11-05 mini-first batches. Each fails once its row and package are verified and its batch has closed.
- `06-divisionmini` exceeds the judge's time limit on 9 of 26 tests (up to 21.4 s; on 2026-11-05 the bundle and an unbundled build took 10.9 s on `large_00` alike and both printed the judge's answer), so the cause is the mini's division speed, not the bundling; P255–P257 (mini parity) own it.
- `ops --mode full` takes about 48 minutes at `-j 6` and `testers --mode full` 20 minutes at `-j 4`; run them in the background.
