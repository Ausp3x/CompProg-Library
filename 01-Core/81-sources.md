## Previous source keys and audit narrative

- Keys retained from the 2026-09-27 inventory: ACL (AtCoder Library), KACTL, CPA (cp-algorithms), OI (OI Wiki), NYA (Nyaan), MAS (maspypy), EI (ei1333), SUI (suisen), HIT (hitonanode), TKO (tko919), GMP, FLINT, NTL, MCA (saved *Modern Computer Arithmetic*), YC (Library Checker).
- The 2026-09-27 audit compared current Core declarations and selected bodies, *Modern Computer Arithmetic*'s contents and the external catalog/documentation sources recorded in the [central audit](../00-Guidelines/16-inventory-audit.md). Catalog inspection establishes missing feature families, not implementation correctness or a claim of surveying every paper.
- The follow-up scope pass inspected the Matrix/BitMatrix/SparseMatrix and archived Poly/Moly public operations, full/mini InfInt conversion and sentinel interfaces, and the saved [KACTL notebook](../95-Resources/05-kactl.pdf) tridiagonal-solver contract; it made structured solves and the mini/sparse migration obligations explicit without verifying implementations.
- The 2026-10-06 rewrite extracted the real public API of every existing header (template, debug, barrett, montgomery, modint, modintmini, infint, infintmini, matrix, bitmatrix, sparsematrix, bitset) and of the archived `OLD/5-Mathematics/10-poly.hpp` and `11-moly.hpp`, and reconciled them with the evidence documents [21](21-c01-verification.md), [22](22-bitset.md), [23](23-reduction.md), [24](24-modint.md) and [25](25-modintmini.md).

## Not adopted

- Library Checker set_power_series (subset convolution, exp/log/composite/power projection of set power series): Mathematics `66-set_power_series.hpp` and `24-transform_algorithms.hpp` own them.
- Library Checker bitwise and/xor, gcd/lcm, min-plus and Dirichlet convolutions: Mathematics `24`, `53`, `32` own them.
- Library Checker number_theory items (sqrt_mod, kth_root_mod, primitive_root, discrete_logarithm, tetration, nim_product, kth_root_integer, rational_approximation, Stern–Brocot): Mathematics `11`, `21`, `30`, `20`, `47` own them.
- Library Checker enumerative_combinatorics (binomials, factorials, Stirling/Bell/partition numbers, sharp-p subset sum): Mathematics `05`, `12`, `37`, `38` own the scalar algorithms; Poly only supplies the generating-function kernels (`famousSeries`).
- maspy `linalg/xor`, suisen `xor_base`, ei1333 `binary-basis`, tko919 `F2vector`: Data Structures `62-xorbasis.hpp` owns the incremental XOR basis.
- maspy/Nyaan polynomial-matrix determinant and prefix products, `det_A_plus_xB` beyond the single named operation, P-recursive finding: Mathematics `51-polynomial_matrix.hpp` owns them.
- Nyaan `matrix-tree`, suisen `count_spanning_trees`: Mathematics `23-matrixtree.hpp` owns them.
- Nyaan `adjunction-modint`, hitonanode `dual_number`, `gaussian_integer`, `nimber`: Mathematics `57-quadratic_integer.hpp` and `47-nimber.hpp` own them; dual numbers have no owner and no demonstrated shared need.
- Nyaan `vectorize-modint`/`simd-montgomery` as public types: SIMD lanes remain internal kernels of Poly/Matrix rather than a separate public residue type.
- maspy `O1_inverse`, `all_inverse`, `power_table`, `factorial*`: Mathematics `09-modinverse.hpp` and `05-combinatorics.hpp` own tables.
- NTL `quad_float`/`xdouble`, FLINT `double_interval`: a double-double float helper has no Core owner; raised as a placement question (Mathematics `63-multiprecision_float.hpp` or `62-ball_arithmetic.hpp` candidates).
- GMP `mpz_nextprime`, `mpz_probab_prime_p` beyond BPSW screening, factorial/binomial/Fibonacci/Lucas/primorial: Mathematics `36`, `05` own them; InfInt only screens primality.
- FLINT HNF/SNF/LLL and `fmpz_lll`: Mathematics `49-integer_linear_algebra.hpp` and `35-lattice_reduction.hpp` own them.
- FLINT `fmpq` continued fractions and rational enumeration (Calkin–Wilf, Farey, simplest_between): Mathematics `20-continued_fraction.hpp` owns them.
- FLINT/NTL finite-field extension polynomials (`ZZ_pE`, `GF2E`, `fq`): Mathematics `42-finite_fields.hpp` owns them.
- Arithmetic modulo 2^64 as a residue type: native `ulng` wraparound suffices; raised as a placement question for the odd-unit inverse only.
- Overflow-checked/saturating add and mul and exact native isqrt/icbrt: Mathematics `01-mod_arithmetic.hpp` and `21-integer_roots.hpp` own them (raised as a placement question for the saturating variants).
- maspy `ds/bitset` (`bit_array`, `bit_vector`, `binary_trie`), hitonanode `dynamic_bitset` beyond the verified Bitset API: Data Structures own succinct/dynamic rank-select and binary tries; no new Bitset operation was found.
