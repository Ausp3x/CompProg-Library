# 07-infint.hpp — evidence

P018/C04 owns `07-infint.hpp`: the arbitrary-precision signed integer `InfInt` (alias `iint`), the fixed-width unsigned `UInt<N>` (alias `u256 = UInt<4>`), and the `infint_detail` word kernels they share. The header depends on `01-template.hpp` only; by decision (2026-10-16) it keeps its own three-prime Montgomery NTT, Goldilocks NTT and double FFT kernels instead of reusing Poly's, and no Core Barrett or Montgomery type. Prerequisites P002, P005 and P025 are verified.

## Contracts

### Representation and sentinel

`InfInt` is sign-magnitude: `int sgn` (`1` or `-1`), `bool is_inf`, `Words n` (`infint_detail::Words`): little-endian base-2^64 words (`infint_detail::W`, little-endian hosts only, `static_assert`ed) without leading zero words, four stored inline and longer values on the heap (`sizeof(InfInt) == 56`; `Words` copies, moves and resizes like a vector with `int` sizes: `data()`, `size()`, `operator[]`, `back()`, `assign`, `resize` zero-filling, `setSize` leaving new words unset, `push_back`, `pop_back`, `reserve`). Zero is `{0}` after any operation (a default-constructed value keeps `n` empty, also zero) with `sgn == 1`. Poly's `BigInt` concept reads `n.data()`, `n.size()`, `sgn`, `trim()` and `isNil()`; `trim()` restores the canonical form after a caller edits `n` directly. Kernels work on the words in place, so no conversion precedes an operation (stage 1 of the 2026-10-25 re-check, 2026-10-26; before it `n` was a `vector<uint>` of base-2^32 limbs copied into words before every kernel call). A moved-from `InfInt` is zero (the move operations reset the source to `sgn = 1`, `is_inf = false`, empty `n`; finish audit 2026-10-26). Operands of `bitLength`, `popcount` and `ctz`, and of the operations that call them (`divMod`, `divExact`, `removeFactor`, `gcd`, `powMod`, `kthRootRem`, `isPerfectPower`, `jacobi`, `kronecker`, `isProbablePrime`, `newtonRaphsonInv`, `toDouble`, `charsBound`, `toChars`, `sample`, `testBit` on a negative), have fewer than 2^25 words (asserted; bit counts are `int`), while `*`, `+`, shifts and `read` admit values up to `NTT_MAX_WORDS = 2^28` words (Limits).

Memory: temporaries come from one thread-local bump arena (`infint_detail::arena()`) of 2 MiB-aligned blocks (`::operator new` with `std::align_val_t`; `madvise(MADV_HUGEPAGE)` under `#ifdef __linux__`, user decision 2026-10-25 overriding the no-POSIX-headers rule of `03-cpp.md`, every other platform gets the aligned memory only), each new block at least twice the previous and at least the frame it serves; `Scratch s(n)` reserves `n` words as the newest frame and frames release in LIFO order; the arena keeps one spare block so that a repeated peak reuses its pages and frees everything at thread exit. Under `INFINT_SCRATCH_HEAP` every frame is a separate `new W[]` allocation filled with `infint_detail::POISON` (the sanitizer builds: ASan sees each frame and a kernel that relies on zeroed scratch fails deterministically; the arena hands out fresh zero pages at first, so such a defect shows there only once memory is reused, which is how the stage-1 Burnikel–Ziegler defect in `div3n2n` escaped the smoke test and was caught by the consumer runs and a poisoned probe). The transform root tables and scratch are typed `HugeVec<T>` tables (huge-page allocations that grow to the largest size used and live for the process, replacing the 12 MB `vector` tables; typed so that no memory is read through two types), the radix cache is `InfInt::radix`. Nothing else allocates per call: `read`, `toChars`, `<<`, `>>` (after its first long token), `divMod`, the shifts, `gcd` and the arithmetic on values of at most four words touch the heap only for a result that outgrows the inline words.

The signed infinity sentinel (kept by the duplicate sweep, 2026-10-16) is produced by `read`/the string constructor from `inf` in any letter case with an optional sign in bases 2–23 (in bases 24–36 the same letters are digits: `INF` is 24171 in base 36, so the sentinel does not round-trip through text there), by `fromDouble(±infinity)`, and by arithmetic. Finite semantics never involve it. Rules, with `x` finite, `p` finite nonzero: `inf + x = inf`, `inf + inf = inf`, `inf + (-inf) = 0`, `inf - inf = 0`; `inf * x = ±inf` for `x != 0`, `inf * 0 = 0`, `inf * inf = ±inf`; `inf / p = ±inf`, `x / inf = 0`, `inf / inf = ±1`; `inf % p = 0`, `x % inf = x`; `divMod` and `divModSlow` agree with `/` and `%`; `abs`, unary `-`, `+`, comparisons (`inf` above every finite value, `-inf` below, `inf == inf`), `++`/`--` (no change), `<<=`/`>>=` (no change), `pow` (`inf^0 = 1`, sign by parity), `sqrt(inf) = inf`, `gcd(inf, x) = |x|` for `x != 0` and `inf` otherwise, `exGcd` with cofactors `±1`/`0`, `lcm(x, inf) = inf` for `x != 0`, `toString` (`inf`/`-inf`), `toDouble` (`±infinity`), the native casts (saturating: `LLONG_MAX`/`LLONG_MIN`, `ULLONG_MAX`/`0`), `tryCast` (false), streams and `std::hash` accept it. Every other operation asserts finite operands (`divModFloor`/`Ceil`/`Euclid`, `divExact`, `removeFactor`, bitwise operators, bit queries, roots, `jacobi`, `kronecker`, `isProbablePrime`, `inv`, `powMod`, `toDigits`, `toLimbs`, `UInt` conversion, `newtonRaphsonInv`, sampling bounds); under `NDEBUG` each of these returns a bounded meaningless value (0, -1, false, the operand or an empty result) instead of looping or reading out of bounds, as do a zero divisor or modulus, a negative shift count or bit index, `pow` with a negative exponent, `removeFactor` by ±1, `kthRootRem` with `k < 1`, bases outside the documented ranges and `UInt` shifts outside `[0, 64 N)`.

| `toChars(char *first, char *last, uint base = 10, bool lower = false)` | Writes the text of `toString(base, lower)` into `[first, last)` without a terminator and returns `{end, errc()}`; when the room is short it returns `{last, errc::value_too_large}` and writes nothing (the length is known before the first byte is stored). | `tryCast<T>(T &out)` | `T` integral through 128 bits. True iff the value is representable (signed minima included), then stores it; otherwise `out` is unchanged. False for the sentinel. |
| `explicit operator lng()`, `explicit operator ulng()` | Finite values reduce modulo 2^64 (two's complement wrap, like a C cast); the sentinel saturates. |
| `explicit operator bool()`, `isNil()` | Nonzero test and its negation (both kept by decision 2026-10-16); the sentinel is nonzero. |
| `toDouble()` | Correctly rounded to nearest, ties to even (a 64-bit window with a sticky bit); magnitudes at or above 2^1024 after rounding give `±infinity`. |
| `fromDouble(double d)` | `d` not NaN (asserted). The integer part toward zero, exactly (`1e300` reproduces its binary value); `±infinity` give the sentinel. |
| Streams | `>>` extracts one whitespace-delimited token with the library's string extractor into a `thread_local` string reused across calls (allocation-free after the first token longer than the buffer; libstdc++ scans the stream buffer's get area directly, which measured 2x faster than a `sgetc`/`snextc` loop in this header, Benchmarks) and parses it with `read` in the stream's base (`SetBase(b)` manipulator stored in a per-stream `iword`, default 10; `std::hex` and `std::oct` flags override it); a malformed token or no token sets `failbit` and keeps the destination; a token that ends at end of input sets `eofbit` and stores the value; a nonzero `width()` limits the token length as it does for strings. `<<` prints `toChars` in the stream's base from an arena frame in one `write`; with a nonzero `width()` it inserts a `string_view`, so `setw`, `setfill` and `left`/`right` apply (`showpos`, `showbase` and `uppercase` do not: `std::format` covers them). `getBaseId()` is the `iword` index. |

Identical to Python's `format(int, spec)` on these specs (the tester's oracle). ### Arithmetic and division

| Feature | Contract |
|---|---|
| `+=`, `-=`, `+`, `-`, `++`, `--`, unary `+`, unary `-`, `abs` | Exact; `a -= a` and `a += a` are allowed. `a + b` and `a - b` on lvalues build the result out of place in one pass over the words (`combine`: the magnitude sum into `max(k) + 1` words, or the magnitude difference after `magCmp`); with an rvalue left operand they run the compound form in its storage. `+=` grows by exactly one word, out of place, when a carry leaves the top word. |
| `*=` (`InfInt`), `*` | Exact; `a *= a`, `a * a` and equal operands take the squaring backends; one-word operands take the word multiply; the dispatcher chooses basecase, Karatsuba, Toom-3 or a transform by the measured thresholds below, and in the transform range cuts the longer operand into chunks that fill their transforms when that costs less (`infint_detail` kernels). |
| `*=`, `*` with a native integer (`isScalar`: integral types of at most 64 bits except `bool`) | Exact, O(n); powers of two shift. |
| `/=`, `%=`, `/`, `%` (`InfInt` and scalars), `divMod` | Truncating division, divisor nonzero (asserted); the remainder keeps the dividend's sign and `\|r\| < \|b\|`; `a /= a = 1`, `a %= a = 0`. `divMod` and `divModSlow` take their operands by const reference (`divMod(a, a)` and operands living in one vector are fine) and build the pair in place; `divMod` on one-word operands divides natively (the scalar `/=` and `%=` keep the word division); a power-of-two divisor (`popcount(b) == 1`) shifts and masks in O(n); other word divisors use Möller–Granlund reciprocal division, longer ones the dispatcher (Knuth D below `BURNIKEL` words or for short quotients, Burnikel–Ziegler above). |
| `divModSlow(a, b)` | The same results through Knuth D only (the schoolbook backend), kept as a separate algorithm. |
| `divModFloor(a, b)` | Floor division pair: remainder with the divisor's sign (`.first` and `.second` are the floor quotient and remainder; there are no separate single-result forms). |
| `divModCeil(a, b)` | Ceiling division pair: remainder with the opposite sign of the divisor. |
| `divModEuclid(a, b)` | Quotient and remainder with the remainder in `[0, \|b\|)`. |
| `divExact(a, b)` | `b != 0` and `b \| a` (asserted modulo 2^61 - 1 after the fact; an inexact input returns a meaningless value under `NDEBUG`). After removing the common power of two: word-by-word Hensel (2-adic) division for quotients of at most `HENSEL` words, the quotient-only Burnikel–Ziegler division above (measured 1.3–2x faster than Newton–Hensel lifting at every larger size). |
| `removeFactor(x, f)` | `x != 0`, `\|f\| >= 2` (asserted). Divides `x` by `f` while divisible and returns the count (0 when not divisible); negative `f` flips the sign per removed factor; powers of two use shifts; `f` may be `x` itself (`x` becomes 1, count 1; before the 2026-10-26 review this looped forever). |
| `newtonRaphsonInv(a)` | `a > 0` with `bitLength(a)` a multiple of 32 and its top bit set, i.e. the top bit of its top 32-bit limb (asserted; the contract predates the word layout and is kept). Returns `floor(2^(2 L) / a)` for `L = bitLength(a)`, exactly. |

### Number theory

| Feature | Contract |
|---|---|
| `gcd(a, b)` | Nonnegative; `gcd(0, 0) = 0`. Backends by size: native `std::gcd` on one-word operands, `gcdBinary` up to `BINARY_GCD` words, Lehmer steps (`lehmerHalfGcd`) and divisions in between, recursive `halfGcd` above `HALFGCD` words. |
| `exGcd(a, b, x, y)` | Returns `g = gcd(a, b)` with `a x + b y = g`; when `a` and `b` are nonzero, `\|x\| <= \|b\| / g` and `\|y\| <= \|a\| / g` (the Euclidean cofactors; half-GCD and Lehmer matrices reproduce the same quotient sequence). |
| `lcm(a, b)` | Nonnegative; 0 when either is 0. |
| `inv(a, mod)` | `mod != 0`; the inverse of `a` modulo `\|mod\|` in `[0, \|mod\|)`, `-1` when `gcd(a, mod) != 1`, `0` for `\|mod\| == 1`. |
| `pow(a, e)` | `e >= 0` (asserted), square-and-multiply with the squaring backends. |
| `powMod(a, e, mod)` | `mod != 0`; `a^e` modulo `\|mod\|` in `[0, \|mod\|)`; `e < 0` uses `inv` and returns `-1` when `a` is not a unit; `\|mod\| == 1` gives 0. Sliding windows of a cost-chosen width (1 to 8 bits); one-word moduli use native 128-bit products, odd multiword moduli Montgomery REDC with a word inverse, even moduli reduction by a reciprocal cached above `NEWTON_DIV` words. |
| `sqrt(a)`, `isqrtRem(a)` | `a >= 0` (asserted; `sqrt(inf) = inf`). Floor root and `a - root^2` by Zimmermann's recursive square root with remainder (the Karatsuba-square-root backend) on words after an even normalising shift; `sqrt` stays beside the pair because it accepts the sentinel. |
| `kthRootRem(a, k)` | `k >= 1`; `a < 0` only for odd `k` (asserted). Truncated root toward zero and `a - root^k` by integer Newton iteration from a floating-point estimate of the root with a 2^-20 relative margin (so the number of iterations is logarithmic in the bit length for every `k`), finished by an exact `(root + 1)^k` check. |
| `isPerfectSquare(a)` | False for negatives, true for 0; residue filters modulo 64, 63, 65 and 11 before the root. |
| `isPerfectPower(a)` | True for 0, ±1 and every `x^k` with `k >= 2` (odd `k` only for negatives). Even values are tested only at the exponents dividing the power of two; odd values filter each prime exponent `p` through up to two primes `q ≡ 1 (mod p)` below 2^31 (`a^((q-1)/p) mod q`) before a root. |
| `jacobi(a, m)` | `m` odd positive (asserted); the binary Jacobi algorithm (native for one-word `m`). `kronecker(a, m)` extends it to every finite `m` (`m = 0` gives 1 iff `\|a\| = 1`; even and negative `m` by the standard rules). |
| `isProbablePrime(a)` | False below 2. Deterministic Miller–Rabin (seven bases) below 2^64. Above: trial division by the primes below 140 (three word products and `gcd`), perfect-square rejection, a strong base-2 Miller–Rabin test and a strong Lucas test with Selfridge's parameters (D = 5, -7, 9, ...; P = 1, Q = (1 - D) / 4), i.e. Baillie–PSW. Monte Carlo: composites could pass only if a BPSW pseudoprime exists; none is known. |
| `sample(bound, rng)` | `bound > 0` finite (asserted); uniform on `[0, bound)` by rejection on `bitLength(bound)` random bits (expected under two draws). `rng` is `std::mt19937`, `std::mt19937_64` or another generator with `min() == 0` and `max()` equal to 2^32 - 1 or 2^64 - 1 (checked at compile time); 32-bit generators are combined in pairs. Results are reproducible from the caller's seed. |
| `sampleBits(bits, rng)` | `bits <= 0` gives 0, else a uniform value with exactly `bits` bits (top bit set). |

### Bits and shifts

Mixed operands: `gcd(a, 18)` and `lcm(a, 18)` do not compile because `std::gcd` is the better match under `using namespace std`; write `gcd(a, InfInt(18))`.

Two's-complement semantics on finite values: `&`, `|`, `^`, `~` (`~a = -a - 1`), `testBit`, `setBit`, `clearBit`, `flipBit`, `scan0(a, i)` / `scan1(a, i)` (index of the first clear / set bit at or after `i >= 0`, or `-1` when none exists: no set bit above a nonnegative value, no clear bit above a negative one), `>>` and `>>=` (floor division by 2^s, so `-1 >> k == -1`), `<<` and `<<=` (exact products; shift counts `>= 0` asserted). Magnitude semantics: `ctz` (0 for zero), `popcount` (of `|a|`), `bitLength` (of `|a|`, 0 for zero). `setBit`/`clearBit`/`flipBit` mutate in place and return the object; on nonnegative values they are O(1) amortised, on negatives O(n).

### UInt<N>

`UInt<N>` holds `array<ulng, N> w` little-endian with wraparound modulo 2^(64 N) in every operation: constructors from any integral type (negative values and signed 128-bit types sign-extend), from `InfInt` (two's-complement image of a finite value), from `UInt<M>` for any `M` (explicit; widening zero-extends, narrowing keeps the low `N` words, i.e. the value modulo 2^(64 N)) and from a string (`UInt(string_view, base)`, which parses as `InfInt` does and asserts validity); `+ - * / % & | ^ ~`, unary `-`, `<< >>` (counts in `[0, 64 N)` asserted, bits leave at the ends; other counts give 0 under `NDEBUG`), the compound forms, `divMod` (divisor nonzero, asserted), `divWord(d)` (in-place quotient by a nonzero word, returns the remainder), `mulHigh` (the high `N` words of the `2N`-word product), `<=>`, `==`, `bitLength`, `ctz`, `popcount`, `toString(base, lower)`, `explicit ulng` (low word), `explicit bool`, `<<` and `>>` on a stream (`>>` reads one token as `InfInt` does and stores its two's-complement image, so a negative token wraps; the `inf` token sets `failbit` and keeps the value), `std::hash`, `std::formatter<UInt<N>>` (the `InfInt` spec). Products are schoolbook (`truncatedMul` for the low half, `mulBasecase` for `mulHigh`), division is the shared word division on stack arrays.

### infint_detail kernels

All kernels take little-endian base-2^64 words and sizes in words; results never alias inputs unless stated. Multiplication: `mulBasecase` (schoolbook), `squareBasecase`, `karatsuba(r, a, n, b, m)` for `n >= m > n / 2`, `karatsubaSquare`, `toom3`/`toom3Square` (equal lengths `>= 6`, Bodrato evaluation at 0, 1, -1, 2, ∞ with exact division by 3), `unbalancedMul(r, a, n, b, m, c)` (chunks of `c` words of `a` times `b`, each through the dispatcher), `truncatedMul` (`a b mod B^n`), `middleProduct(r, a, na, b, nb, lo, cnt)` (`r` = words `[lo, lo + cnt)` of `a b` summed over the terms with `i + j >= lo` only, so the exact words exceed `r` by less than `min(na, nb) B` at word `lo`; a direct sum below `MIDDLE`, else a cyclic `fftRun` plan of at least `max(lo + cnt, na + nb - lo, na, nb)` words (never shorter than an input, so no input folds), whose window exceeds the exact words by the carry of the folded high part, 0 or 1, so `subWord(r, cnt, 1)` leaves `exact - r` in {0, 1} (the `nttCyclic` limbs with the same window when no plan fits); `reciprocal` uses it with two guard words for the residual `B^(m + h) - b xh`), `fftPlan(n, m, want, cyclic)` (the plan of an n-word by m-word product: the smallest FFT length `r 2^lg` complex points, r in {1, 3, 5} in order of size, `lg` in [3, 24] (cyclic plans from 5), and the widest piece width k in [8, 20] whose bound holds (Exactness); `len = n + m` words, or for a cyclic plan `len = k · 2 r 2^lg / 64 >= want` words with the precondition `want >= max(n, m)`; `lg = 0` when no plan fits), `fftRun(r, p, a, n, b, m, cyclic)` (the exact product into `n + m` words or, cyclic, `p.len` words holding a representative in `[0, B^len)` of `a b mod (B^len - 1)`, the all-ones value standing for 0; `b == a` with `n == m` transforms once; `fftSplit` into balanced pieces, the radix-r column stage and the chunk transforms of `Fft`, `dot`, the inverse and `fftMerge` with the scale `1 / (8 r 2^lg)`; AVX2-FMA kernels under `__AVX2__ && __FMA__` in `Fft`, `__AVX2__` in the split, and scalar twins returning the same integers), `transformMul` (an FFT plan whenever one exists, else `nttCyclic`), `nttCyclic` (the limb convolution through `ntt3Cyclic` (primes 2013265921, 1811939329, 469762049 in Montgomery form, block roots `g^((P - 1) bitrev_B(b) / 2B)`, depth-first radix-4 above 2^12-limb leaves, 8-lane AVX2 kernels under `__AVX2__`, fused split and Montgomery CRT, length at most 2^26 limbs, coefficients below 2^89) or `ntt64Cyclic` (2^64 - 2^32 + 1 on 16-bit pieces, scalar) for the lengths above 2^26 limbs up to `NTT_MAX_WORDS = 2^28` words). `mul`/`square` dispatch by the thresholds `KARATSUBA`, `KARATSUBA_SQR`, `TOOM3`, `TOOM3_SQR`, `FFT`, `FFT_SQR`; from `FFT` words `mul` scores the whole transform (kept with a 10% edge for the chunked variants' extra passes) against cutting `a` into chunks of `s - m` words for every power of two `s > m` below the padded length (a chunk shorter than `FFT` words re-enters the dispatcher through `mulAny` and takes Karatsuba or Toom-3), each chunk costing `transformWork` (the smallest `r 2^lg >= len`, r in {1, 3, 5}, times the log of the length) with the last chunk at its own length, and runs the cheapest through `unbalancedMul`; below `FFT` an `n >= 2 m` product uses `m`-word chunks. Division: `invWord`/`div2by1` (Möller–Granlund), `divWord`, `divBasecase` (Knuth D on a normalised divisor of `>= 2` words), `div2n1n`/`div3n2n`/`divBurnikelZiegler` (block recursion padded to `bs 2^k` words), `reciprocal` (exact `floor(B^(2m) / b)` by recursive Newton on the top half, the residual through the guarded middle product, and a final correction), `divNewton` (block division by a cached reciprocal), `divRem` (normalises, then Newton when a reciprocal is passed or, from `NEWTON_LONG` divisor words, when the quotient has at least four times the divisor's words; Knuth D below `BURNIKEL` words or quotients, Burnikel–Ziegler otherwise; a null `q` or `r` is written into the frame), `invMod64`, `divExactHensel` (word-by-word 2-adic division, quadratic). GCD: `gcdBinary`. Caches: the NTT root tables, the FFT root tables (one `HugeVec` pair per chunk table: the main one and the chunks of radix 3 and 5, plus a 128 KB static double-double cache of the 2^12-th roots), the FFT's packed buffers `bx`/`by` and the NTT scratch are `HugeVec` tables (function-local statics in huge-page memory), the radix powers/reciprocals (`InfInt::radix`) ordinary statics; all grow to the largest size used and live for the process and hold no per-value state, so nothing invalidates them, and the transforms are not reentrant (Limits). The cyclic limb kernels (`nttCyclic`, `ntt3Cyclic`, `ntt64Cyclic`) write into caller-provided `lo`/`hi` words (`cyclicLimbs(len, n, m)` words each); every other temporary is a `Scratch` frame of the arena (Representation). `add`/`sub` are the carry chains unrolled by four on `__builtin_addcll`/`__builtin_subcll` (Benchmarks, kernels), `remWord` the remainder-only word division. `schonhageStrassen(r, a, n, b, m)` (n >= m >= 1, n + m <= 2^30, r of n + m words, which may alias a or b: the inputs are split before r is cleared) is the Fermat-ring product: K = 2^k pieces of p words with k = (bit_width(n + m) + 1) / 2 and p = (n + m) / K + 1, convolved over Z/(2^N + 1) with N = 64 L, L = roundUp(2p + 1, max(1, K / 128)) words, so that 2^(2N / K) is a principal K-th root (K | 2N), every coefficient is below K 2^(128 p) <= 2^N and ceil(n / p) + ceil(m / p) - 1 <= K pieces never wrap; `Fermat` holds the ring (elements of L + 1 words valued in [0, 2^N]: `add`, `sub`, `neg`, `shift` by 2^s for s < 2N with the overflow negated, `reduce` of a product, and the radix-2 `transform`, decimation in frequency forward and in time back with the 1 / K = 2^(2N - k) scaling), the pointwise products go through `mulAny` and the coefficients are added at word offsets j p. It is not dispatched (Limits).

### Exactness

The double FFT is exact by a proved bound: `fftPlan` admits a plan only when the worst-case rounding error of every merged coefficient stays below 0.49, so the product never depends on a test. Notation: u = 2^-53, |·| the complex modulus, ‖·‖ the 2-norm of a vector of complex values, ‖·‖_1 its 1-norm, M = r 2^lg complex points, N = 2M real pieces.

- **Pieces and coefficients.** `fftSplit` writes each operand as Σ x_j 2^(kj) with balanced pieces |x_j| <= 2^(k-1) (kernels above), nx = ceil(64 n / k) + 1 of them for n words. The product's piece coefficients c_j = Σ x_i y_(j-i) (indices mod N in a cyclic plan) are integers with at most min(nx, ny) terms, so |c_j| <= min(nx, ny) 2^(2k-2), ‖x‖ <= sqrt(nx) 2^(k-1) and ‖y‖ <= sqrt(ny) 2^(k-1); digits alternating 2^(k-1) and 2^(k-1) - 1 make every piece ±2^(k-1) and attain all three (the tester's worst-case operands). `fftMerge` rounds each computed coefficient to the nearest integer (`+ 0x1.8p52` after the scale; exact rounding below 2^51, implied by the bound since 0.49 / Φ < 2^46.3 over the whole table), so the product is exact when |ĉ_j - c_j| < 1/2 for every j.
- **Rounding model.** Round to nearest: fl(a ∘ b) = (a ∘ b)(1 + δ), |δ| <= u, for +, - and ×; no overflow (magnitudes stay below 2^70: the unscaled inverse outputs reach about 2^66 at the judge plans); a subnormal intermediate can only come from a near-cancellation and carries an absolute error below 2^-1074, absorbed by the slack 0.49 < 0.5. A complex product in the four-multiplication form, with FMA or with GCC's contraction of either satisfies |fl(a b) - a b| <= ρ |a| |b|, ρ = (1 + sqrt 2) u (1 + u): per component the error is at most u (1 + u)(|a_r b_r| + |a_i b_i|) + u |Re(a b)| (two rounded products or one exact one, then a rounded sum), the vector of the first terms has norm at most sqrt 2 |a| |b| (Cauchy–Schwarz, 4 |a_r a_i b_r b_i| <= |a|^2 |b|^2) and the second has norm u |a| |b|. A stored root is ŵ = w (1 + η) with |η| <= μ = 1.02 u, so a multiplication by a stored root has error at most τ |x| with τ = μ + ρ + μ ρ = 3.43 u (`FFT_TAU`, written in that form because (1 + μ)(1 + ρ) - 1 double-rounds), and a butterfly (a + ŵ b, a - ŵ b) then adds one u to each output; multiplications by 1 and i are exact.
- **Stored roots.** The tables hold T_q[B + b] = exp(iπ (q + r bitrev_B(b)) / (r B)) (main table q = 0); `Fft::level` forms each entry as the product of a coarse root (static double-double cache of the 2^12-th roots, `coarse`) and a fine root (double-double from `long double` trig over a sqrt-size table per level) in double-double arithmetic and rounds once to double in the AVX2 build, or multiplies in `long double` in the scalar build, so the error is the final rounding of each component (at most u / 2 for a component in [1/2, 1), u / sqrt 2 = 0.7071 u for the entry) plus about 2^-10 u from the double-double product and the `long double` trig (assumed within one 64-bit ulp). Measured 2026-10-26 against `long double` trig over every entry of the judge-size tables (main table 2^20 entries, the radix-3 chunk tables 2^19 each, the radix-5 tables 2^18 each): maximum 0.7068 u in both builds; μ = 1.02 u is the budget the bound uses. The two builds' tables differ in the last bit of some entries and the kernels' floating intermediates differ (FMA), but both stay within the bound, so the merged integers are identical.
- **Forward transform.** Every radix-2 level of `transform` is a scaled isometry (it multiplies ‖·‖ by sqrt 2), so a level with stored roots multiplies the accumulated relative 2-norm error factor by (1 + τ)(1 + u) and a level with exact roots (the first two levels of the main table: 1 and i) by (1 + u). The real-packed unpack fused into `one`/`pairs` (E = Z_p + conj Z_q, O = -i (Z_p - conj Z_q), X_p = E + ŵ O, X_(N-p) = E - ŵ O; positions 0 and 1 are their own partners) scales the norm of a pair by exactly 2 and of a self position by 1, so in the norm weighted 2 on pairs and 1 on self positions, in which ‖X‖ = sqrt N ‖x‖ (Parseval), it costs (1 + u)^2 (1 + τ): two additions and one stored root. The radix-r column stage (`col3`, `col5`: the sums and differences of the chunk values, the constants ±sqrt 3 / 2 and the cosines and sines of 2π/5 and 4π/5 stored to within u) is a scaled isometry too (‖·‖ times sqrt r); composing the per-operation u along every output's data path and bounding the result in the column's 2-norm with exact rational arithmetic gives relative errors 6.83 u (r = 3) and 15.4 u (r = 5), rounded up to ε_3 = 7 u and ε_5 = 16 u (`FFT_EPS`; ε_1 = 0). A main-table chunk has lg levels, two exact; a chunk q ≠ 0 of a mixed-radix plan uses its child table at every level, so with t = lg - 1 (r = 1) or lg + 1 (r > 1) stored-root multiplications including the unpack's, the forward factor is F = (1 + u)^(lg + 2) (1 + τ)^t (1 + ε_r): ‖X̂ - X‖ <= (F - 1) ‖X‖ in the weighted norm, and the same for Y.
- **Pointwise products.** Ĉ_j = fl(X̂_j Ŷ_j) with |Ĉ_j - X_j Y_j| <= |X̂_j Ŷ_j - X_j Y_j| + ρ |X̂_j| |Ŷ_j|; summing over the held half-spectrum with Cauchy–Schwarz and ‖X̂‖ <= F ‖X‖ gives ‖Ĉ - C‖_1 <= (F^2 (1 + ρ) - 1) ‖X‖ ‖Y‖ / 2 = (F^2 (1 + ρ) - 1) N ‖x‖ ‖y‖ / 2 (the weighted norm counts each held pair twice, as the full spectrum does). The exact inverse of the full spectrum is c_j = (1/N) Σ_k C_k ω^(-jk) with each held value appearing twice, so the exact inverse of the pointwise error moves every coefficient by at most 2 ‖Ĉ - C‖_1 / N = (F^2 (1 + ρ) - 1) ‖x‖ ‖y‖ (the pointwise term).
- **Inverse transform.** Its own rounding is bounded by fan-in in the 1-norm. The repack fused into `one`/`pairs` (E' = Ĉ_p + Ĉ_m, D = (Ĉ_p - Ĉ_m) conj ŵ, Z'_p = E' + i D and its partner from conj E' and D) produces values of 1-norm at most 8 ‖Ĉ‖_1 (|1 + i conj ŵ| + |1 - i conj ŵ| <= 2 sqrt 2 per output, two outputs per pair); every output of the inverse `transform` (and of the inverse column stage) is a sum of unimodular multiples of these values, so the computed output differs from the exact one by at most (Σ) times the 1-norm, where Σ = (1 + u)^(lg + 3) (1 + τ)^t (1 + ε_r) - 1 is the product of the per-operation factors along the longest data path: lg butterfly levels, the repack's two additions and one more u because a product reaches each repacked value along two paths (through E' and through D) whose errors add, t stored-root multiplications including the repack's, and the inverse column stage; the product form keeps the second-order terms exact. `fftMerge` scales by 1 / (8 r 2^lg) = 1 / (4 N), so the inverse term is Σ · 8 ‖Ĉ‖_1 / (4 N) = 2 Σ ‖Ĉ‖_1 / N <= 2 Σ F^2 (1 + ρ) ‖x‖ ‖y‖, using ‖Ĉ‖_1 <= F^2 (1 + ρ) ‖X‖ ‖Y‖ / 2.
- **Bound and planner.** |ĉ_j - c_j| <= Φ ‖x‖ ‖y‖ with Φ = F^2 (1 + ρ)(1 + 2 Σ)(1 + u)^2 - 1 when r > 1, because the scale 1 / (8 r 2^lg) and the product by it then round, and without the (1 + u)^2 factor when r = 1, where both are exact. `fftPhi(lg, r)` evaluates this at compile time with (1 + acc)(1 + t) - 1 steps (`FFT_PHI`; its own rounding is relative 2^-50 and sits in the slack); the tester's `phi` protocol cases hold every entry within 2^-46 relative of an exact-rational evaluation of this formula (`fractions.Fraction`); the values: Φ(1, 19) = 2^-44.61, Φ(1, 20) = 2^-44.53, Φ(3, 18) = 2^-44.45, Φ(5, 17) = 2^-44.38, Φ(1, 24) = 2^-44.27, Φ(3, 23) = 2^-44.14, Φ(5, 22) = 2^-44.09. `fftPlan` admits (lg, r, k) when sqrt(nx ny) 2^(2k-2) Φ(r, lg) <= 0.49, coded squared as nx ny 2^(4k-4) Φ^2 <= 0.2401, and nx + ny - 1 <= N (cyclic: k N >= 64 want), trying the sizes 2^lg, 5 2^(lg-2), 3 2^(lg-1) in increasing order and the widest k first; the first admitted plan is the smallest transform. Judge-size plans: 2^17 by 2^17 words (hex and decimal maxima) and 125,000 by 125,000 words take 5 2^17 points with k = 13 (bound 0.47 and 0.45), 100,000 words 2^19 with k = 13, 4096 words 5 2^12 with k = 15, 64 words 2^8 with k = 19, 1,048,576 words 3 2^21 with k = 11. The tester's worst-case operands exercise every (r, lg) in reach with both leaf parities; the bound, not those runs, is the exactness evidence for the untested sizes (Limits).

## Limits and handoffs

- Products need `n + m <= 2^28` words (`NTT_MAX_WORDS`) through the transforms, so that the Goldilocks NTT's piece count 2^30 fits an `int` (longer products fall back to Toom-3 and Karatsuba on top of them). `fftPlan` searches `lg <= FFT_MAX_LOG = 24`, so the largest FFT is 3·2^23 complex points: balanced operands get a plan up to 3,932,159 words each (k = 10, 7,864,318 product words), a one-word multiplier up to 11,796,478 words (k = 15); beyond, `nttCyclic` takes over (three-prime NTT up to 2^26 limbs, Goldilocks NTT above). The largest plan's static memory is 1.6 GB (root tables 768 MB: the main table of 2^24 complex entries and the two radix-3 chunk tables; packed buffers `bx`/`by` 805 MB), 1.0 GB for 2^24 points and 1.3 GB for 5·2^22, kept for the process (the 2026-10-25 decision to record, not guard, the table memory stands). The plans above the tester's reach (every (lg, r) class to lg = 18, up to 5·2^18 points, in full mode) were checked for existence and bound only (probe 2026-10-26: Φ(3, 23) = 2^-44.14, Φ(1, 24) = 2^-44.27, Φ(5, 22) = 2^-44.09); their exactness rests on the Exactness argument, not on a run.
- `schonhageStrassen` is implemented and tested but not dispatched: at 2^14–2^20 words it measured 3.2–10.5x the three-prime NTT and 1.6–4.4x Toom-3 over the transforms in the AVX2 build, 1.6–3.4x and 0.8–1.5x in the scalar build (Benchmarks), so above `NTT_MAX_WORDS`, where no whole transform applies, Toom-3 and Karatsuba over the transforms stay (user decision 2026-10-25: the backend is kept for completeness, not dispatched). The extrapolation there is not one-sided: the sub-products beyond 2^26 limbs run on the Goldilocks NTT, 5.0x the three-prime cost in the AVX2 build and 1.3x in the scalar build (Cyclic transforms table), so one Toom-3 level costs about 16 three-prime-equivalent transforms in the AVX2 build against the 9–10 measured for Schönhage–Strassen, whose pointwise products stay on the three-prime NTT; a 2 GB-operand measurement would be needed to decide it (user decision 2026-10-25, asked with this extrapolation: Toom-3 stays).
- `isPerfectPower` costs O(pi(b) * n) word operations plus the roots that survive the residue filter: fine to a few hundred thousand bits, slow beyond; `jacobi` and `kronecker` are quadratic; `kthRootRem` is Newton with full-precision divisions (O(M(n) log(b) log(k)) after the floating start), so the cube root of 16,384 words takes about 0.3 s; `isqrtRem` is O(M(n)).
- `isProbablePrime` is Monte Carlo above 2^64 (BPSW, no counterexample known); callers needing a proof use Mathematics' primality rows.
- `divExact` above `HENSEL` quotient words uses the (measured faster) quotient-only Burnikel–Ziegler division; a Newton–Hensel lifting variant measured 1.3–2x slower than it at every size above 48 words and was removed, so `divExactHensel` is the quadratic word-by-word backend.
- `truncatedMul` above 32 words is the full product truncated (no low-half Karatsuba); the measured gain of the basecase below 32 words is 1.5–2x.
- The transform cyclic kernels use process-wide `HugeVec` scratch and root tables, so a call is not reentrant; the arena is thread-local and never shrinks below its largest frame set (one spare block stays mapped so that a repeated peak reuses its pages) until thread exit; single-threaded contest execution is the baseline. `MADV_HUGEPAGE` is advice: with transparent huge pages set to `never` the arena still works, with more page faults on the first use of each block.
- The middle product takes the cyclic transform from `MIDDLE` words (AVX2 64, scalar 160): at the Newton shapes the full product's window never won against it (Benchmarks: middle product, 2026-10-26), so that branch is gone and the direct O(na nb) sum serves below `MIDDLE` (user decision 2026-10-31: it stays removed); `divNewton` and the Hensel quotient use full products.
- Unbalanced products with `m < FFT` and `n >= 4 m` take `m`-word chunks although a whole transform measured 1.45x and 1.55x faster at AVX2 256 × 64 and 1024 × 64 and 1.21x at scalar 1024 × 512 (Benchmarks, unbalanced table, 2026-10-31 run; 1.4–2x and 1.33x in the 2026-10-26 run, whose chunk additions were quadratic); a per-`m` gate needs a measured crossover grid, which stage 3, whose Newton blocks have these shapes, measures and adds (user decision 2026-10-31).
- `ntt64Cyclic` is scalar: the dispatcher reaches it only above 2^26 limbs, beyond any judge workload; stage 3 adds an AVX2 kernel for completeness (user decision 2026-10-31).
- The Python driver streams the protocol corpus, so its memory stays small; the recorded scope peaks (2.4–3.0 GB in stage 1, up to 3.6 GB before it) come from the ASan/UBSan builds of the self-test, whose quarantine and shadow memory multiply the 1.9 million checks' allocations; the optimized self-test stays below 30 MB.
- `operator>>` costs the library's string extraction (about 0.55 ns per character here, Benchmarks: text) on top of `read`; a solution that needs faster input reads the whole input itself (the fastio handoff below) and calls `read`. `<<` honours width and fill only; `std::formatter` takes a literal width (no nested `{}` width, precision or `L`).
- `std::hash` is not cryptographic and not stable across library versions (its values changed with the word layout).
- Bit counts are `int`: `bitLength`, `popcount` and `ctz` (asserted below 2^25 words), `charsBound`, the power-of-two `toChars`, `toDouble` and `kthRootRem` overflow above 2^31 bits, although the word kernels admit products to `NTT_MAX_WORDS = 2^28` words; a value of 2^25 words or more is a kernel-level object, not an `InfInt` (review 2026-10-26).
- Stage 1 left the AVX2 build's Knuth D and Hensel kernels 1.06–1.21x slower than the committed header (identical source; GCC's spill of the 128-bit product in `subMul`'s carry chain, Benchmarks); stage 3 replaces the division backends and inherits this item.
- Python 3.10 execution of the driver was not run (3.10 grammar only); the six Library Checker sources under `97-Online Testing/src/01-Yosupo/02-Big Integers` compile unchanged.
