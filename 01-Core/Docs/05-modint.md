# 05-modint.hpp — evidence

P005/C03 owns `05-modint.hpp`, which declares the six full public types and their shared `modint_detail` implementation in one header. P005/C16 separately owns the four independently copyable structs in `06-modintmini.hpp`; see [06-modintmini.md](06-modintmini.md). C01 and C02 are the verified prerequisites.

## Contracts

### ModInt, ModInt64, DynModInt, DynModInt64, MontModInt64, DynMontModInt64, ModInt61, mint

| Type | Modulus | Stored word `n` |
|---|---|---|
| `ModInt<MOD>` | Compile-time `uint`, `1 <= MOD < 2^32` | The canonical residue in a `uint`; `mint` is `ModInt<998244353>` |
| `ModInt64<MOD>` | Compile-time `ulng`, `1 <= MOD < 2^64` | The canonical residue in a `ulng`; `ModInt61` is `ModInt64<2^61-1>` |
| `DynModInt<ID>` | Run-time `uint`, the same range, one context per `ID` | The canonical residue |
| `DynModInt64<ID>` | Run-time `ulng`, the same range, one context per `ID`, independent of the 32-bit IDs | The canonical residue |
| `MontModInt64<MOD>` | Compile-time odd `ulng`, `1 <= MOD < 2^64` | The Montgomery form `x * 2^64 mod MOD`, in `[0, MOD)` |
| `DynMontModInt64<ID>` | The modulus of `DynModInt64<ID>`, which must be odd while a value of this type is in use | The Montgomery form |

Every type is one trivially copyable word of standard layout. All six share every operation of the table below with identical results; they differ only in which operations are cheap. Canonical storage (user decision 2026-11-20) makes `val()`, comparison, construction and streams free of a conversion. The Montgomery-form types are separate types for product-heavy code on an odd modulus from `2^32` other than `2^61-1`, the class on which they measured 0.48–0.68 of the canonical types' product rows (Benchmarks); below `2^32` and on `2^61-1` the canonical types are as fast or faster. On a form type `n` is not the residue: `val()` costs one Montgomery reduction, `raw(x)` and construction one product, and `==` compares the forms, which is the same relation.

A static zero modulus is rejected at compile time, an even modulus of `MontModInt64` too. Static types keep no run-time state except two words per type, `last` (pow, below) and `sqrtRun` (trySqrt, below); their tables are constants: the inverse table of a prime below 2048 (`MOD` words), the 2048 words of the inverses below 2048 of any other modulus that is not a power of two (8,192 bytes on a 32-bit word, 16,384 on a 64-bit one), the square-root tables of a prime `p ≡ 1 (mod 4)` (13,320 bytes for `mint`, 22,544 for Goldilocks, 38,928 for `ModInt64<29 * 2^57 + 1>`), and the header-wide `BCD4` (40,000 bytes, four decimal digits per entry, for `operator<<`), `INV_STEP` and `INV_RECIP` (256 and 128 bytes, for a dynamic modulus's inverses below 16), `WHEEL` (3,760 bytes), `FJ32` (512 bytes) and `P10`.

### Dynamic lifetime (setMod)

Dynamic types default to modulus 998244353: every context member is `constinit`, so the types work without an initialization guard from global initializers and from setup in another translation unit. `setMod(m, prm = -1)` requires `m != 0` and `prm` in `{-1, 0, 1}` (assertion); `DynMontModInt64<ID>::setMod` also requires an odd `m` (assertion). `prm = -1` detects primality, `prm = 0` clears the prime flag even for a prime, and `prm = 1` is the caller's promise of a prime, unchecked (user decision 2026-11-18: the promise costs O(1); under a false promise `trySqrt` and `sqrt` return meaningless values within their bounds, and the nonresidue search of the root table may scan up to the least odd prime factor). `isPrime()` computes the actual primality; `is_prime` reports the flag, a compile-time constant for static types.

Every `setMod` invalidates all earlier values of that context, references to their meaning and caller caches, even for an identical modulus. Discard or overwrite stale storage; never read a stale residue as a live value. No generation tags are stored, which keeps a value one word. Distinct IDs and widths do not invalidate each other, with one exception by design: `DynModInt64<ID>` and `DynMontModInt64<ID>` share one context, so `setMod` of either sets both, and `DynModInt64<ID>::setMod` with an even modulus leaves `DynMontModInt64<ID>` without a valid modulus (no assertion can see it there; using the form type then is a precondition violation with meaningless results inside the operations' bounds).

Context state per dynamic `ID` and width, all rebuilt by `setMod`, whose own arithmetic divides once on a 32-bit word (the reducer's reciprocal; a 64-bit word goes through the `Barrett64` and `Montgomery64` constructors of P004, which divide 128-bit values, and detection adds `isPrime`'s cost): `MOD`, `is_prime`, `reducer` (returned by `reduction()`), `montgomery` (the `Montgomery64` of `m | 1`), `reciprocal`, `BIAS`, and the words the kernels read, each alone in a one-member struct (`mod`, `small`, `quot`, `t64 = 2^64 mod m`, `t31 = 2^31 mod m`, `bias`, `mthr`) with the flags `sel`, `selc`, `mont`. `MOD` and `BIAS` mirror `mod` and `bias` for inspection. Shared context fields are inspection-only; use `setMod` to change them. State that `setMod` does not touch and that needs no invalidation because it is keyed by the modulus or steers only a choice between loops with equal results: `minv`, `minvOf` (the Newton inverse of an odd modulus, built by the first inverse under it), `cache` (the inverses below 2048 that were asked for, see tryInv below; 16,384 bytes on a 32-bit word, 32,768 on a 64-bit one), `last` and `rootLast` (the exponent of the previous `pow` and of the previous root power), and the square-root state `sqrtCache` (15,636 bytes on a 32-bit word, 39,456 on a 64-bit one) with the counter `sqrtRun`. There are no owned allocations. Single-threaded semantics apply: `last`, `rootLast` and the square-root state are written by `pow`, `trySqrt` and `sqrt` on every type, static ones included, and `cache` by `tryInv`, `inv` and `/` on dynamic types, so concurrent calls on one type are outside the contract.

### Value operations

| Feature | Contract |
|---|---|
| Construction and assignment | All built-in integral types, including signed and unsigned 128-bit and signed minima, normalize modulo `mod()`; the default is zero; `a = x` converts through the constructor. No path holds a division instruction or a 128-bit library call (Correctness and cost, division listing). Floating-point construction is excluded. |
| `val()`, `n`, `mod()` | The canonical unsigned representative, the stored word and the modulus. Public `n` may only be set to a word the type could hold: a canonical residue, or on a form type the form of one. |
| `raw(x)` | Requires a canonical `x < mod()` (assertion); does not reduce. On a form type it converts `x` into the form. |
| Integral conversion | Explicit conversion to an integer type that can hold `val()` (assertion). `bool` means nonzero, so `!a` tests for zero. |
| Arithmetic | Unary and binary `+ - * /`, compound forms, prefix and postfix `++ --`. Mixed integral operands normalize through the constructor. Division requires a unit denominator. |
| Comparison | `==` and `<=>` compare canonical representatives, not an order compatible with ring arithmetic. |
| `tryInv(a, out)` | True iff `gcd(a.val(), mod()) == 1`. On success writes the inverse; on failure leaves `out` unchanged. Input and output may alias. |
| `inv(a)` and `/` | Unit precondition (assertion). Composite moduli are supported; nothing assumes Fermat's theorem. |
| `pow(a, e)` | Every native signed or unsigned exponent width through 128 bits. A negative exponent requires a unit, the signed minimum included. Exponent zero returns the multiplicative identity. The result never depends on earlier calls; the loop chosen at run time does (power, below). |
| `trySqrt(a, out)` | Requires the prime flag (assertion). True iff a square root exists; writes the smaller canonical root. False leaves `out` unchanged. Aliasing allowed. |
| `sqrt(a)` | The smaller canonical root, or the residue of `-1` without one. The sentinel cannot equal a valid result: for an odd prime the smaller root is at most `(p-1)/2`, and for `p = 2` every input has a root. |
| `batchInv(a, out)` | Length at most `INT_MAX` (assertion); succeeds iff every element is a unit, with one inverse and linearly many products. Empty input succeeds with empty output; failure leaves `out` unchanged; `a` and `out` may be the same vector. Allocates one work vector of the input's length. |
| `operator>>` | Streams, below. |
| `operator<<` | Streams, below. |

Modulus one is the zero ring: its single element is also the multiplicative identity and a unit. Its inverse and every power, exponent zero included, are zero. Prime-root operations are unavailable there. Integer division, remainder, bitwise operations and shifts on residues are deliberately not invented; composite-modulus roots, primitive roots, discrete logarithms and CRT belong to Mathematics.

### Streams

`is >> a` reads one token as `is >> std::string` delimits it (the stream's `skipws` flag, its `width()`, which bounds the token and is reset to zero, a flush of a tied stream, the locale's white space) and accepts an optional sign followed by one or more decimal digits of any length, reduced 18 digits per modular step. Reader rule (user decision 2026-11-21, "digits belong to the number"): a leading sign and every decimal digit belong to the token whatever the stream's locale classes them as, as `cin >> int` treats them; white space is the locale's. The digits are decimal whatever the stream's `basefield`. A token with any other character, a lone sign or no character sets `failbit`, leaves `a` unchanged and is consumed whole, to its delimiting white space; end of input sets `eofbit` as the string extractor does; a buffer that throws sets `badbit` and rethrows when the exception mask asks for it. The result, the stream state, the exceptions and the unread input are the same on every path.

Paths, chosen from the stream's state alone: when the stream is good, untied, skipping white space and without a width, and the whole token with its delimiter lies at least eight bytes before the end of the buffer's get area, the token is parsed in place in groups of eight digits and the get pointer advanced; a token whose delimiter lies in the last eight bytes of the area is finished in place by a partial group when the stream arrives on the general path; everything else (an unbuffered stream, a token across a refill, a width, `noskipws`) is read character by character through the buffer's own calls. The in-place paths reach the get area's protected pointers through member pointers of a derived class, and under libstdc++ (`__GLIBCXX__`) the character classification is the facet cached in the stream; other libraries look the facet up in the stream's locale (user decision 2026-11-18). After `ios_base::imbue` called on the base class, which changes the locale without that cache, the reader keeps the cached facet for the leading white space and for the token's end, as libstdc++'s sentry does for the white space it skips; libstdc++'s string extractor ends its token by the new locale, so the two differ there until the stream's own `imbue` (probe of 2026-11-22 on GCC 16: `12,34 56` under a locale that classes the comma as white space gives the string `12` and a failed read of `12,34`; Limits and handoffs).

`os << a` writes `val()` exactly as `os << val()` would in every stream state, with one stated difference: on the plain path (no width, decimal base) the digits are written without consulting the locale, so a locale that groups digits is not applied; under a width or a non-decimal base the stream formats the value itself, grouping included (user decision 2026-11-17). When the stream is good, untied, without `unitbuf` and its put area holds at least 20 free bytes, the digits are written straight into the area and the put pointer advanced; no byte behind them is touched. Otherwise they go through the buffer's `sputn` (a buffer that overrides `xsputn` receives the digits in one call on this path and none on the in-area path: the bytes are the same).

### ModularInt, StaticModularInt

Public concepts for generic Poly and Matrix dispatch: `ModularInt<T>` accepts any full or mini residue type (`Word`, `mod()`, `val()`, `n`), the form types included; `StaticModularInt<T>` additionally requires a constant `mod()`. Generic code that reads `n` as the residue is valid on a form type only where the computation is linear in the stored word.

### Context (MOD, is_prime, isPrime, red, mul, canon, montgomery, reciprocal, BIAS, setMod, reduction)

`Value::operator*=` calls `Context::mul(a, b)`, the product of two canonical words; `Context::red(x)` reduces any double-width dividend. `canon(y)` exists on static contexts: the residue of `y < 2 * MOD` without a branch. `montgomery` is the `Montgomery64` of `MOD | 1` and `reciprocal` the `modint_detail::Reciprocal` of `MOD`, both on every context (constants on static ones); `BIAS = biasOf(MOD)` is the multiple of `MOD` in `[2^63, 2^63 + MOD)`, `MOD` itself from `2^63`, which makes a negative 64-bit source an unsigned dividend. The product by class:

| Context | `mul(a, b)` |
|---|---|
| Static power of two | `a * b & (MOD - 1)` |
| Static `2^61-1` | one 64×64 product, `Barrett64::fold61`, `canon` |
| Static `MOD < 2^31`, not a power of two, whose round-up reciprocal for 64-bit dividends needs 65 bits (7, 469762049, 167772161, `2^31-1`; `EXACT`) | the round-up reciprocal at `2^(64 + PS)`, which is exact on products of residues (they are below `MOD^2`): one multiply-high, one multiply-subtract |
| Other static 32-bit words; static 64-bit words below `2^32` | the 64-bit product `% MOD`, GCC's constant-divisor sequence |
| Static Goldilocks `2^64 - 2^32 + 1` | its own fold (`2^64 ≡ 2^32 - 1`, `2^96 ≡ -1`) |
| Static `MOD = 2^k - c` from `2^32` with `c < 2^32` and `(c + 1)^2 <= MOD` (any such `c` when `k = 64`; `FOLD`) | two folds by `c` and one `min` |
| Every other static 64-bit modulus | `reciprocal.mul(a, b)`: Möller–Granlund division of the product by the modulus normalized to its top bit, in C++ products that GCC folds and hoists for a constant divisor |
| Dynamic 32-bit word | the context's one-word reciprocal `small = floor((2^64 - 1) / m)`: `r = x - hi(x * small) * m`, at most one `m` too large; the correction is a predicted jump, or a select under `sel` (set by `setMod` when `(2^64 mod m) * m >= 2^62`, where a sixteenth of random products and more need it) |
| Dynamic 64-bit word, by the class `setMod` stores in `small`: below `2^32`; power of two; `2^61-1`; other | one-word reciprocal with a `min`; a mask (behind an empty assembly barrier that keeps GCC from compiling the sums after it as jumps); the static Mersenne fold; `reciprocal.mul` with both products by `mulq` on x86-64, whose halves stay in registers (the C++ products elsewhere and in constant evaluation) |
| Montgomery-form types (`MontContext::mul`) | `mmul`: the Montgomery product without a branch, for `a * b < m * 2^64`, so one factor may be any word |

A product with a compile-time operand tells GCC that its result is below `MOD` (`Context::below`), as GCC's own remainder would, so sums after it fold. `MontContext` adds `cube()` (`2^192 mod m`) and `one()` (the form of one). `Reciprocal` holds `sh = countl_zero(m)`, `d = m << sh` and `v = floor((2^128 - 1) / d) - 2^64`; `mul(a, b)` needs `a < m`, accepts any word `b` and returns `a * b % m`; `rem(r, lo)` is `(r * 2^64 + lo) % m` for `r < m`.

Construction reduces by class, never negating a signed value:

| Source and context | Path |
|---|---|
| Any source, static power of two | a mask |
| Form types | one product by `2^128 mod m` (any 64-bit factor is allowed), a signed source first biased under its sign mask; 128-bit sources by two products (`lo * 2^128 + hi * 2^192`) and a subtraction for a negative high half |
| At most 32 bits, static `MOD < 2^31` smaller than the type's range | the exact one-multiply remainder by `ceil(2^64 / MOD)`, a signed source first shifted by the least multiple of `MOD` from `2^31` |
| At most 32 bits, dynamic 32-bit word | the two-product remainder of Lemire, Kaser and Kurz on `small + 1`; a signed source as `rem32(a + 2^31) - (2^31 mod m)` with the borrow fixed, a source known non-negative at compile time without it |
| At most 32 bits, dynamic 64-bit word | modulus from `2^32`: `a + (m & sign)`, no reduction; a dynamic power of two: a mask; below `2^32`: the two-product remainder on `quot + 1` for unsigned sources, the biased one-word step for signed ones |
| Signed, the modulus at least `2^(bits - 1)` (static) | `a + (MOD & sign)` |
| 64 bits, dynamic | `rem64`: `u - hi(u * quot) * m` with one `min`, `quot = floor((2^64 - 1) / m)` (the quotient is at most one short); a signed source first adds `bias` under its sign mask; a 32-bit word takes its one-word reduction with a jump or, under `selc` (`2^64 mod m >= m / 8`), a select |
| 64 bits, static | unsigned: GCC's constant remainder; signed: `(a + (BIAS & sign)) % MOD`, the bias only below zero so that a loop hoists it, or the signed remainder with a mask for `MOD = 2^k - 1` with a long reciprocal |
| 128 bits | by halves, a negative value as the complement of a non-negative one (`~a = -a - 1`), mapped back as `(r ^ k) + (k & MOD)`: a dynamic 64-bit word by `rem64` of the high half when it is at least `m` and one reciprocal step; a dynamic 32-bit word as `(hi mod m) * t64 + lo` in two one-word reductions; a static 32-bit word by the out-of-line `Context::fold(hi, lo)`; a static 64-bit word by `red` |

### pow

`pow` starts from the identity. Under constant evaluation every type runs the binary loop on its own product. At run time the loop is chosen per context and exponent; `modint_detail::Direct<C>` names the contexts whose product is one short word step (32-bit words, static powers of two, static `2^61-1`, static 64-bit moduli below `2^32` with a one-word or exact reciprocal):

| Context | Exponent | Loop |
|---|---|---|
| `Direct` | below 4, at least `2^64`, or equal to the previous call's (`last`) | the binary loop inline, from the lowest set bit; a 32-bit word on 64-bit registers |
| `Direct` | in `[4, 2^64)` and changed since the previous call | `powBlind`, out of line, with no branch on the exponent's bits: the binary loop with its multiplier selected under a mask, or base-4 digits under a power of two |
| Form types | from 5 | `powMont` on the form: Montgomery products, lazy (values below `2 m`) for `m < 2^62`; the select loop when the exponent changed |
| Static odd modulus from `2^32`, not `2^61-1` | from 5, or from 9 for a modulus from `2^63` | `powMont` with conversion in and out |
| Static 64-bit word below `2^32` outside `Direct` | odd: from 96, or from 16 when changed | `powMont`; a changed exponent below that, and every changed exponent of an even such modulus, takes `powBlind` |
| Static even modulus from `2^32` | all | the binary loop on its product; a long-reciprocal modulus, odd or even, runs its binary loop on `reciprocal.mul` by `mulq` |
| Dynamic 64-bit word below `2^32` | from 4 | unchanged: `powSmall`, out of line, on the one-word product with a predicted jump; changed: `powBlind` on 64-bit registers |
| Dynamic 64-bit word, odd from `2^32`, not `2^61-1` | from 5 | `powMont`, the select loop when changed |
| Dynamic `2^61-1` | from 8 | changed: `powBlind`; else the binary loop on the Mersenne fold |
| Dynamic power of two | from 4 | changed: `powBlind` by digits; else the binary loop on the mask |
| Dynamic even modulus from `2^32` | all | the binary loop on `reciprocal.mul` |

`last` is one word per type; an exponent counts as changed when it lies in `[4, 2^64)` (from 8 on a dynamic `2^61-1`) and differs from the stored one, and only such exponents are stored. Alternating between two exponents is the pattern the heuristic cannot serve (Benchmarks, trade-offs). A branch-free loop pays only where the product is shorter than a misprediction's refill, which is why the reciprocal-product classes keep the branchy loop: its bit branches read only the exponent and resolve behind the 24-cycle product chain. Root powers of a dynamic context track their exponent in `rootLast`, apart from `last`. No hardware division runs in any power (user decision 2026-11-19). A negative exponent inverts the base first and takes its magnitude by unsigned negation, defined for the signed minimum.

### tryInv, inv, batchInv

| Case | Algorithm |
|---|---|
| Static prime below 2048 (canonical types) | a compile-time table of all inverses: O(1) |
| Power of two (static, or dynamic by `reducer.mask`) | an even operand has none; otherwise Newton's iteration from the five correct bits of `3 a ^ 2`, each step doubling them: as many steps as a static modulus's exponent needs (none up to `2^5`, one up to `2^10`, two up to `2^20`, three up to `2^40`, else four), three on a dynamic 32-bit word and four on a dynamic 64-bit one: O(1) |
| Odd modulus, operand at least 2048 | `invBinary<false>`: subtract-and-shift on two odd values with cofactors `p a = s u 2^k`, `q a = -s v 2^k (mod m)`, `p v + q u = m`; one division first when the modulus is 8 bits or more longer than the operand; the factor `2^-k` removed by one or two Montgomery reductions on `m^-1 mod 2^64` |
| Even modulus that is not a power of two, odd operand at least 2048 | `invBinary<true>`: the same loop with the roles swapped, `y = m^-1 mod a`, then `a^-1 = m - (m y - 1) / a`, the division exact and taken as a product by `a^-1 mod 2^64`. The loop starts from `m` itself; `m mod a` is taken first only when the operand is 8 bits or more shorter than the modulus |
| Operand 1 to 2047 (`INV_TABLE`), modulus not a power of two | a table of 2048 entries. Static: `InvTable`, the words built at compile time by Euclid, zero where there is no inverse: O(1). Dynamic: `cache`, a pair {modulus, word} per value and type, written by the first call for that unit under a modulus and read by every later one: O(1) from the second call. The first call takes the two loops above for an operand from 16 on; below 16 (`INV_TINY`) it takes the quotient of the modulus, in O(1) without a division: with `m = q a + e` and `t e = -1 (mod a)`, `a^-1 = t q + (t e + 1) / a`, where `INV_STEP[a][e]` holds `t` and `(t e + 1) / a` in one byte (255 where `gcd(a, e) > 1`: no inverse) and `q` is one product by `INV_RECIP[a] = floor((2^64 - 1) / a)` with one correction |
| Operand zero | no inverse, except under the modulus one |

`tryInv` and `inv` are inlined up to the loops: the table lookups, the test of the modulus and the lift sit at the call; `invBinary` and `invRest` (a dynamic modulus's first call for a value below 2048, the even-modulus dispatch, zero) stay out of line. `m^-1 mod 2^bits` comes from `inv64`, Newton's iteration with the error term squared beside each step (two independent products a step; 10, 20, 40 and 80 bits after one to four steps). `cache` belongs to the residue type, so `DynModInt64<ID>` and `DynMontModInt64<ID>`, which share one modulus, keep their own words. Each pair names its modulus, so `setMod` neither clears nor invalidates it, and a modulus set again finds its pairs still valid. A value without an inverse is never stored: below 16 it is refused in O(1), from 16 on every call runs its loop.

On x86-64 and outside constant evaluation the loop of `invBinary` is an inline-assembly loop of 17 instructions with identical results to the C++ loop below it, which serves constant evaluation and other architectures (user decision 2026-11-17 on guarded inline assembly). A form type inverts the canonical value and folds the form into the closing product.

`batchInv` keeps prefix products in 1, 2, 4 or 8 interleaved chains by length and product class (`BATCH_STATIC {9, 22, 80}`, `BATCH_EXACT {11, 14, 64}`, `BATCH_DYNAMIC {13, 13, 96}`, `BATCH_MONT {6, 16, 256}`: one chain below the first bound, two below the second, four below the third, eight from there), joins the chains before the one inversion and walks back. A 64-bit word with an odd modulus from `2^32` other than `2^61-1` runs its chains on Montgomery products, each chain carrying a power of `2^-64` that its inverse cancels. With `__AVX2__`, a 32-bit word with an odd modulus above one uses 8, 16 or 32 lanes of `Montgomery32` from lengths 48, 80 and 512, with results identical to the scalar chains.

### trySqrt, sqrt

`a < 2` and `p = 2` return `a`. For `p ≡ 3 (mod 4)` the root is `a^((p + 1) / 4)` followed by a square check; `sqrt` selects the sentinel by a mask there. Otherwise `p - 1 = q * 2^s` with `q` odd and `s >= 2`:

| Case | Algorithm |
|---|---|
| Static prime | one power `w = a^((q - 1) / 2)`, then the discrete logarithm of `a^q` in the 2-group by windows of 8 bits against compile-time tables: `8 (k - 1)` squarings for `k` windows, a table product per window, a hashed slot lookup (a multiplier that separates the 256 keys is searched at compile time and `static_assert`ed); a nonresidue shows in the first window |
| Dynamic, `s = 2` | Atkin: `b = (2 a)^((p - 5) / 8)`, `i = 2 a b^2`, the root `a b (i - 1)` iff `i^2 = -1` |
| Dynamic, the first 256 calls under a modulus | Cipolla when `s^2 > 15 * bits(p)` (`9 * bits(p)` on a 64-bit word), after a Jacobi test of `a` and with the nonresidue found by Jacobi symbols; else Tonelli–Shanks from one power, with the roots `z^(q 2^k)` of a nonresidue `z` (the first odd `z` whose symbol is `-1`) built once per modulus |
| Dynamic, from the 257th call under a modulus | the window tables, built once at run time; if no separating multiplier is found within 1,024 candidates the tables are never used and the earlier algorithm stays |
| Dynamic 64-bit word, modulus from `2^32`, after eight nonresidues in a row | the Jacobi symbol is tested first |

A static exponent whose top is a run of at least 16 ones is raised by a fixed chain (`rootFixed`). The table path is O(log(p)) products per root; the dynamic path before the tables is O(log(p) + s^2) for Tonelli–Shanks and O(log(p)) products for Cipolla after an expected two symbol tests. The order searches are bounded by `s`, so a modulus that violates the prime precondition under `NDEBUG` cannot loop there.

### modint_detail::isPrime

`isPrime(m, r = 0)` is exact for every `ulng`; `r` is `2^64 mod m` when the caller holds it (`setMod` does). `m mod 30030` indexes the `WHEEL` bit table, which settles every multiple of 2, 3, 5, 7, 11 and 13; fourteen constant-divisor tests settle the multiples of the primes 17 to 71, with no division instruction; `m < 73^2` is then prime. Below `2^32` one strong probable-prime test to a base from Forišek and Jančina's 256-entry hashed table decides, in a loop that selects instead of branching on the exponent's bits; the tester checks it against a sieve for every `n < 2^32` and pins the table by a digest. From `2^32` the test is Baillie–PSW: a strong test to base 2 and the extra strong Lucas test with `Q = 1` and the first `P >= 3` whose `(P^2 - 4 / m)` is `-1`, found from a mask of ten small Jacobi symbols; no composite below `2^64` passes, since every composite that passes the base-2 test is in Feitsma and Galway's list of the base-2 Fermat pseudoprimes below `2^64`, and the tester's `--pseudoprimes` mode runs the whole list through `isPrime` (Commands and results). Constant evaluation uses the seven-witness Miller–Rabin test on 128-bit remainders; the tester's table of cases passes through both paths.

### Correctness and cost

Addition compares `a` with `m - b` before adding. Subtraction adds `m` to the wrapped difference under the borrow mask on every context (user decision 2026-11-19). `++`, `--` and unary minus are written per context so that GCC's `-O2` vectorizer takes in-place loops over them and so that a zero or a wrap is a select, never a jump: zeros arrive unpredictably.

`Reciprocal::mul` is Möller and Granlund's division of a two-word dividend by a normalized word with a precomputed reciprocal (their Algorithm 4): `a < m` gives `x = (a << sh) * b < d * 2^64`; the quotient estimate `q = v * x1 + x` does not overflow two words; the candidate remainder `x0 - (q1 + 1) * d` is corrected by adding `d` when it exceeds `q0` and by `min(r, r - d)`; the result is `(a * b mod m) << sh`. The one-word reductions use `floor((2^64 - 1) / m)`: for `x < 2^64` the quotient estimate is at most one short, so `r < 2 m` and one correction suffices; for a power of two the 32-bit context stores `2^64 / m`, which is exact. The exact product of the `EXACT` class rests on Granlund and Montgomery's Theorem 4.2 with the dividend bound `MOD^2` in place of `2^64`. The fold class: with `x < M^2`, `M = 2^k - c`, the first fold leaves `y < 2^k (c + 1)` when `(c + 1)^2 <= M`, the second a value below `2 M`, and for `k = 64` the carry out of the word is one more `c`; the condition is evaluated in 128 bits (a 64-bit evaluation wrapped for `c = 2^32 - 1` and was the one arithmetic defect this run found in its own drafts, before any commit).

`mmul(x, y) = t - u + (t < u ? m : 0)` with `t = hi(x y)` and `u = hi(lo(x y) * m^-1 * m)` is `x y 2^-64 mod m` in `[0, m)` for `x y < m 2^64`; `mmulLazy` omits the correction for `m < 2^62`, where factors and results below `2 m` keep `x y < 4 m^2 < m 2^64`.

`invBinary` keeps `p b = s u 2^k`, `q b = -s v 2^k (mod w)` and `p v + q u = w` with `u`, `v` odd and `s = ±1`; each step replaces the larger of `u`, `v` by the odd part of their difference, so the loop ends at `u = v = gcd`, and `p, q <= w` bounds every word. At `u = 1` the cofactor `x` satisfies `x b = 2^k (mod w)` up to the tracked sign, and `x 2^-k mod w` is one Montgomery reduction by `2^(64 - k)`, two when `k > 64`. In the swapped form `b = m` may exceed `w = a`: the invariant holds from `p = 1`, `q = 0`, `v = w` whatever `u` is. Every shift of `z` bits shortens `u` or `v` by at least `z` bits, so `k` is at most the bits of `b` plus the bits of `w`: 64 on a 32-bit word, where one reduction always suffices, and 128 on a 64-bit one. Euclid runs only in constant evaluation, where it builds the static tables: it keeps remainders `r, s` and unsigned cofactor magnitudes with alternating signs, and the magnitudes grow monotonically to `m / gcd`, so every value fits the word for the full unsigned domain. The quotient form of a dynamic value `a < 16` under `m = q a + e`, `0 <= e < a`: with `t e = -1 (mod a)` the sum `t e + 1` is a multiple of `a`, and `a (t q + (t e + 1) / a) = t (m - e) + t e + 1 = t m + 1`, which is 1 modulo `m`; `t < a` bounds the result by `((a - 1) m + 1) / a < m`. Since `gcd(a, m) = gcd(a, e)`, `a` has an inverse exactly when `e` has one modulo `a` (for `a = 1`: `e = 0`, `t = 0`, the result 1). The quotient is `hi(m * floor((2^64 - 1) / a))`, which is `q` or `q - 1` because `m * floor((2^64 - 1) / a) / 2^64` lies in `(m / a - 1, m / a)`; the comparison `e >= a` corrects it. Failure never writes the output.

The square-root window tables hold `R^(v 2^e)` for the generator `R = z^q` of the 2-group; with `a^q = R^L`, the root is `a w R^(-L / 2)`, and `L` is recovered from the low window up, each window after `8 (k - 1 - j)` squarings and the product by the diagonal entries of the windows already known; an odd `L` is a nonresidue. Cipolla computes `(b + w)^((p + 1) / 2)` in `F_p[w] / (w^2 - d)` for a nonresidue `d = b^2 - a`.

Division listing (2026-11-22, `g++-15 -O2 -S` of a probe with one out-of-line function per operation on 21 types, 649 functions, this header): division instructions occur only in `invBinary` (the one skew division and the swapped form's `m mod a`), in `setMod` (one on a 32-bit word; three and one call each of `__udivti3` and `__umodti3` on a 64-bit word), in `sqrtRoots` and `sqrtBuild` (`p mod z` of the nonresidue search) and in `isPrime`'s strong test (`2^64 mod m` when the caller passes none and the modulus is at least `2^32`, and a hashed base at or above the modulus). No product, reduction, construction, power, table square root, read or write holds one, and neither does `invRest`: Euclid's loop runs only in constant evaluation, where it builds `InvTable`.

Cost: arithmetic and construction are O(1) word operations; `tryInv`, `isPrime` and a power are O(log) products or steps, a negative exponent adds one inversion; `batchInv` is O(k + log(m)) time and O(k) memory; stream input is O(d) for `d` characters and O(1) memory; output O(digits).

The raw logs of each round are local records under `.claude/finish/C03-proto/` (git-ignored). ### Dependent-owner handoff

Matrix (P020/C07, existing-unverified): its optimized modular kernels derive the modulus through an `int` cast, assume particular 32-bit ranges, and its field classification includes a compile-time use of `is_prime`. C03's wider domains and dynamic prime flags do not establish Matrix support for those domains. C07 must review full-width/64-bit modular matrices and dynamic field classification before advertising them; reconstruct matrices and cached factors after dynamic modulus changes. Start at `FastGaussian::getMod`, `Matrix::isField/is_field`, and the `is_mint32` accelerated paths: derive moduli through `T::mod()` with correct word widths, enforce each kernel's domain, and replace static field constraints with a runtime contract for dynamic types. Reproducer: `using D = DynModInt<>; static_assert(Matrix<D>::is_field);`. Generic Matrix/Poly code may constrain on `ModularInt`/`StaticModularInt`.

Catalog items for other owners, reported, not changed: double factorial and inverse binomial caches (`05-Mathematics/05-combinatorics.hpp`), fast-IO `rd`/`wt` overloads for residues (`01-Core/19-fastio.hpp`, not adopted there: [19-fastio.md](19-fastio.md#limits-and-handoffs)), `randgen` hash base on `ModInt61` (Strings `randomBase`).

Measured for P004 during this header's sweeps, reported in its plan note, not changed. On 2026-11-16 (GCC 16): `Barrett32::divMod`'s correction `over ? r - mod : r` compiles to a branch that mispredicts on dividends near `2^63`, GCC stops inlining `divMod` into a larger caller (an `.isra` call per multiply), and a branch-free multiplier select in `Montgomery64::powMont` measured 0.72–0.78 on random exponents and 0.96–1.01 on fixed ones.
