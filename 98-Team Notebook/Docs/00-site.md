# Documentation site — evidence (P239)

Scope: the documentation-site generator [06-site.py](../06-site.py) for Zensical or MkDocs Material, its pages, charts, link rewriting and article merge (P239, support batch SUP08; reasons: [decision log](../../00-Guidelines/10-decisions.md), Dependency graph and documentation site). Rules: [07-notebook.md](../../00-Guidelines/07-notebook.md).

## Contracts

- Location (user decision 2026-10-25): the generator lives in this folder and writes the git-ignored `site/` (`mkdocs.yml`, `docs/`, `html/`, and the engines' `.cache`). `generate` uses the standard library only. It builds every page first, then replaces `site/docs`, so no stale page survives.
- Engines (user decisions 2026-10-25): the generated `mkdocs.yml` serves both Zensical and MkDocs Material. `build` runs `<engine> build -f site/mkdocs.yml --strict`, and `serve` runs `<engine> serve -f site/mkdocs.yml --dev-addr 127.0.0.1:<port>`, generating once (restart it after edits). `--engine auto` (the default) takes the first usable engine: Zensical first, then MkDocs. An engine is usable when it is on PATH and the Python on its `#!` line imports what the site needs: `zensical`, or `material` and `pymdownx`. Arch's `mkdocs-material` package does not pull in `python-pymdown-extensions` (found 2026-10-25). With no usable engine, the command names each engine's problem and how to install it, and exits 1.
- Pages: one per inventory row (plan.py `inventories`) whose header or module exists, at `<folder, lowercase with hyphens>/<NN-stem>.md`, the evidence document's name. A page has an H1 with the file name. Its facts line gives folder, tier, Core's Basic flag, status, line count, last commit date (`git log %cs`; omitted outside git) and the GitHub source and evidence links. Then come the `#include` line (headers), the article and `## Operations`, one bullet per `;` outside parentheses and brackets (a half-open `[l, r)` counts as a bracket pair). `## Complexity` (user decision 2026-10-25) lists each declaration with its complexity comment: every `// T:` or `// S:` line of the header (`03-cpp.md`, Complexity comments). The declaration is the code after that line up to the first `{` or `;` outside parentheses; each is one code span whose delimiters outrun any backtick inside (`05-Mathematics/10-crt.hpp` has some). The evidence sections follow, copied verbatim with their titles: `## Contracts`, then `## Dependencies` (headers in the include graph), `## Limits and handoffs` and `## Sources`. `## Tests` lists the tracked files of plan.py `tests_for`. `## Source` puts the file in a collapsed `??? abstract` block, fenced by more backticks than any run inside it.
- Dependencies (from [05-dependencies.py](../05-dependencies.py) `plan`): direct includes, the typing order with line counts and total, Compact-only reduction includes and untested mini notes, and the direct includers except aggregates, each with its row status. Python imports are not followed (no module exists yet).
- Folders: `index.md` holds the inventory Scope paragraph, a link to the notes page when `Docs/00-notes.md` exists (copied whole), the folder article and, for `01`–`07`, the `chart` Mermaid flowchart, or a sentence when every header includes only the template. Then come the inventory tables per tier, with header cells linked to existing pages. The home page counts rows, pages and verified rows per folder. Nav: home, then per folder its overview, notes and pages in inventory order, grouped by tier except Core.
- Articles (user decisions 2026-10-25): `Articles/<NN-Folder>/<NN-stem>.md` is merged into that header's page after the include line, and `Articles/<NN-Folder>/00-index.md` into the folder overview after the notes link, each without its first `# ` line. Other files under `Articles/<NN-Folder>/` are assets (images), copied beside the folder's pages. An article without an existing inventory header, module or folder, or a file outside a known folder, raises `SiteError` naming it.
- Links: copied Markdown (scope, cells, evidence sections, notes, articles) is relinked relative to its own file. The rewrite targets the site page when the target (a header, its evidence document or article, a folder, its index, article or notes) has a page and the anchor exists there, and an article asset is a target too. An anchor into a copied document (evidence, article, notes, and the inventory, whose tier headings head the tables) is that document's own heading id. The page maps it to the id the same heading gets on the page, which differs when an earlier part repeats the heading (user decision 2026-10-25). A document's heading that is not copied sends the link to GitHub. Otherwise the link goes to `<origin>/blob|tree/master/<path>`, with `?raw=true` for an image, when the path is tracked (`git ls-files`; any existing path outside git) and an `origin` remote is set (credentials removed). Failing that, the label stays as plain text. External, `mailto:`, escaped (`\[`), inline-code, inline-math and fenced links stay unchanged. Code spans are found as Python-Markdown 3.11 finds them: a backtick run closes at the next run of its length, else at the first longest later run, and an escaped backslash pair before a backtick does not escape it. In a table block (the tables extension's test: a header of two or more cells, or one bordered, and a separator row; a block that is no table splits at its first hash heading) they are found per cell, split as that extension splits rows (user decision 2026-10-25); elsewhere per line. Heading ids follow the renderer, ported from Python-Markdown 3.11 (user decision 2026-10-25). Hash headings need no space and drop a closing run of `#`; an unpaired trailing backslash makes no heading, and a hash line inside a table is a row. The inline patterns run in the renderer's order with its stash placeholders: code span, arithmatex math (`$…$`, `\(…\)`), escape (`$` included), link, image, autolink, inline HTML, entity, then the delimiter emphasis of `*` and `_` (`DelimiterProcessor`). The inline tree processor's walk then reruns them on element texts and tails. The toc text is the serialized inner HTML with escapes and raw HTML restored, then `strip_tags` (comments, then `<` to the next `>`, whitespace collapsed), then entities decoded. Ids count repeats with ASCII digits. The result goes through `pymdownx.slugs.slugify(case="lower")` (configured in `mkdocs.yml`; GitHub's rule), with `_1` suffixes for repeats. Fences follow `pymdownx.superfences`: a run of three or more backticks or tildes, an optional language, then `{attributes}` or only `pymdownx.highlight` options with valid values (`hl_lines`, `linenums`, `title`, `title_mode`), opens one only when a later bare line of exactly that run closes it. Then `validation.anchors: warn` with `--strict` fails the build on any anchor the site lacks.
- Rendering: search with the `offline` plugin, light and dark palettes, heading permalinks, code copy buttons, `pymdownx.arithmatex` (generic) with MathJax 3 for `$…$` and `$$…$$`, configured as cp-algorithms does but loading the SVG build `tex-svg-full.js`, which needs no font files and bundles every TeX extension, and Mermaid through a `superfences` custom fence. The `privacy` plugin (user decision 2026-10-25) self-hosts every font and script the pages load (Google Fonts, MathJax, Mermaid, the `iframe-worker` shim that `file://` search needs) under `assets/external`; the tester checks MathJax, Mermaid and the shim there. The first build downloads them; later builds reuse `site/.cache`, since the engine runs in `site/`. Both engines honour it. `03-consistency.py` skips `site/`, whose Markdown hygiene the tester checks.

## Run on 2026-10-26

Generation took 2.3 s for 180 pages (1 home, 8 overviews, 8 notes, 163 headers; 3.9 MB of Markdown). The strict repository build (`06-site.py build`, generation included) took 5.3 s with Zensical 0.0.72 and 7.3 s with the system MkDocs 1.6.1, Material 9.7.7 and pymdown-extensions 12.1 (Arch packages); the tester's full build also ran on MkDocs 1.6.1 with Material 9.8.0 in a scratch venv. All use Python-Markdown 3.11.2. Zensical and MkDocs venvs live in `/tmp/p239-zensical` and `/tmp/p239-mkdocs`, outside the repository. On every engine the heading ids of all 180 built pages equal the generator's, and the built HTML loads no CDN URL. `serve` answered HTTP 200 on `127.0.0.1` only: Zensical at port 8765 after 4.5 s, MkDocs at port 8766 after 8 s.

## Completeness sweep

`@researcher` compared the planned features with the generated sites of Nyaan, ei1333, hitonanode, suisen and maspypy (online-judge-verify-helper), cp-algorithms, the AtCoder Library documentation and KACTL; the `/finish` audit added OI Wiki, another Material site. Adopted: the `#include` line, status beside dependency links, last commit dates, provenance (the evidence Sources section), dark mode and permalinks, and cp-algorithms' MathJax configuration. Not adopted:

- Bundled listings (the closure expanded into one file): each page lists the typing order with links, and a bundle would repeat up to 5403 lines per page.
- A page per tester: the Tests list links each tester.
- Tags: tier and status already group the nav and tables.
- OI Wiki's article markup extensions (`footnotes`, `def_list`, `pymdownx.tabbed`, `tasklist`, `snippets`), Disqus comments and a feedback widget: article markup is chosen with the first articles (P240), and comments do not suit a local site. OI Wiki self-hosts MathJax, as the `privacy` plugin does here.
- Usage examples, practice problems, conventions and install pages: hand-written content for the P240–P246 articles.
- KACTL's per-file hash: a notebook feature, not a site feature.
- Authors (needs an API key) and RSS: no use for a local library site.
- Per-operation signature tables (AtCoder, ei1333): rows name operations without signatures; contracts stay one block per header from the evidence document.

## Limits

- Zensical 0.0.72 is marked alpha on PyPI ("Development Status :: 3 - Alpha") and is installed with pipx, since Arch has no package. Material for MkDocs 9.8.0 announces its end of life on 2027-05-05; until then MkDocs stays the fallback engine.
- The first build after a cache wipe needs network for the `privacy` downloads. The offline pages were not opened in a browser, so math and diagram rendering from `file://` is shown only by the files being present. Zensical's privacy plugin also follows URLs inside its own bundle: its `assets/external` held 46 files (7.2 MB, including video-player and ad SDKs that no page loads) against 35 for MkDocs.
- Repository links point at `master` on `origin`, so files not yet pushed return 404 there. Commit dates ignore uncommitted edits.
- Mermaid nodes are not links: Material's Mermaid integration does not set `securityLevel`, and Mermaid's default `strict` disables click links.
- Heading ids follow Python-Markdown for hash headings in top-level text only. They do not cover:
  - headings inside block quotes, admonitions or list items;
  - setext headings (`T` over `---`);
  - a heading after a raw HTML block such as `<details>`, which Python-Markdown does not treat as a heading;
  - links outside the plain `[label](url)` form: a title (`[a](b "t")`), brackets inside the label, parentheses inside the URL, images (whose alt text Python-Markdown drops), and raw HTML holding code spans;
  - a `$$` block holding `#` lines;
  - fences whose reading depends on context: a fence indented one to three spaces outside a list, a fence closed by an indented run, or one indented four spaces inside a list item.

  These were checked by rendering on 2026-10-25, and no copied document has them. A link to such a heading goes to GitHub, and a page anchor that does not exist fails the strict build. The heading pipeline matched Python-Markdown on 24 000 fuzzed emphasis headings and 15 000 token-fuzzed headings mixing code spans, escapes, math, entities, inline HTML, comments and plain links; character-level fuzz with nested brackets and parentheses in links differed in up to 0.6 % of cases.
- Indented code blocks are not recognized, so a link in one is rewritten and its displayed code changes (no copied document has one). Reference links, `<user@host>` autolinks and links with a title, brackets in the label or parentheses in the URL are outside the heading-id and relink domain (Limits above).
- Outside tables, code spans are found per line, so a span that Python-Markdown closes on a later line of the same paragraph leaves a link inside it rewritten, or one after it unrewritten (no copied document has one).
- A complexity declaration is cut at the first `{` or `;` outside parentheses within the next 11 lines, comment lines included, so a brace in a template argument or a longer declaration (none today: all 1284 are cut) would shorten it.
- `engine()` reads the Python from the `#!` line, so pip's `#!/bin/sh` launcher (written for a venv path with spaces or over 127 characters) skips the module check, and a missing module shows only when the build fails. `repository()` reads any `host:path` remote as scp syntax, so an SSH alias (`github-work:u/r.git`) becomes `https://github-work/u/r`.
- Module pages and a Python Dependencies section are exercised only by fixtures until `08-Python` has modules.
