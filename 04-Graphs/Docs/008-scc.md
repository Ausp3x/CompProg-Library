## Contracts

### Scope

The row covers static strong connectivity on one snapshot. Incremental SCC belongs to `070-incrementalscc.hpp`, and SCC-based transitive closure and reduction to `040-reachability.hpp`.

### SccResult, tarjanScc and kosarajuScc

`tarjanScc(g)` and `kosarajuScc(g)` require directed input and return an owning `SccResult` that does not borrow the graph. `component[u]` indexes the nonempty `groups` partition. IDs run from zero in source-to-sink order: each arc between different components goes from a smaller ID to a larger one. The relative order of components that cannot reach each other is unspecified for each algorithm and may differ between them (user decision 2026-11-16), and group member order is unspecified. An empty graph has no components.

Tarjan keeps separate DFS and active-component stacks. A discovered vertex stays active until its component root closes. A DFS child passes its lowlink up on completion, an active discovered neighbour contributes its discovery index, and arcs to completed components contribute nothing. So a vertex whose lowlink equals its discovery index is the earliest active ancestor reachable from its subtree, and the active-stack suffix through it is exactly its SCC. Components close in sink-to-source order; reversing their IDs and the group vector gives the stated order. Each vertex and arc is processed a constant number of times: O(n+m) time, O(n) auxiliary and returned storage.

Kosaraju computes the complete DFS finishing order and traverses the transpose in decreasing finish order. For every arc between SCCs, the source component has the larger maximum finishing time, so each transpose traversal reaches exactly the next remaining source component. Explicit DFS frames replace recursion, and the transpose searches use a vector stack. The two passes take O(n+m) time and O(n+m) storage including the transpose and results. Tarjan avoids the transpose; Kosaraju stays as an independent alternative with the same semantics.

### condensationDag

`condensationDag(g,scc)` requires an unchanged valid SCC result for the graph. It returns a directed `Graph` with one vertex per component and exactly one unit-weight edge per distinct ordered intercomponent pair; original weights, multiplicities and edge IDs are not kept. A group-wise traversal with a destination stamp per component removes duplicates in O(n+m) time without sorting or hashing; result and workspace total O(k+d) for k components and d condensation edges. The strict ID increase proves acyclicity, and replacing maximal same-component subpaths by component vertices proves that reachability is preserved.

### attractingComponents and isSemiconnected

Both take a directed graph and a valid SCC result for it (from `tarjanScc` or `kosarajuScc`; the sizes are asserted) and cost O(n + m) time and O(k) memory for `k` components. `attractingComponents(g, scc)` returns the increasing IDs of the components no arc leaves (NetworkX `attracting_components`; the members are `scc.groups[c]`). `isSemiconnected(g, scc)` is true exactly when every vertex pair has a path in at least one direction, and true on the empty graph by convention, where NetworkX raises. Proof: the graph is semiconnected exactly when its condensation has a Hamiltonian path; a DAG with a Hamiltonian path has exactly one topological order, and the component IDs are a topological order, so the test is whether every pair `c, c + 1` is joined by an arc.

### strongConnectivityAugmentation

`strongConnectivityAugmentation(g, scc)` returns a minimum set of arcs whose addition makes `g` strongly connected (Eswaran and Tarjan 1976, CSES 1685). Each arc joins two component representatives `scc.groups[c][0]`. The set is empty for at most one component and otherwise has exactly `max(s, t)` arcs for `s` source and `t` sink components (an isolated component counts as both), never a loop. That count is a lower bound because every source needs a new incoming arc and every sink a new outgoing one.

Construction on the condensation: a DFS from each source in increasing ID order, over vertices no earlier search entered, stops at the first sink it enters and pairs it with that source. Every entered vertex then reaches a paired sink: it either lay on the path when a search stopped, or was finished, so all its successors were entered. Every unpaired sink is reached from a paired source, through the vertex where that source's search was blocked. Arcs `tail_i → head_(i+1)` join the `p` pairs into one cycle `C`, where `p >= 2` or the single pair has distinct ends whenever there are at least two components. Then `min(s, t) − p` arcs run from unpaired sinks to unpaired sources, and the rest run from the first tail to the remaining unpaired sources, or from the remaining unpaired sinks to the first head. Every sink reaches `C` and `C` reaches every source, so the result is strongly connected, with `p + max(s − p, t − p)` arcs. O(n + m) time, O(k + d) memory. The first arc also answers CSES 1682 Flight Routes Check: it runs from a sink component to a different source component, so its tail cannot reach its head.

Eswaran and Tarjan (1976, §2), read on 2026-11-22 ([00-sources.md](00-sources.md#fetched-2026-11-22-source-check)), prove the same bound: Theorem 2 needs `max(s, t) + q` arcs, where their sources and sinks exclude the `q` isolated components; that equals `max(s, t)` as counted here, with an isolated component counted as both. Their construction differs. Their search explores everything reachable from a source and records the first sink it meets, and the surplus sinks and isolated components join the cycle as one chain. The header stops each search at its first sink and routes the surplus through the first pair. So the construction proof above is this package's own, and the closure oracle checks it.

### maximumWeightWalk

`maximumWeightWalk(g, scc, w)` asserts `w.size() == n` and `w[u] >= 0` once at entry. It returns `{value, components}`, where `value` (`lll`) is the largest total weight of the distinct vertices of a directed walk and `components` lists the components the walk passes in order (CSES 1686 Coin Collector, OI Wiki's condensation example). A walk entering a component can visit all of it, and nonnegative weights make that optimal, so this is a longest vertex-weighted path in the condensation. Component IDs are topological, so one pass in ID order over `condensationDag` relaxes `best[d] = max(best[d], best[c])`, keeping the first strict improvement as the predecessor. The witness is fixed: it ends at the smallest component ID whose heaviest walk ending there has the largest value, and steps back from each component `c` to the smallest-ID component with an arc into `c` among those of largest positive ending value, stopping when every such value is 0; the arcs' order in `g` never matters. The result is `{0, {}}` exactly when `n == 0`; otherwise the list is nonempty, consecutive components are joined by an arc, and their weights sum to `value`, which stays below `n · 2^63`. O(n + m) time, O(k + d) memory.

### reachabilityRealization

`reachabilityRealization(g)` treats the arcs of a directed `g` as requests `(a, b)` (loops need nothing) and returns a minimum set of arcs, none a loop, giving a path `a → b` for every request (CSES 1699 Flight Route Requests). For each weak component of the requests with `s` vertices it adds `s − 1` arcs along its vertices in the order of `tarjanScc(g).groups` concatenated (a topological order), and closes them into a cycle with one more arc when the component holds a nontrivial SCC. The output order is fixed: first the chain arcs, each weak component's chain interleaved in that vertex order (each arc listed when its head is reached), then the closing arcs `(last, first)` in increasing order of `first`, independent of the DSU's representatives. Every request then follows the chain, or the cycle. Minimality: the requests of one weak component must lie in one weak component of the answer, which needs at least `s − 1` arcs, plus one more when the requests contain a directed cycle, since a tree has none. Merging several components never saves arcs. O((n + m) · α(n)) time, O(n) memory.
