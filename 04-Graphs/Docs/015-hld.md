## Contracts

### HLD

`HLD(g, root = -1)` takes `Graph` or `CsrGraph`: an undirected simple forest. One assertion after the build checks m + components = n, which rejects loops, parallel edges and cycles; under `NDEBUG` the build skips an arc to a visited vertex and stays O(n + m). `root = -1` roots every component at its minimum vertex; an explicit root roots its own component first and the rest at their minimum.

The build is iterative:
- a BFS gives `parent`, `parent_edge`, `component` (the component's root vertex), `dep` and `edge_vertex[id]` (the child endpoint of tree edge id);
- sizes come bottom-up, and each vertex's heavy child is its first child of maximum size in adjacency order;
- an explicit-stack preorder pushes the light children before the heavy child, so the heavy child gets the next `tin` and each heavy path is a contiguous block headed by `head`;
- the preorder keeps every subtree contiguous, so v's subtree is `[tin[v], tout[v])`, `order[tin[v]] = v`, and each component is the block of its root.

Every light edge at least halves the subtree size, so a root path crosses at most ⌊log2 n⌋ light edges and at most ⌊log2 n⌋ + 1 heavy paths.

- `lca(u, v)`, `distance(u, v)` (edge count) and `kthAncestor(u, k)` (k a `lng`, as in row 07) run in O(log n) and return −1 across components or when k > dep[u]. They are the O(n)-memory HLD algorithm beside row 07's binary lifting and Euler RMQ, under the same names.
- `edgeVertex(id)` returns the child endpoint of tree edge id.
- `processPath(u, v, edges, f)` makes O(log n) calls f(l, r, up). In call order, `order[l..r)` (read from r − 1 down to l when `up`) spells the path u → v. With `edges` the LCA is omitted, so each slot stands for the edge to its parent. It returns false, making no calls, across components. Ranges on u's side are emitted while climbing; v's side is buffered in a 64-entry array, which holds the ≤ 32 heavy paths of n < 2^31, and emitted in reverse.
- `subtreeRange(v, edges)` = `{tin[v] + edges, tout[v]}`.
- `rerootedSubtreeIntervals(v, r, edges)` asserts v and r share a component and returns the nonempty ranges of v's subtree under root r: the whole component when v = r; when r lies strictly inside v's subtree, the component minus the subtree of x, the child of v toward r (`kthAncestor(r, dep r − dep v − 1)`); otherwise v's own subtree. `edges` drops the component root's slot or v's own slot.
- `reorderArray(a)` gives `res[tin[v]] = a[v]`, the base array for a caller's own segment tree (duplicates ledger keep).

### TreeMonoid

`TreeMonoid<A, COMMUTATIVE = false>(g, values, edges = false, root = -1, mon = {})` derives from `HLD`.
- **Values:** one per vertex, or one per edge id when `edges` (stored at the child slot; component roots hold `e()`).
- **Monoid:** A is a monoid or an acted monoid from row 00 of `02-Data Structures`. The engine is a `SegmentTree`, or a `LazySegmentTree` when A has `F`.
- **Noncommutative storage:** when `COMMUTATIVE` is false, each node stores `Reversible<A>`, the forward and backward product (twice the `op` calls). An upward range contributes its backward product, so `pathFold` is the exact ordered product for any associative A. An action reaches both components through `Reversible::mapping`, which requires the action to distribute over `op` in either order, as every acted preset does. With `COMMUTATIVE = true` the engine stores A directly, and results are correct only for commutative A.
- **get, set:** `get(i)` and `set(i, x)` address a vertex, or an edge id when `edges`.
- **pathFold:** `pathFold(u, v)` returns `{true, product along u → v}`, or `{false, e()}` across components.
- **pathApply:** `pathApply(u, v, f)` (acted A only) applies f to every slot on the path and returns false across components.
- **Subtree operations:** `subtreeFold(v)` and `subtreeApply(v, f)` cover v's subtree, without v's own edge slot when `edges`. The fold multiplies in `tin` order, a heavy-first preorder, so it is meaningful for commutative A (contributor proposal 2026-11-04).
- **maxPath:** `maxPath(u, v, pred)` requires `pred(e())` and pred monotone along the path, true then false. It returns the last vertex x on u → v with `pred(pathFold(u, x))`, or −1 across components or, in vertex mode, when u alone fails; in edge mode x = u always qualifies. Each range of `processPath` is first tested whole with one `seg.prod`. The first failing range is searched by binary search on its accepted length, with `seg.prod` of the prefix (downward) or suffix (upward) inside the range, and the walk stops there. Searching the whole array with `minLeft`/`maxRight` would be wrong: pred is monotone only along the path, and tree nodes mix in off-path slots. An accepted upward slot y reaches y in vertex mode and `parent[y]` in edge mode; a downward slot reaches y in both modes.
- **Engine access:** the public `seg` exposes the engine; `seg.prod`, `seg.allProd` and the complement ranges of `rerootedSubtreeIntervals` cover outtree and rerooted subtree queries.

Costs: `set`, `get`, `subtreeFold` and `subtreeApply` O(log n); `pathFold`, `pathApply` and `maxPath` O(log^2 n). Memory O(n).

### Legacy Mapping

- `HLD(N)` + `addEdge(u, v)` + `build(root)` (`OLD/algorithms.cpp:4118-4230`, `OLD/Team Notebook/src/graph/hld.cpp`, `algs.cpp`, `algsbetter.cpp`): `HLD(g, root)` on a `Graph`, which also accepts forests. The legacy recursive DFS overflowed the stack on deep paths; the build is now iterative.
- Renamed operations: `getDis` → `distance`; `kthAnc` → `kthAncestor`; `processSubt(u, is_edge, f)` → `subtreeRange(u, edges)`, half-open where the legacy form was inclusive; `getLCA` → `lca` (P276, 2026-11-10).
- `processPath(u, v, is_edge, f)` with inclusive f(l, r) in arbitrary direction → `processPath(u, v, edges, f)` with half-open ranges in path order and an `up` flag; it returns false across components.
- `in`, `out`, `rev`, `par` → `tin`, `tout` (exclusive), `order`, `parent`.
- `reorderArray`: kept.
- `TreeEdgePainting` (`algs.cpp`, `algsbetter.cpp`; planned as `treePainting`, until then): `TreeMonoid<Sum<int>, true> t(g, vector<int>(m), true)`. Map the legacy edge ids onto `Graph` edge ids; `paintEdge(id, paint)` becomes `t.set(id, paint)`, and `queryAncPath(anc, dec, …)` becomes `t.pathFold(dec, anc).second`. The tester's `painting` case reproduces it against a naive array.

Tester: [`015-hld_tester.cpp`](../../96-Local%20Testing/04-Graphs/015-hld_tester.cpp), driven by its `.py`. | Operation | Oracle and cases |
|---|---|
| `HLD` construction | Every field against the oracle; `order[tin[v]] = v`, `tout = tin + size`, nesting, the heavy child is exactly the first child of maximum size in adjacency order, head chains, contiguous heavy paths, `edge_vertex`; an isolated forest of 10^6 vertices (component, head, `tin`, `tout`, parent) |
| `lca`, `distance`, `kthAncestor`, `edgeVertex` | Parent-walk LCA; k = dep + 1, `INT_MAX` and `INT64_MAX`; pairs across components |
| `processPath` | Both modes: concatenated ranges equal the brute path, every call nonempty and in range, at most 2 · bit_width(n) + 2 calls, false with no calls across components |
| `subtreeRange`, `reorderArray` | Direct checks against the oracle |
| `rerootedSubtreeIntervals` | BFS reroot; ranges nonempty, disjoint and covering exactly the subtree, both modes |
| `TreeMonoid`: `get`, `set`, `pathFold`, `subtreeFold`, `pathApply`, `subtreeApply` | Naive arrays with ordered path walks under random update/query mixes, vertex and edge mode: `AffineComposite<mint>` and a stateful string-hash `Monoid` (noncommutative, both directions), `Sum`/`Min`/`Max` with COMMUTATIVE true and false, `RangeAssignRangeComposite<mint>`, `RangeAddRangeSum` (both), `RangeAffineRangeSum<mint>`; tin-order brute for `subtreeFold` |
| `maxPath` | Prefix thresholds on nonnegative and signed `Sum`, `Min`, `Max` and `MaxGain` (noncommutative), both modes, single and isolated vertices; the oracle checks only paths whose prefix predicate is monotone (the contract's domain); `maxPathRegressions` for a search leaving the path range (path 0-1-2-3 with `{-100, 0, 0, 5}` upward, `{0, 5, -100, 0}` downward, edge mode `{-100, 0, 5}`, and n = 2 without edges) |
| `treePainting` (planned; legacy cases) | `treeEdgePainting`: edge-mode `Sum<int>` paint/unpaint by id and counts from a vertex up to an ancestor, against a naive array |
| Preconditions | 22 checked-build probes: directed, self-loop, cycle, multi-edge, root and vertex ranges, negative k, edge id, path vertex, `rerootedSubtreeIntervals` across components, values size, and out-of-range ids for the root, either `lca` vertex, `edgeVertex`, the second `pathFold` end, `subtreeRange` and both `rerootedSubtreeIntervals` arguments, plus `reorderArray` arrays shorter and longer than n and `TreeMonoid` values shorter than n |

Large shapes: deep and shuffled paths, star, caterpillar, binary, random and a 40-tree broom forest at 2·10^4 (quick), 2·10^5 (full) and 10^6 (stress) vertices.
